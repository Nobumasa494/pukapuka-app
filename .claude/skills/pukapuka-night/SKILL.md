# pukapuka 夜空スキル

pukapuka の3つ目の画面「星空」（2026-10-10 に「夜空」から名前を変えた。画面は 水辺 → 夕空 → 星空）を作る・直す・確かめるためのスキル。コードやこのスキルの中では、前の名前「夜空」「拾ったことば」「川」も残っている。
**何を作るか・なぜかは `docs/SPEC.md`（第1部 5.「夜空」、第2部 C.）。決めたことは設計書に書く（`/pukapuka-spec`）。このスキルは、作り方・確かめ方・数字の根拠のメモ。** 色と世界観は `/pukapuka-design`、保存は `/pukapuka-db`。

---

## 1. 次にやること（2026-10-09 夜 更新。ここから始める）

- **スマホ（Galaxy S20・Android）で、夜空の星・ボタン・なぞるは、押せる・動く**ようになった（下の 6. の止めどきを満たした。見本（多め）で 60コマ/秒・遅れ0%・CPU 約97%）。つまむ（2本指）は adb で送れないので、ユーザーに触ってもらって確かめる
- 川の画面のほうが重い（CPU 約190%・遅れ4.6%）。スマホが熱いのは川かもしれない。夜空の外の話なので、ユーザーに報告して方針を聞く
- 数字の根拠（3.）：A（検定・期間）はダミーで総当たりして、検定を1%にした（2026-10-09）。B・C は「分析に役立つぐらい」で見送り。**本物の記録が数週間たまったら、`npx tsx scripts/night/tune-test.ts` を本物の記録でやり直す**
- ブランチ `feat/save-check`。PR #9 はユーザーの OK のあと

## 3. 数字の根拠（いちばん大事。数字を変えたら、ここと設計書を直す）

根拠の種類：
- **A. 偶然の記録で試す**：でたらめに拾う人の記録を何百人分も作り、偽の線の数を数える
- **B. 画面で測る**：文字の大きさと画面の広さから、重ならずに置ける数を計算する／絵にして見る
- **C. スマホで測る**：星を増やしながら、動かしたときのなめらかさを測る
- **D. ユーザーが見て決めた**：好み・手触り。何を見て決めたかを書く（見たものが変われば、見直す）

| 数字 | 場所 | 何のため | 種類 | 根拠（確かめた日・結果） |
|---|---|---|---|---|
| 検定 **1%** | `ALPHA` | 偶然の線を出さない | A | **2026-10-09 総当たり**（`tune-test.ts`、ダミー40人・6週間・拾う量のばらつきあり）：でたらめな人の偽の線 5%→12.8本、1%→1.4本。本当の線 1%→15.5本。ユーザーが任せたので、偽の線約1本・本当の線十分で1%に |
| 点線の検定（実線と同じ **1%**） | `ALPHA` | 点線（別々の星座どうしの弱い線）を出す | A | 2026-10-10：点線だけ2%（0本の人44%→16%）・FDR 10/20/30% を比べて、1%に戻した（ユーザー「30ってやりすぎでは」→「はい」）。正しい FDR 20% は本当の線10本で1%より少ない。`fdr-test.ts`・`crosscheck/` |
| 一緒の日 2日以上 | `MIN_CO` | 1回きりの偶然を出さない | A | 2026-10-09 総当たり：1%では1日以上と2日以上は同じ結果（1%を通るのは2日以上だけ）。3日以上は本当の線が少し減る（14.0本）だけ |
| 6週間 | `NIGHT_DAYS` | 線が出るだけ記録をためる | A＋平日と週末を同じ数に（7の倍数） | 2026-10-09 総当たり（1%）：本当の線 2週0.5本・4週8.4本・6週15.5本・8週23.4本、偽の線は 6週1.4本・8週2.8本。6週は、線が十分出て偽が少ない所 |
| **星26だけ**（1画面） | `NORMAL_CAPS` | 1画面で名前が読める | B | 2026-10-10 上限を星の数だけに（ユーザー「はい」）。描く線は骨組みなので線の上限は不要。1%では、ふつうの人は届かない。26の値そのものは、1%後は測るのを見送り（「分析に役立つぐらい」） |
| **星60だけ**（動かせる夜空） | `WIDE_CAPS` | 重くならない・見て分かる | C＋B | 一部：Galaxy S20 で星46まで 60コマ/秒・遅れ0%（2026-10-09）。線150本の上限は 2026-10-10 になくした |
| ~~1つの星から3本（動かせる夜空）~~ → **なし** | `WIDE_CAPS.perStar` | ごちゃごちゃさせない | D | 2026-10-10 ユーザー「3本までの役目はなしでいい」。描く線を骨組み（最大全域木 `skeleton`）にしたので不要。（前：8→5→3） |
| 拡大 2.5倍まで | `MAX_SCALE` | 寄りすぎない | D | なし |
| 星座どうしの間 44px・広がり 横÷縦 1.15・星座の広さ 150＋80√星の数 | `SKY_GAP`・`SKY_ASPECT`・`layoutSky` | 星座が別々に見える・夜空らしい | B | なし（見本の絵で見ただけ） |
| 線の理想の長さ 64px | `IDEAL_LEN` | 星を引き伸ばさない | B | なし |
| 滑り 0.996・端の重さ 0.3・戻る 0.26秒 | `Constellation` の `withDecay`・`rubber`・`SETTLE` | 手触り | D | なし（スマホでユーザーに触ってもらって決める） |

数字を決めるときの約束：
- 私が数字を決めない。測った結果と選択肢を図で見せて、ユーザーが決める
- 「強さ」を見る試し（A）と、「見やすさ」を見る試し（B・C）を混ぜない。上限を変えても、線の本物らしさは変わらない（弱い線が消えるだけ）
- 試しのスクリプトは `scripts/night/` に残す（あとで同じ試しをやり直せるように）

## 4. 確かめ方

- **配置を絵で見る**：`npx tsx scripts/night/draw-sky.ts <出力フォルダ> 1 4`（1＝見本、4＝記録4倍のダミー＝星が多い人）。点線の四角＝スマホ1画面、赤い丸＝開いたときの真ん中。出力は scratchpad に置き、`SendUserFile` でユーザーに見せる
- **見本**：星が出ないときの「見本を見る」（1画面。**種463・2026-10-09 までの6週間に固定して今日までずらす**＝毎日同じ形。5つの星座・点線1本（ひらめいた→わくわく）。`SAMPLE_SEED`・`SAMPLE_ANCHOR`）。種を選び直すときは、数百通り作って「3つ以上の星座の数」「2つ組の少なさ」「関係ない言葉のなさ」「点線が1〜3本」で比べ、絵にしてユーザーに選んでもらう。**「見本（多め）」ボタンは 2026-10-10 に消した**（ユーザー「多め消してくれない？」）。星が多い人（動かせる夜空）は `draw-sky.ts … 4` で絵にして見る。スマホで動かせる夜空を測りたいときは、一時的に `sampleCaptures` を記録4倍にして試し、終わったら戻す
- **本物に近いダミー**：`npx convex run demo:seedDemo '{"days":60,"heavy":true}'`、web で `?demo=1`
- **スマホ**：ユーザーの 8081（tunnel）で Expo Go。**トンネル越しでは Fast Refresh が届かない**ので、`scripts/night/phone/reload.sh`（R を2回）で読み込み直す。こちらの確認用は 8091（ユーザーの 8081 は止めない）
- 型と書き方：`npx tsc --noEmit`、`npx eslint src/components/NightOverlay.tsx src/constellation.ts`

## 5. つまずいた所（同じ失敗をしない）

## 6. スマホで「押せる・動く」まで直す繰り返し（ユーザー「押せるようになるまで、自分で問題点を見つけ、修正して、更新する。最適化するまで繰り返し続けて」2026-10-09）

ブラウザで動いても、Android では動かないことが何度もあった（5. の表）。触る・押す・重さの直しは、**本物のスマホを、こちらから操作して確かめる**。ユーザーに毎回試してもらわない。

**準備（1回だけ。ユーザーにしてもらう）**
- スマホ：設定 → 開発者向けオプション → ワイヤレスデバッグをオン → 「ペア設定コードによるデバイスのペア設定」で、IP:ポートと6桁のコードを教えてもらう。ワイヤレスデバッグの画面の「IP アドレスとポート」（接続用。ペア用と別）も教えてもらう
- こちら：`~/.local/android/platform-tools/adb pair <IP:ペア用ポート> <コード>` → `adb connect <IP:接続用ポート>`（仮想スマホは使えない：KVM に sudo が要る）

**道具（`scripts/night/phone/`。`PHONE=192.168.1.9:ポート` を付けて使う）**
- `reload.sh [sample]`：R を2回送って読み込み直し（約12秒）→ 川 → 夜空 →（「見本を見る」。星が出ていないときだけある）。**アプリを閉じて開くより速い**
- `ensure_sample.sh`：見本が開いたか（「← ことばへ」の文字が消えたか）を画素で確かめ、開いていなければ「見本を見る」を押す
- `perf.sh 名前`：10秒の「遅れたコマ」・CPU・温度、星（散歩）を押して0.8秒後のヒントを撮る
- 座標は Galaxy S20（1080×2400）の値。ほかのスマホでは撮って直す

**1周（押せるまで、くり返す）**
1. **見る**：`adb exec-out screencap -p > shot.png` で画面を撮り、Read で見る。押せる部品の場所は `adb exec-out uiautomator dump /dev/tty` で取れる
2. **押す・動かす**：`adb shell input tap X Y`（押す）、`adb shell input swipe X1 Y1 X2 Y2 300`（なぞる）。座標はスマホの画素（画面の dp × 画素密度。`adb shell wm density` ÷160）
3. **確かめる**：撮り直して、星が光ったか・ボタンが開いたかを見る。重さは `adb shell dumpsys gfxinfo host.exp.exponent`（遅れたコマの割合）、熱は `adb shell dumpsys battery`（temperature）・`adb shell top -n 1`
4. **ログ**：`adb logcat -d -t 200 | grep -iE "ReactNative|error"`、Metro（ユーザーの 8081）のログ
5. **直す**：原因を1つに絞って、1つだけ直す（まとめて直すと、どれが効いたか分からない。今日は押す仕組みを入れ替えて、悪くした）
6. **確かめ直す**：1〜4 を同じ手順で。悪くなったら、すぐ前のコミットに戻す
7. **記録**：5. の表に、原因・直し方・確かめ方を1行。直ったらコミット

**時間を短くする（毎回、何に時間がかかったかを下の表に書き、次の周で生かす。ユーザー「時間かかりすぎ。なぜ時間が掛かったかを記録して、時間短縮をし続けて、自己改善して」2026-10-09）**
- 確かめる前に、**スマホが新しいコードで動いているか**を確かめる（画面に一時的な印を出し、撮って見る）。サーバーを起動し直したあと、スマホは古いコードのまま動き続ける（「Cannot connect to Expo CLI」）
- 待つときは、必ず上限をつける。待つ目印は、確かに画面に出る文字にする
- 画面の文字を読む `uiautomator dump` は、アニメーション中は11秒待って失敗する（could not get idle state）。**`screencap` → `ffmpeg -vf crop=…` で切り出して Read** にする
- JS の詰まりは、画面に「0.25秒ごとに+1する時計」を出し、10秒あけて2回撮って比べる（40 進めば詰まりなし）。時計は小さな部品にして、測る対象を描き直させない
- 直す前に測る。原因が分かる前に作りを変えない
