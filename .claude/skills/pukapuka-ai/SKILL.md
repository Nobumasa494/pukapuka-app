# pukapuka AI（API）スキル

AI を「どう使うか」の担当。**何を保存するか**は `/pukapuka-db`、**星空・夜明けの計算への影響**は `/pukapuka-night`・`/pukapuka-me`、設計書は `/pukapuka-spec` に任せる。
決まった事実は設計書 `docs/SPEC.md` に書く（このスキルには進め方と見方、決まるまでの途中経過だけ）。

---

## 進め方

1. **先に壁打ち、コードはあと。**ユーザーの「はい」まで設計書もコードも触らない
2. 1回に1つの問い。むずかしい言葉は使わず、小さな例と図で（ユーザーは数学・技術の知識がなく、聞けない。使えそうな手はこちらから提案する）。返事は日本語
3. 決まったら設計書に書く → コード → スマホで確かめる
4. AI につなぐ前に、**送るもの・お金の上限・失敗したときの動き**を決めておく

## 決めるときの見方

- **記録は本人のもの。**AI に送るのは最小限（拾った言葉1つなど）。名前・過去の記録・日記は送らない。AI の会社に残さない設定にする。「そっとしておく」言葉は送らない（SPEC D.）。AI の言葉は使い回すので、誰の分かは伝わらない。API の内容は学習には使われないが一定期間は保存される（ゼロ保存は個別契約）ので「残さない」とは書かない
- **自分で自分を強めない。**よく拾う → よく流れる → もっと拾う、のくり返しで川が1色にならないように、**見つける枠**（好みと関係なくランダムに流す枠）を必ず残す
- **数えるときは割合。**川がその人向けに変わるので、「何回拾ったか」ではなく「流れた回数のうち何回拾ったか」で比べる。流れた回数の記録が土台（`/pukapuka-db`）
- **AI がずれていかない。**AI の言葉から AI の言葉を作り続けると、言葉が遠くへずれる。何を元に作るかを決める
- **AI がなくても川は流れる。**電波なし・遅い・上限に達したときは、手元の言葉だけで流す。泡が出るのを AI の返事で待たせない
- **お金は上限を先に。**1日に呼ぶ回数・1回の長さの上限を決める
- **画面が決めつけない。**AI が作るのは「流す候補」。拾うかどうかは本人。AI の言葉を答えのように見せない

## 決まったこと（2026-10-11 壁打ち。設計書は第2部 A.「その人向けの川」・G.・K.）

- **川は全部（ものさしの言葉も、していることも）その人向けにリアルタイムで変わっていく**（ユーザー「ものさしも、していることも、すべてリアルタイムでかわってほしい」）
- **変える理由は「その言葉が好きか」（量）だけ。「何のあとに何を出すか」では変えない**。後者は夜明けが探す「散歩のあとに元気」を川が自分で作ってしまう（試算：偽の源 13%→18%）。量だけなら、夜明けは同じ週の中で日を入れかえて比べるので、だまされない（13%→13%）。星空も増えない（偽の線 2.4本→2.2本）。根拠は `scripts/river/personalize-test.ts`
- **見つける枠**：10個のうち1〜2個は好みと関係なくランダム（新しい興味の入り口・ゆがみのない比べ物）
- **応える泡**：していることを拾ったら、すぐ細かい言葉（散歩 → 夜の散歩）が流れてくる。同じ日の中だけのことなので夜明け（次の日以降を見る）には響かない。星空では元の言葉としてまとめて数える。どの細かい言葉が流れてくるかは均等（「散歩の中では夜の散歩をよく選んでいます」を事実として言えるように）
- **AI の役目**：細かい言葉を作るだけ。選ぶのはアプリの計算。1つの元の言葉につき1回だけ作って言葉の表にしまう（待ち時間なし・電波なしでも流れる）
- **AI の言葉はみんなで使い回す（D、2026-10-11）**：持ち主は「みんな」。組み合わせの言葉（散歩＋写真）も組ごとに1回だけ作って使い回す（していること同士の325通りまで。案）。パーソナライズは拾った記録・流れた記録で「どれを多く流すか」で行う。出す前に作った言葉を確かめられる。送るのは決まった言葉1つか2つ。誰の分かは AI の会社には分からない（前に「この人は散歩が好きと伝わる」と書いたのは言いすぎ）
- **いつ作るか：そのつど作って、しまう（②。2026-10-11、ユーザー「２にしよう」）**：必要になったとき、まだない細かい言葉・組み合わせの言葉だけ AI に作ってもらい、言葉の表に「みんな」でしまって使い回す。最初はあなたと身近な数人だけで使い、流す前にあなたが見られる（つらい気持ちの言葉は確かめるまで流さない・案）。先に作っておく分（約500円）は、人が増えてから足すか決める。先に作るのはサーバーの「そのつど作る」部分（どの案でも要る）。会社とモデルは Gemini 3.1 Flash-Lite で仮決定（2026-10-11。無料チャットで比べて「かなりいい」→ API で6語を 3.5 と並べ、3.1 のほうが離れた言葉の幅が広かった。ユーザー「はい」。本物の記録で見てから正式に決める。返事の形はばらつくので形を決めて頼む）。テストの間（家族・友達）は無料プランのまま（2026-10-12、ユーザー「テストの間には有料にしない」。無料は送った内容が改善に使われ、人が読むことがあるが、送るのは言葉1つだけ。そのつど作るも無料で続ける。製品にするとき改めて決める。テスト中に有料をすすめない）。呼び方は公式のページで確かめてから書く（Interactions API）
- **お金のしかけ（案）**：前払い・コンソールの月の上限・アプリの中の上限・上限でも川は流れる。モデルはまず Opus 5.5 で試し、Haiku 5.5 と見比べる
- **好きなことは、いろいろな言葉になって流れてくる**：近い言葉（散歩 → 夜の散歩）と、抽象的に近い言葉（散歩 → 古本屋をのぞく。共通点「知らないものに出会う」）の両方を AI に作らせる
- **ラベルは2つ**：生まれ（事実・変えない名札）と共通点（AI の解釈・分析の土台にしない）。分析は名札で数え、画面には拾った言葉を見せる。抽象的に近い言葉は元の言葉に入れない。何日も拾った言葉は、星空・夜明けにも自分の言葉で出る（案6日。2026-10-13 に1日を試して見送り。前の呼び名「独り立ち」はやめた）。通しの試算は `scripts/river/whole-test.ts`
- つらい気持ちも AI が細かくするが、あまり流さない。やわらかい言い方だけ・応える泡にしない（2026-10-11）
- 合わない AI の言葉は何もしない（消すボタンなし。拾わなければ減る）。共通点は画面に出さない（2026-10-11 に見直し。前は夜明けに問いで出す案だった。ユーザー「それはユーザーが気付くことだから、こちらがやることではない」。言葉の表には残す）
- 自分の言葉は今は入れない（水辺で書く・日記からなぞる・AI が日記から取り出す、どれもやめた。日記は自分だけの場所のまま。2026-10-11）
- 夜明けのため、していることも気持ちも拾いやすくする（案：1日1回まとめて流れる時間。毎日同じなので「何のあとに何」にならない。2026-10-11）
- 最初から全部 AI にはしない（最初の日は材料がない・同じ言葉が来ないと回数がたまらない）。決まった言葉は今の一覧のまま（AI は作らない）

## 作ったところ（2026-10-11、PR #15）

- 好みの量：`convex/river.ts` の `weights`（流れた回数のうち何回拾ったか・直近6週・10回に1回より拾う言葉ほど多め・4倍まで・流れた記録をとりはじめる前は使わない）
- 見つける枠・拾いやすくする時間（その日はじめての90秒、していること＋元気・好奇心の言葉を6割）：`src/riverWords.ts`
- どの枠から来た泡か（like / find / gather / even）を、流れた記録と拾った記録に残す
- AI の言葉（2026-10-11）：`npx convex run ai:generateFor '{"word":"散歩"}'`・`ai:generateMissing '{"limit":30}'`（action は10分までなので区切る）。鍵は Convex の環境変数 GEMINI_API_KEY（dev。無料プランの鍵）。一覧は `npx convex run aiWords:listGenerated`。127語ぶん・1,162語を作り、ユーザー「全部流していいよ」
- 流し方（2026-10-11 夜に直した）：好みの枠の半分は AI の言葉から。重さ＝元の言葉の好みの量×その言葉自身の好みの量（つらい気持ちの仲間は0.3倍）。近い言葉の回数は元の言葉にも足す（流れた・拾った両方。`convex/prefs.ts` の withParents）。星空・夜明けは `tagCaptures`（近い→元の言葉、離れた→入れない、6日以上拾った AI の言葉はそのまま出る）。夕空は `categoryOf` でそのまま。ユーザーは「離れた言葉が育たないと新しい興味が見えない」と気にした
- スマホ：開いたままコードが入れかわると、AI の言葉がほとんど流れなかった（2分で2語）。Reload したら1分で20語。確かめる前に必ず読み込み直す
- 試し方のつまずき：web の試験で新しい端末は好みのメモがなく均等の川のまま（AI の言葉が出ない）。好みのメモがある端末 ID を localStorage の `pukapuka.deviceId` に入れて開く
- 応える泡（2026-10-11）：していることを拾ったら生まれた言葉を2つ・10秒以内（answerTo。枠 answer）。気持ちには応えない
- 裏側の言葉（2026-10-11）：つらい気持ち19語から `ai:generateBehindAll`（words.kind = "behind"）。ふつうの量で流し、元の言葉には数えない。頼み方は「自分の気持ちとして言う・助言/なぐさめ/説明はしない・句点なし」（最初の頼み方では「今はただ、休んでもいい」などが混ざった）。作り直すときは `aiWords:retireKind`（消さずに source を old に。記録から引けるように）
- そのつど作る（2026-10-11）：captures.add → maybeGrow（AI の言葉・3日拾った・先に言葉がない・1日200回まで）→ words.askedAt を付けて ai:generateFor を予約。数え方は rootOf でいちばん元までさかのぼる（prefs も tagCaptures も）。試し方：過去の日の captures を `npx convex import --table captures --append` で入れ、captures:add を3回 → 試したあと removeOne で消す
- 夕空の割合（2026-10-12）：`withRates`。見えない泡は「決まった言葉が流れた回数の真ん中×その人の拾いやすさ」（10回1回だと AI の言葉ばかり上に来た）

## 試算で分かった注意（設計書 K. に書いた）

- 乱数は質のよいもの（mulberry32 など）を使う。簡単な LCG は日をまたいだかたよりを作り、試算をまちがえた
- 1つの言葉が流れてくるのは3日に1日くらい（泡60個/日・約130語）。川を通すと、夜明けは本物の源をかなり見つけにくい（12週で数%）。パーソナライズとは別の問題。流れた記録がたまったら本物の泡の数で確かめ直す
- 細かい言葉（夜の散歩）は記録が少なく、夜明けの源としてはまず見つからない。選んだ事実で見せる

## 倉庫と庭師（決定 2026-10-13〜14。前の「その場で作る」が中心の考えを置きかえる）（詳しくは `/pukapuka-words`、設計書 第2部 A.「倉庫と箱」）

- 言葉は**倉庫**（みんなで共有）にしまう。箱（45個）ごとに、最初に AI で100語。上限は箱ごと200語。人ごとに作らない
- **使っている間は AI を呼ばない**。その人向けは「流す言葉の選び方」（その人の記録で計算）。近い言葉は、言葉ごとに1回付けた意味の位置（Gemini の埋め込み）で Convex の検索
- **AI は書くだけ。判断は計算**。庭師（週1回・夜中）：全員分の拾われた割合で、休ませる言葉（100回以上流れたものだけ）と増やす方向（上位5つ）を計算で決め、AI に箱ごと1回「上位の仲間を10個」と頼む。長さ・重なり・箱からはみ出しを意味の位置で確かめて入れかえる。月 約6円
- AI に渡すのは言葉と数だけ。だれの記録かは渡さない
- 新しい言葉のきっかけ：同じ言葉を別の日に2日拾った（`GROW_DAYS = 2`）。倉庫に近い言葉が足りないときだけ。その場で作るのは止めて、足りなかった回数を記録し、庭師がまとめて作る（案）
- 試しの道具（保存しない）：`ai:previewBoxes`（言葉に箱の番号を付ける）・`ai:previewBoxWords`（箱ごとの言葉）・`ai:previewWishes`
- 言葉の長さは7〜10文字（上限12。決定 2026-10-14。前は10〜14文字）。頼み方に「箱の中でいろいろな種類を混ぜる」「好奇心につながるもの（掃除の汚れなどは書かない）」「その箱そのもの（買い物などにしない）」を入れる（2026-10-13 の試しで、和楽器ばかり・汚れの言葉・長すぎが出た）
- 1万人でも費用は増えない（最初 約30円＋月 約6円）。本当の心配は読みこみ：その人の箱の言葉＋知らない箱の分だけ取ってくる
- 川の配合（決定 2026-10-14）：泡10個のうち 自分の箱4・知らない箱3・気持ちの箱3。前の「したいこと30%」と「見つける枠2個」を置きかえる（作るのはこれから）
- 川の配合は 3・3・4 に変えた（2026-10-14。前は 4・3・3）
