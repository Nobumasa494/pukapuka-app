# pukapuka デザインスキル

pukapukaアプリのUI/UX設計・実装を行うためのスキル。デザイン変更・新画面追加・モックアップ更新のときに呼び出す。

## アプリの世界観

「拾う・消える・気づく」——川に流れる言葉を無意識に拾い、積み重なりで自分を知る。

- **コンセプト**: 「流れてくる言葉を拾い、夜に星として振り返る」
- **川画面のムード**: 夕方17〜18時の渓流。露天風呂から眺める川。深緑の木々、木漏れ日、水面のきらめき。温泉旅館の灯り
- **星画面のムード**: 昼に拾った言葉が夜空の星になる。深い藍色の夜空、満天の星、天の川、川面への反射。幻想的・静か・上質
- **ユーザーの状態**: 疲れた社会人（25〜40代）が隙間時間に開く。没入感・癒し・静けさが大事

## アニメーション仕様

| 要素 | 動き | 数値 |
|---|---|---|
| 言葉の流れ | 川筋に沿って奥→手前 | 手前32px/s、奥は9割。奥〜中ほどから浮かび上がる（1.2秒） |
| 泡のボブ | 上下ゆらゆら | 振幅3px、周期2.8秒 |
| チャージリング | 押すほど拡大 | 2000msでMAX、ゴールド→オレンジ |
| キャプチャ | ふわっと上昇 | translateY -150px、1400ms、cubic-bezier |
| 星のきらめき | フェードイン/アウト | sin波、各星で位相ずらし |
| 星座ライン | 順番に描画 | revealProgress×線数でインデックス制御 |
| 流れ星 | 斜めに流れる | 約31秒周期 |
| 画面遷移（川→星） | 泡上昇 + 暗転 + 星出現 | 1600ms |
| 画面遷移（星→川） | フェードアウト + 川復帰 | 900ms |

**React Native実装での禁則**:
- `useCallback`の中でSharedValueを変更しない（react-hooks/immutabilityエラー）
- `startPress`/`endPress`はplain関数にする

## 画面構成

### ことばの川（メイン）— 2026-10-03 Blender 動画背景に作り替え ★現行
- **背景**: Blender で作った4秒ループ動画 `assets/video/river_bg.mp4`（1080×1920、`/pukapuka-blender` の v21B）を `expo-video` でループ・無音再生。下に1コマ目の静止画 `river_bg_poster.jpg` を敷く（読み込み中・Web の H.264 非対応時の代わり）
- **画面に合わせる**: `contentFit="cover"` と同じ計算 `coverRect()`（`src/riverPath.ts`）で動画の位置と大きさを決め、**泡の座標も必ず同じ rect で変換**する。縦に長い機種は動画の左右が切れるが泡はずれない
- **泡の通り道**: `src/data/riverPath.json`（Blender の川の中心線を画面座標に投影した50点 `[x, y, halfw]`、奥→手前、動画の 0〜1 座標）。Blender 側でカメラ・川を変えたら書き出し直してここに入れる
- **流れ方**（`src/app/index.tsx`）:
  - 泡は川筋の位置 `s`（px、0=奥）と横位置 `lane`（-0.42〜0.42 × 川幅の半分）を持つ。横位置は奥ほど中心へ寄せる（`×(0.3+0.7t)`、奥のS字で岸に乗らないように）
  - **奥〜中ほど（s 0〜250px）の水面から「ぷかっ」と浮かび上がる**（1.2秒で透明→表示）。奥の端からだけ出すと狭いS字で一列に詰まり6個しか流れない（シミュレーションで確認）
  - 速さ: 手前 32px/秒、奥でも9割（遠近は大きさで表す）。前の泡にぶつかる位置へは進まない
  - 起動時は30秒ぶん先に計算して、開いた瞬間から川全体に泡がある
  - **動かし方（軽さ）— 2026-10-04 UI スレッドに移した**: 流れの計算（`src/riverFlow.ts` の worklet: `stepBubbles`・`spawnBubble`・`placeBubble`）を `useFrameCallback` で**毎コマ UI スレッド**で動かす。状態は SharedValue `sim`。JS（React）は「どの泡があるか」だけ持ち、泡が出る・消えるときだけ描き直す（出す言葉は JS で選び `runOnUI` で置ける場所を判定、消えたら `runOnJS`）。JS が遅れても泡は止まらない
  - 泡は大きさ `BASE`=80 で一度だけ描き、毎コマ `scale` で正しい大きさにする（**流れている泡は描き直さない**）。文字は 15px で描いて拡大縮小を打ち消し、10〜15px に保つ（折り返さないよう泡より広い箱に置く）。奥のもやも毎コマ不透明度で。ぷかぷか・指の移動・拾って昇る動きは `1/scale` で入れる
  - 起動時の30秒の先回し計算は、同じ worklet を JS で `useState` の初期化で実行（effect で setState しない）
  - 長押しのリング SVG は押している間だけ
  - 結果: 常に約10〜11個、重なり0
- **泡の大きさ**: 奥でも文字10px以上（`bubbleSize()`、`/pukapuka-blender` の式と同じ）。奥の泡も薄くしない（opacity 0.8〜1）
- **泡の見た目**: 半透明の青のグラデーション、クリーム色の縁、上に夕日側の暖色の線、小さな光点1つ、下に楕円の波紋2重＋ごく薄い映り込み（opacity 0.05。濃いと灰色の板に見える）、ぷかぷか上下±3px。長押しのチャージリング・拾う動きは従来どおり
- **画面下**: 泡の下の方がヒント文に近づいたら消える（中心で判定すると大きな泡が文字に重なる）。下端だけ薄く暗くして文字を読みやすく
- 文字色は空の暖色に合わせてクリーム（ロゴ・振り返る）

### 川 → 拾ったことば の画面遷移（2026-10-03 実装）
- 「振り返る」を押すと、Blender の遷移動画 `assets/video/river_to_cloud.mp4`（2秒、`/pukapuka-blender` 参照）を再生。カメラが川岸から空を見上げ、夕暮れ→日没直後→ブルーアワーへ時間が進む
- 遷移動画は最初の 200ms でフェードイン（ループ中の波と動画の最初の波のずれを隠す）。下に川の1コマ目を敷く
- 泡は 1600ms で空へ昇りながら消える（`rise`）。**水面の波紋・映り込みは昇り始めにすぐ消す**（空に波紋が残る）。ロゴ・ボタン・ヒント文もフェードアウト
- 再生終了（`playToEnd`）か 2.2秒の保険タイマーで `/words` へ。`words` は `animation: 'fade'`。背景が動画の最後のコマと同じ絵なので切り替わりは見えない
- 移った 600ms 後に、川の画面の下で帰りの動画（最初のコマ＝空）に差し替えて待つ（`atCloud`）

### 拾ったことば → 川 の画面遷移（2026-10-03 実装）
- 帰りの動画 `assets/video/cloud_to_river.mp4` は行きの48コマを逆順にしたもの（新しくレンダリング不要。最初のコマ＝ワードクラウドの背景、最後のコマ＝川）
- 「← 川へ」で `router.back()`（`words` のフェードで消える）。川の画面は `useFocusEffect` で戻ってきたことを知り、帰りの動画を再生
- 泡は空から降らせない（ユーザー指摘「変」）。カメラが川岸へ下りた後半、1300ms 後から 900ms かけて**元の位置の水面から「ぷかっ」と浮かび上がる**（`appear` 0→1、下から10px）。動画が終わったら 300ms でフェードし、ループ中の川に戻す（波のずれを隠す）
- 遷移中（idle 以外）は泡の計算を止め、遷移動画が川を覆ったら裏の川の動画も止める（`arriveRiver` で再生）
- **演出と保険タイマーは動画が実際に再生を始めた時（`playingChange` の `isPlaying`）から数える**。時計で決めるとスマホの再生開始の遅れで「泡が空に残る」「動画の途中で切り替わる（スキップ）」が起きた。1.2秒たっても始まらなければ（Web で再生できない等）動画なしで進める。保険の終了タイマーは再生開始から 2.8秒
- 動画3つ（川・行き・帰り）はすべて `surfaceType="textureView"`（Android で重なり順・透明度を効かせる）
- 遷移動画の表示（不透明度）は再生が始まってから。それまでは下の静止画（各動画の最初のコマ）を見せる（再生前の動画は Android で黒く見えることがある）

### 起動
- 起動・再読み込みは必ず川（`/`）から（`_layout.tsx` で最初の1回だけ `router.replace('/')`）。Expo Go は再読み込みで最後の画面から再開してしまう
- 遷移の段階は `idle / forward / atCloud / reverse` で管理（`phaseRef` で二重実行を防ぐ）

### 拾ったことば（ワードクラウド）— `src/app/words.tsx`
- 背景: **川が流れ続ける4秒ループ動画** `assets/video/cloud_bg.mp4`（ユーザー要望「振り返りでも川が流れていてほしい」）。最初のコマは遷移動画の最後のコマと完全に同じ絵（差0）なので切り替わりは見えない。下に同じ1コマ目 `cloud_bg.jpg` を敷く。`coverRect()` で川と同じ切り取り、`surfaceType="textureView"`
- 上: 「← 川へ」・タイトル「拾ったことば」。下: 「つながりを見る」（→ `/archive`）
- **ワードクラウド（2026-10-04 仮データで実装）**: 計算は `src/wordCloud.ts`（RN に依存しないので node で検証できる）、カテゴリは `src/words.ts` の `WORD_CATEGORY`
  - **文字の大きさ＝回数**（16＋回数×2px、上限40）、**文字の色＝カテゴリ**（`CATEGORY_COLOR`、淡い5色）、**文字のキラキラの度合い＝強さの平均**。位置に意味は持たせない。式は SPEC
  - **キラキラは文字そのもの**（ユーザー指定「星はいらない。文字がキラキラしてその度合いで強さ」）。同じ文字の「光る写し」（白へ寄せた色＋カテゴリ色の `textShadow`）を上に重ね、写しの層の不透明度をまたたかせる。写しの濃さ・にじみが強さで決まり、強さ0.25以下は写しなし
  - またたきは `SPARKLE_GROUPS`=3 の層ごとに `useAnimatedStyle` 1本（共通の時計 `clock` を2.4秒でループ）。言葉ごとにアニメーションを持たせない（NG「泡ごとにアニメーション」と同じ理由）。グループは言葉の hash で決め、7/7/7 と偏らないことを数値で確認
  - 写しの層は文字の上に重ね `pointerEvents="none"`。タップが下の言葉に届くことを `elementFromPoint` で確かめる
  - **周りの光（強さ）も重ねる**（ユーザー判断「パラメータに幅があってわかりやすい」）: 言葉の後ろに `HaloLayer`（グループごとの全画面 `Svg`＋`RadialGradient` の円）。**半径は強さだけ**（16＋40×k px×縮小率）で文字の大きさに比例させない（比例させると回数と混ざる）。光の層も同じ時計で 0.55〜1倍に息づく
  - 試した順: 文字の濃淡（差が見えない）→ 後ろの光の円（文字がクリーム色で色分けが弱い）→ 言葉のまわりの星（ユーザー「星はいらない」）→ 文字そのもののキラキラ → ＋周りの光（決定）
  - 配置: 大きい言葉から、中心から渦を巻いて空いている場所へ。入りきらなければ全体を同じ割合で縮める（**間隔も一緒に縮める**）。光が文字の外へ出る分の 1/4 を置き場所の判定に含め、「ほかの言葉の中心が光の内側70%に入る組」が0か node で確かめる（SE で0.75倍・最小13.5px）
  - **またたきの確認は時間を追って数値で**: 層の不透明度を0.6秒おきに4回読む（静止画では動いているか分からない）。最初の読み込み直後はアニメーションが始まる前で 1.00 のままに見えることがある（2回目に測ると動いていた）。様子は Playwright の `recordVideo` で webm に録ってユーザーに渡せる
  - 光る写しの文字も `div[dir=auto]` なので、Playwright で言葉を探すと同じ言葉が2つ出る。タップ確認は `closest('[tabindex],[role=button]')` でボタンかどうかを見る（写しを本物と取り違えて「届かない」と誤判定した）
  - **置く範囲は画面の上 96px〜高さの6割**。7割だと下の言葉が木にかかる
  - 間隔は横12・縦8px（×縮小率²）。詰めると「単純なワードクラウド」に見える
  - `numberOfLines` は使わず、幅も固定しない（文字が「…」で切れる）。タップで `/archive?word=…`
  - 画面下に凡例（色の点＋カテゴリ名、bottom 100）とヒント「文字の大きさ＝拾った回数　キラキラ・光＝気持ちの強さ」（bottom 76、常に表示）。ヒントは SE で1行に収まる長さにする（「キラキラと光の広がり」だと端が切れかけた）
  - 本物の記録（`captures.listByUser` → `aggregate()`）にはまだつないでいない。今は `SAMPLE_STATS`

## React Native実装注意点

- `expo-linear-gradient`でグラデーション背景（Canvasの代替）
- `react-native-reanimated` v4.5.1: SharedValue操作はplain関数内で
- `expo-haptics`: キャプチャ時に2回（開始Light、離すMedium）
- `BlurView`はAndroidで不安定なため使用しない
- `position: 'absolute'`で泡を配置
- 泡は`overflow: hidden`のViewでラップしてクリップする
- `wordsRef`で泡の現在位置をリアルタイム追跡（スポーン判定に使用）
- ESLintルール`react-hooks/immutability`に注意

### Web版で確認するときの注意（2026-10-03）
- **この環境では Metro がファイルの変更を検知しないことがある**（WSL）。古いコードのまま画面を撮って「泡が流れない」と誤解し、時間を失った。**撮る前に、配信中のコードに今回の変更が入っているか確かめる**:
  ```bash
  U=$(curl -s http://localhost:PORT | grep -o 'src="[^"]*entry[^"]*"' | head -1 | sed 's/src="//;s/"$//')
  curl -s "http://localhost:PORT$U" | grep -c "今回変えた文字列"
  ```
  0 なら Metro を起動し直す（`touch` では直らない）。**探す文字列は英字の識別子にする**（日本語はバンドル内でエスケープされ、新しいコードでも0件になる）
- 8081 はユーザーの Expo が使っていることがあるので、自分の確認用は別ポート（例: `CI=1 npx expo start --web --port 8091`）。終わったら自分が起動した分だけ止める
- **重さ・カクつきは数値で測ってから直す**: Playwright で CDP `Emulation.setCPUThrottlingRate: 4`（スマホ相当）にし、rAF の間隔で「34ms 超のコマ数」と longtask の合計を測る（スクラッチパッドの `jank.mjs`）。原因は CDP `Profiler` で関数ごとの時間を見る（`prof.mjs`）。泡の動きのなめらかさは1つの泡の位置を毎コマ記録して速さのばらつきを見る（`motion.mjs`。中央値だけでなく**最大値**も見る。跳ねは最大値にしか出ない）。直す前と後を同じ条件で比べる
- **Web の数値がよくても実機（Expo Go）は別**: 実機は JS が遅れる・動画の再生開始が遅れる。JS のタイマーや「押した時刻」に依存した動きは、Web で測ってなめらかでも実機でカクつく・ずれる。設計の段階で UI スレッド／イベント基準にする
- 動きの確認は、Playwright で数秒おきに泡の文字と位置を読み取る（静止画1枚では流れているか分からない）。流し方の調整は、同じ計算を node で動かしてから入れる（泡の数・重なりを数値で）
- Playwright の Chromium でも H.264 の動画は再生される（以前「再生しない」と書いていたのは誤り。実際は setup で play していたため止まっていた）。動画が動いているかは `document.querySelectorAll('video')` の `currentTime` が進むかで確かめる（スクラッチパッドの `river_video.mjs` / `words_video.mjs`）

### 確認のルール
- **確認は常に iPhone SE（375×667）のみ** — `node scripts/screenshot.mjs`
- ボタンを足したら、ボタンの座標で一番上にある要素がボタンか（`document.elementFromPoint`）を確かめ、`touchscreen.tap` で押す
- 泡の位置や文字は、画面幅に対する割合で決める（固定pxで画面端に置かない）

### 効率化の原則（品質を落とさずに時間短縮）
次の3点を守ることで、試行回数を減らし品質を保つ：

1. **「自動検証できる部分は実装前に検証する」**
   - Metro が古いコードを配信していないか確認（撮る前に必ず）
   - 複雑な計算（泡の流れ方・間隔など）は node で検証してから実装
   - 判定基準（中心か端か）は実装前に決める → コードの修正が減る

2. **「判定基準・座標計算は一度で決める」**
   - 泡の消える判定 → 端座標(`w.x`/`w.x+bw`)で統一
   - 泡の浮かび上がり → 水面から1.2秒で浮上（決定済み）
   - 泡の間隔 → 大きさに比例させる（決定済み）
   - 一度決めたら「要件」として固定、試行中に変更しない（変更すると試行回数が増える）

3. **「複雑な流れは数値検証してから実装する」**
   - 泡の数・重なりはシミュレーションで確認（Playwright や node スクリプト）
   - 静止画1枚では「流れているか」判断できない → 複数フレーム読み取り
   - 計算結果（「奥からだけ出すと6個で頭打ち」など）が見た目にも反映されることを確認

## NGパターン（技術実装）

- **押されている泡を「後ろを止める壁」にすると、後ろの泡が列になって固まる**: 押した泡の `s` で止まるので、追いついた泡はそこで衝突して止まり、次も止まる…と連鎖する（実測: 4秒のあいだ1秒以上止まった泡 3.7個 / 押した泡の真後ろの最小隙間 2.8px = ほぼ接触）。押された泡は `done`（衝突の集合）に入れず、**横によけて通す**。泡には `drift`（横ずれ px）を持たせ、前方の障害・押された泡の横へ `AVOID_SPEED` px/秒で滑らせる。前方の泡も障害なので、よけたい相手は「押された泡」だけ 말고**「このコマで止まった泡」**も含める。列の入口は一番手前の泡なので、ここをよけないと列が解けない

- **前後は画面座標の y で判定しない（川は S 字に曲がっている）**: すぐ後ろの泡は y が同じかむしろ**小さく**なる（= 奥に見える）。y で前後を判定すると、よけるべき泡を「通過済み」と誤認して列が解けない。逆に、 통과済みの泡まで止めて固まる。前後は必ず川筋に沿った距離 `s` で判定する（`s` が大きい方が手前）

- **`hitsHeld` の前後判定を逆にすると、押した泡に重なったままになる**: `held.s <= b.s` をスキップする（= 押した泡が手前にあるときだけ敵にする）が逆になっていると、押した泡の**後ろ**にある泡が制約を受けずにそのまま重なる。実装したら `押した泡との重なり=0` を数値で確認する

- **横よけの重なり判定に押された泡を忘れると、よける動作で押した泡に踏み込む**: `sideIsFree` に渡す「他の泡」の配列に押された泡を入れておく。入れないと、横にずらす動作そのもので押した泡に重なる

- **波紋を泡より外に出すと「障害物の境目」に見える**: 波紋の直径が泡の 1.6 倍（左右に 24px はみ出す）だと、後ろの泡は波紋の手前で止まるので「波紋が障害物」と見える。直径を泡の 1.1 倍以内に収める。長押しのリングや波紋のような「見える円」は、観察者が位置の境界として認識する。見えるリングはすべて泡に密着させる（`RING_PADDING` は 6 程度）

- **等間隔・高opacity の水平線は「仕切り線」に見える**: 過去に等間隔波線 → WaterFlow → どちらも「横棒」に見えて失敗。水平線を追加する場合は①不規則な間隔②opacity 0.04〜0.07（極めて薄い）③strokeWidth 0.8〜1px④明確な sine 曲線（straight line はNG）⑤アニメーションで流す、すべて同時に守ること

- **泡の端フェードを中心座標で計算すると端にかかった泡が透明にならない**: `w.x + bw/2`（中心）基準ではなく、左フェードは `w.x`（左端）、右フェードは `w.x + bw`（右端）を基準に計算すること。中心が画面内でも泡の端が画面外に出ていれば見切れが発生する
- **泡を水面から離す演出（昇る・飛ぶ）で、波紋・映り込みも一緒に動かす**: 空に楕円が浮いて不自然。水に属する部品は水面に残すか、離れ始めにすぐ消す
- **ボタンなどのハンドラで SharedValue に `.value =` で代入／`useVideoPlayer` のプレーヤーのプロパティに代入**: `react-hooks/immutability` エラー。`sv.set(...)`、`player.replay()` などのメソッドを使う。ref を描画中に更新するのも NG（effect の中で）
- **泡の位置を短い間隔（0.05秒）の React 再描画で動かす**: スマホでカクつき・重い。CPU 4倍遅い Web で川を眺めるだけで 11コマ/秒、3秒中2.5秒が JS で埋まっていた。位置は粗く計算し、間は共通の時計で補間する（上の「動かし方」）
- **泡ごとにアニメーション（位置x・y・透明度・ぷかぷか）を持たせる**: 11個×4本＝44本。Web では同じスレッドなので重い
- **泡の位置を JS で計算して、間を補間する（0.2秒ごとに次の位置を渡す）**: スマホの JS が遅れるたびに泡が目的地で止まり、カクつく（Web で測ってもなめらかだったのに実機でカクついた）。動き続けるものは UI スレッドで毎コマ計算する
- **大きさが変わるたびに泡を描き直す（大きさを React の props で渡す）**: 描き直した1コマだけ新しい大きさと古い位置の計算が食い違い、泡が跳ねる（1つの泡を毎コマ記録すると速さの最大が普段の6倍）。一定の大きさで描いて scale する
- **遷移の演出・タイマーを押した時刻から数える**: 動画の再生開始が遅れる実機でずれる。再生開始のイベントから数える
- **`useVideoPlayer` の作成時（setup）に `play()` する**: Web では動画の要素がまだ無いので再生されず、最初のコマのまま止まる（川の動画が Web でずっと止まっていたのに気づかなかった）。`useEffect(() => player.play(), [player])` で画面に出てから再生。動画を足したら Playwright で `video.currentTime` が進むか確かめる
- **Android で `VideoView` を重ねる・透明度で出し入れするのに標準の SurfaceView のまま**: SurfaceView は重なり順と親の透明度を無視するので、遷移動画が川の動画に隠れて「上を向くアニメーションが出ない」。重ねる動画はすべて `surfaceType="textureView"`（Web では再現しないので実機でしか気づけない）
- **戻る演出で、消えた方向（空）から泡を戻す**: 不自然（ユーザー指摘）。泡は川のもの。元の水面から浮かび上がらせる
- **遷移中も裏で泡の計算・川の動画を動かし続ける**: 動画のデコードと再描画が重なって遷移がカクつく。覆われている間は止める
- **横幅いっぱいの `position:absolute` の文字（タイトルなど）をボタンより後に置く**: スマホでは後の要素が上に重なり、ボタンが押せない（Web の文字指定クリックでは気づけない）。タイトルは先に置き `pointerEvents="none"` の View で包む。ボタンには `hitSlop`
- **Web での押せる確認を `getByText().click()` だけで済ませる**: 文字を直接押すので、上に重なった透明な要素を見逃す。ボタンの座標で `elementFromPoint` と `touchscreen.tap` を使って確かめる
- **Context の setWords 型を `(words: T[]) => void` にする**: React の setState は関数updater `(prev) => T[]` を受け付けるが、Context 型が `(words: T[]) => void` だと型エラーになる。`Dispatch<SetStateAction<T[]>>` で定義すること
- **Context の RiverWord 型とローカルの RiverWord 型を分離する**: Context と index.tsx で同名の型を別定義すると「Two different types with this name exist」型エラーが起きる。型は Context に一元化するか、共通ファイルに切り出す

- **ティール背景に有色オーバーレイで「光」を作れない**: ティール背景に暖色・黄色・白以外の色を opacity < 0.5 で重ねると、アルファブレンドにより「別の色調のティール」になり、光ではなく浮遊物（海藻、バーなど）に見える。光のエフェクトは①純白 `rgba(255,255,255,1)` を使う、②もしくは sparkle（点）のような小さく明確な形にする。大きな形は背景の色と混ざって異物感が出る
- **星画面へ接続しようとして背景を暗くしすぎる**: 川画面は夕方の水面感が必要。全体を暗くすると「夜」になってしまい川に見えない。上部は明るいティール/ブルーを保ちつつ下部だけを徐々に暗くする

## 解決済みの問題

- ~~テキスト省略（...）が出る~~ → `numberOfLines`削除、`getBubbleDimensions`でサイズ対応
- ~~左右端で文字が切れる~~ → edgeOpacityを泡の左端/右端座標基準で計算（`w.x` / `w.x+bw`）
- ~~泡サイズの格差が大きすぎる~~ → 上限112pxに設定
- ~~等間隔の波線が仕切り線に見える~~ → WaterFlowに置き換え
- ~~川に見えない（川岸がない）~~ → RiverBanks SVGコンポーネント（上下の曲線シルエット）で川の形が認識できるようになった
- ~~川らしく見えない（水面の質感不足）~~ → WaterRipple SVGコンポーネント（不規則間隔のsine波5本、opacity 0.07〜0.10、14秒で1周する横スクロールアニメーション）で水面の流れが表現できるようになった
- ~~「水面」にはなったが「川の風景」にない~~ → SceneSilhouette（RiverBanksを置き換え）：①夕方の空グラデーション（茜→金→ティール。水面上部は霞がかった薄色で遠近感）②密な樹冠ラインSVG（水平接線付き三次ベジェ、峰26点）③樹冠をY軸反転した水面反射シルエット（opacity 0.22）④木の影オーバーレイ（LinearGradient）により「川を見ている視点」が確立された。水面反射が遠近感の決め手
