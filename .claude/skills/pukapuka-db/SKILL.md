# pukapuka データ設計スキル

Convex の表と保存する項目を決めるためのスキル。**Convex の書き方**（関数・index・検証）は `convex/_generated/ai/guidelines.md` と `convex-design` / `convex-expert` に任せる。このスキルは「**pukapuka に何を保存するか**」の担当。
決まった事実は設計書 `docs/SPEC.md` の **G. データ**・**H. ログイン**・第2部 C3. に書く（書き方は `/pukapuka-spec`）。このスキルには**進め方と見方**だけを書き、事実は二重に書かない。

---

## 進め方

1. **先に壁打ち、コードはあと。**勝手にスキーマや関数を書き始めない。まず「どの画面の、どの分析に要るか」を一緒に決める
2. 相談では、むずかしい言葉を使わず、例で話す（ユーザーは DB や数学の知識がなく、聞けない。使えそうな手は先に提案する）。返事は日本語
3. 決まったら、先に SPEC の G./H. に書く（決定日つき）。そのあとコードにする
4. 表やインデックスを変えたら、`npx convex dev --once` で送り、`npx convex run` で保存と読み出しを1回試す。画面はブラウザ（`http://127.0.0.1:8081`）とスマホで確かめる
5. このスキルの「いまの形」「迷っていること」も、決まるたびに更新する

## 決めるときの見方

- **使う分析があるか。**「どの画面の、どの計算に要るか」を言えない項目は保存しない（例外は、あとから取り戻せないもの。足すときはユーザーと決める）
- **記録は本人のもの。**気持ちの記録なので、他の人から読めない・売らない・AI の会社に残さない。外に送るのは最小限（SPEC D. の決定）
- **仕組みで独立させるもの：**拾った記録（川）と気づきの日記は、データを渡し合わない。表も分け、つなぐのは本人の気づきだけ
- **ログインなし → ログインへ移っても記録を失わない。**`deviceId` から `userId` への引き継ぎの手順を先に決めてから、ログインを足す
- **数を出さない画面のために、数を溜めない。**スタンプの数・連続日数・催促のための項目は持たない
- **小さく足す。**表は MVP では最小にして、足したくなったら足す。作り直しになる決め方（例：後から意味が変わる項目）は避ける
- 読み出しは index で絞る（全件を読まない）。期間は呼び出し側で決める

## いまの形（2026-10-08。事実は SPEC G.、コードは `convex/schema.ts`）

- 表 `captures`：`deviceId?`・`userId?`・`capturedAt`・`wordId`（言葉の表の番号）・`frame`・`strength`。2026-10-11 に `word`（文字）から書きかえた。アプリは文字で送り、Convex が `convex/words.ts` の `findWordId` で番号にする。読むときは `wordTexts` で文字に戻す。関数は `captures.add`（保存）と `captures.listRecent`（直近 N 日、新しい順）
- 表 `diaries`（日記、2026-10-11）：`deviceId`・`day`（dayKey の文字）・`text`（4000字まで）・`savedAt`。index `by_deviceId_and_day`。関数は `diary.save`（1日1つ、同じ日はおきかえ、空なら消す）・`diary.remove`・`diary.list`。拾った記録とはつなげない（作り方は `/pukapuka-diary`）
- 表 `words`（言葉の表、2026-10-11）：`text`・`category`・`source`（fixed/ai/own/season/old）・`owner?`・`parent?`（名札）・`kind?`（near/abstract）・`theme?`。決まった言葉は `npx convex run words:seedFixed` で入れる（src/words.ts を変えたら呼び直す）
- 表 `flows`（流れた記録、2026-10-11）：`deviceId`・`day`・`counts`（言葉の番号・枠・回数の並び。Convex の record は日本語のキーを持てないので並びにした）・`updatedAt`。index `by_deviceId_and_day`。関数は `flows.add`（同じ日に足し算）・`flows.listDays`。数えるのは `src/useFlows.ts` の `countFlow`（`src/app/index.tsx` の泡が浮かんだとき）。開発用に `test-flow-…` の1行が入っている
- 端末の ID は `src/useCaptures.ts` が作って AsyncStorage（ブラウザは localStorage）に覚える。**ブラウザは開くアドレスごとに別 ID になる**（`localhost` と `127.0.0.1` は別。127.0.0.1 で開く）
- 日付は保存しない（決定 2026-10-09）。時刻だけ残し、「同じ日」は端末の時計で0時切り。海外の人が使う公開のときに決め直す
- 保存の確認は済み（ブラウザ・スマホ。2026-10-08）
- 開発用のダミーの人：`convex/demo.ts` の `seedDemo`（`npx convex run demo:seedDemo '{"days":60}'`）で、専用の目印に60日ぶんを入れる。web で `?demo=1` をつけて開くと、その記録で動く（保存はしない）。夜空など、数週間たまった後の見え方を確かめるため
- いまの保存先は**開発用**の Convex。本番用は公開前に別に用意する

## 決まったが、まだコードにない（2026-10-11 壁打ち。事実は SPEC G.。AI 側は `/pukapuka-ai`）

- **言葉の表**（正規化）：決まった言葉も AI の言葉・自分の言葉も1つの表に。項目は言葉・種類（6つ）・どこから来たか（決まった／AI／自分／季節…）・持ち主（みんな／その人）・生まれ（元の言葉の番号。変えない名札）・近い言葉か抽象的に近い言葉か・共通点（AI の解釈）。分析は名札で数え、抽象的に近い言葉は元の言葉に入れない。他の人の言葉は持ち主で絞って見せない
- **流れた記録**：**1日1行**にまとめ、中に「言葉の番号・どの枠か・回数」を入れる（1語ごとに1行だと1年で約3万行。1日1行なら365行）。端末で数えて、川を閉じたときにまとめて送る。使い道は夕空の大きさ（流れた回数のうち何回拾ったか）・細かい言葉の「よく選んでいます」・本物の泡の数で夜明けを確かめ直すこと
- **拾った記録**は言葉の番号と「どの枠か」を持つ。**古い記録も番号に書きかえる**（先に写しをとる。`convex-migrate`）
- Convex には JOIN がないので、言葉の表はコードでつなぐ（数百語なので困らない）

## 迷っていること（決まったら SPEC に移し、ここから消す）

1. **「していること」の持ち方**：言葉の1種類として `captures` に入れる（いまの作り）か、別の表か
2. **流れ（何のあとに何が来たか）**：保存せず、時刻の順から毎回計算する（案）。計算が重くなったら集計表を足す
3. ~~気づきの日記の表~~ → 決めて作った（2026-10-11。上の `diaries`）
4. **ログインの引き継ぎ**：`deviceId` の記録を `userId` に付け替える手順
5. **データが増えたときの読み方**：`listRecent` は5000件まで。1年・毎日拾う場合は足りるか

## 確かめ方のコマンド

```bash
npx convex dev --once                         # 関数と表を送る
npx convex data captures --limit 10           # 保存の中身を見る
npx convex run captures:listRecent '{"deviceId":"<ID>","days":7}'
npx convex run demo:seedDemo '{"days":60}'   # ダミーの人を入れ直す（開発用）
```

開発サーバーは 8081（ユーザー用）に触らない。確認用は 8091（`CI=1` なし）。
