# pukapuka Convex スキル

Convex（サーバーとデータ）の**読み書きの量**を、無料枠の中に収める。何を保存するか（表の形）を決めるのは `/pukapuka-db`。このスキルは、量を測って、多すぎる所を直す。
Convex の書き方の決まりは `convex/_generated/ai/guidelines.md`（必ず先に読む）。

**決まり**
- **有料にはしない**（テストの間は無料枠だけ。メモリ `feedback_no_paid_plans`）
- **表・query・mutation を足す・変えたら、`scripts/convex/usage.sh` で1回あたりの量を測る**。下の「目安」を超えたら、直してから報告する
- **直す前に測る。直したら同じ手順で測り直す**。数字は 4. の表に書く
- 保存の形を変えるときは、今までの記録を消さない（写してから使う）。`/pukapuka-db` の「先に案を決める」に従い、案と見込み（今 → 案）をユーザーに見せて「はい」をもらってから作る
- 報告は日本語。数字は表と短い文で

## 1. 無料枠と目安

| もの | 無料枠 | 意味 |
|---|---|---|
| Database I/O（読み＋書き） | **1GB／月**（＝1日 約33MB） | いちばん先に足りなくなる（2026-10 に 1.71GB で超えた） |
| 関数の呼び出し | 100万回／月 | まだ余裕（1日 1〜2万回） |
| 保存 | 512MB | まだ余裕（約30MB） |

**1回あたりの目安**（これを超えたら直す）

| 種類 | 目安 | 理由 |
|---|---|---|
| アプリを開くたびに走る query | 合計 50KB 以下 | 1GB ÷ 50KB ＝ 約2万回開ける |
| 何かが変わるたびに読み直す query（購読） | 1回 20KB 以下 | 書き込みのたびに、開いている全員の画面で読み直す |
| 1分ごと・泡ごとの mutation | 1回 10KB 以下 | 1人が1時間に何十回も呼ぶ |

**web 版**：main にマージすると、Cloudflare の Workers Builds が自動でデプロイする（https://pukapuka.pukapuka-app.workers.dev/）。つなぎ先は開発用 `tacit-pelican-314`。サーバー側（convex/）の直しは `npx convex dev --once` の時点で、家族の web 版にも効く（呼び出し方を変えないこと）

## 2. 測り方

```bash
scripts/convex/usage.sh 60
```
- 直近60分の、関数ごとの回数・1回の読み書き・合計と、「このペースだと1日何MB」を出す
- 中身は `npx convex logs --success --jsonl` の `usageStats`（`databaseIoReadBytes`・`databaseIoWriteBytes`）。開発用（dev）の記録
- `convex logs` は終わらずに待ち続けるので、`timeout` で切る（そのまま `| python` に渡すと、切られて何も出ない）
- **自分のテスト（読み込み直し・何往復）も数に入る**。1回あたりの量で判断し、合計はテストの分だと割り引く
- 月の合計は、Convex の画面：右上の黄色い帯の「View Usage」→「Database I/O」の「>」（日ごとの棒。日付は UTC）

## 3. 直し方（よく効く順）

1. **大きな1件を、小さな行に分ける**：1人1件に全部を書き足す作り（例：好みのメモ `prefs`、約0.45MB）は、少し変えるたびに丸ごと読み書きになる。言葉ごと・日ごとの行に分け、変わる行だけ直す
2. **変わる所と変わらない所を、別の query にする**：query は、読んだデータが変わると自動でやり直す。今日の分（毎分変わる）と過去の日（変わらない）を1つで読むと、毎分、過去まで読み直す
3. **アプリを開くたびに全部を `.collect()` しない**：一覧は、箱ごとの塊など、小さな写しを作って読む（例：倉庫の言葉 `boxLists`）
4. **要らない query は `'skip'`**：使わない画面・使わない動き方（例：倉庫で動くときの前の言葉）は読まない。「届いてから決める」だと、最初の1回だけ読んでしまう。届いたその場で決める
5. **重い表（ベクトルなど）は、「あるかどうか」を調べるためだけに読まない**：印（例：`words.vec`）を付ける

## 5. 残っている課題（直したら 4. へ）

- **`flows:add`（1分ごと）が 読み約58KB・書き約54KB**。その1分に流れた言葉ごとに、流れた記録の行と好みのカードを1枚ずつ直す（1語 約1.3KB。索引の書き込みも数に入る）。手：送る間隔を長くする（同じ言葉がまとまる）、拾ったことのない言葉はカードを直さない（ただし、初めて拾ったときの割合の計算をどうするか決める）
- **今月の超過（1.71GB）は減らない**。11月1日に戻る。止められるかは未確認。止まったら、すぐユーザーに知らせる
