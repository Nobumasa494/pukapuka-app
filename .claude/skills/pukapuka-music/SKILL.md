# pukapuka 音楽スキル

pukapukaアプリの曲と効果音を作るためのスキル。曲・効果音を新しく作る／直す／アプリでの鳴らし方を変えるときに呼び出す。
**世界観・画面の意味は `/pukapuka-design`、決まったことの一覧は `docs/SPEC.md` の「音」。このスキルは作り方と確かめ方の技術メモ。**

### ユーザーが決めたこと（変えない）
- 参考は**ジブリ（久石譲）・どうぶつの森・Sky 星を紡ぐ子どもたち**。**メロディはまねない**（音色・和音・鳴らし方の傾向だけ取り入れる）
- 方向は**試作 B「空」**（まばらなピアノ＋ハープ＋弦＋深い残響）。試作 A「森」（カリンバ・マリンバの軽快なもの）は不採用
- **作り方は Python でコードから合成**（2026-10-04。素材の利用規約の心配がない・作り直せる・git で履歴とレビューができる）
- **3画面で別々の曲**（「同じものを使い回さず別のBGMに」）。和音の進行・メロディ・拍子・主役の楽器を変える。そろえるのは調（D メジャー／B マイナー）だけ
- **場面ごとに雰囲気を変える**（2026-10-04「3曲とも同じ曲に聞こえる。場面にあった曲調で」）: 川＝温かくゆっくり／拾ったことば＝明るく弾む（キラキラ光る言葉）／夜＝暗く拍のない内省（星座を見て振り返る）。**明るさ・拍の速さ・拍のはっきりさ・音域・残響**を曲ごとに大きく離す
- **3曲と拾った音はすべて決定**（2026-10-04「これでいいと思う」）。その後「高くてキンキンする」で、全体を -5 半音・高い楽器の音域を下げた（音の高さは低め・耳に刺さらないことが決まりごと）。**決めた音は変えない**。変えるときは試聴ファイルを聴いてもらい、OK をもらってから `uv run build.py --approve`
- 決めた音は `scripts/music/approved.json` に指紋（書き出す前の音のハッシュと 0.5秒ごとの音量）がある。`build.py` が毎回これと比べて「ビットまで同じ／ほぼ同じ（計算環境の差）／違う」を出す

## 2. 今の作り方

### compose.py の部品
| 部品 | 作り方 | 主な数値 |
|---|---|---|
| `piano` | 倍音を10本まで足す。高い倍音ほど早く消える。弦2本を ±0.6 セントずらしてうなり | 倍音 1/n^1.15、消える時間 4.5秒/(1+0.45(n-1)) |
| `felt_piano` | 倍音を6本に絞り、立ち上がり 12ms。低いノイズの「トン」を少し | 倍音 0.55^(n-1)/n |
| `harp` | はじく位置 0.18 で倍音の強さを決める（sin(nπp)/n^1.6） | 倍音12本、3.2秒 |
| `music_box` | 芯＋すぐ消える高い金属の響き（5.27倍・8.9倍） | 1.5秒 |
| `bell` | 整数倍でない倍音（1, 2, 3, 4.16, 5.43） | 2.2秒 |
| `pizz` | ピチカート: 倍音8本が 0.28秒ほどで消える | ベース用 |
| `celesta` | チェレスタ: 1・2・3・4倍の倍音＋たたく音。書いた音で鳴らし、1オクターブ上を gain 0.3 で重ねてキラキラを残す（1オクターブ上だけだと最高 E7 で耳が痛かった。書いた音だけだと明るさが川に近づく） | 1.1秒 |
| `marimba` | 1・4・9.9倍。ブルーアワーの裏拍の和音 | 0.55秒 |
| `shaker` | 5〜12kHz のノイズの短い粒 | 40ms |
| `bowed` | 弓で弾く弦: のこぎり波に近い倍音、0.9秒かけて立ち上がり、後半に 5Hz のゆらぎ | 夜の低い弦 |
| `glass` | ほぼ純音＋2.76倍の響きを少し。立ち上がり 40ms | 夜の星 |
| `bubble` | 拾った音の泡: 純音の高さが 0.55倍から 25ms で目標へ上がる。0.07秒で消える | 拾った音 |
| `soft_glass` | 柔らかいガラス: 純音＋すぐ消える2倍の響き（0.12）。立ち上がり 12ms | 拾った音の余韻 |
| `kalimba` | 試作 A 用（`version_river` の乱数の順を保つためだけに呼ぶ） | — |
| `music_box` / `felt_piano` | 前の版のブルーアワー・夜で使った（今は使っていない。部品として残す） | — |
| `pad` | 1音を −6・0・+6 セントの3本に重ね、倍音 `bright` 本。立ち上がり `atk`・余韻 `rel`、`vib` で 5.2Hz のゆらぎ | 割る数 = 音の数×3 |
| `water` / `wind` | 茶色っぽいノイズを帯域で絞り、ゆっくり揺らす（水はまばらな水滴も） | 水 350〜2600Hz、風 150〜900Hz |
| `reverb_ir` | 左右別のノイズを、高い音ほど早く減衰させた響き | `t60`（低い音）・`t60_hi`（高い音） |
| `soften` | ループのまま FFT で高い帯域をなだらかに下げる（1.5kHz 中心の1次シェルフで -6dB）。周期として扱うのでつなぎ目は保たれる。今は川だけ | — |
| `Mix` | `add(音, 時刻, pan, gain, send)` で置き、`render(ループ秒, wet, t60, t60_hi)` で残響を足して**終わりの残響を頭へ回し込む** | ピーク 0.89 にそろえる |
| `seamless` | 風・水のノイズを、それ自体でつながるループにする（終わりの先を頭に1秒かけて重ねる） | — |

### 楽譜はデータで書く
- 和音: `(ベースのMIDI番号, [和音の音])` の並び（`CHORDS`＝川、`CLOUD_CHORDS`）。1小節に1つ。夜は拍がないので `NIGHT_SECTIONS` に `(秒, 持続音, 和音, 弓の弦の音[(秒, 音, 長さ)])`
- スマホのスピーカーは 80〜100Hz より下がほぼ鳴らない。**持続音やベースは B1（62Hz）より下に置かない**（夜の初版は E1＝41Hz で、スマホでは空っぽに聞こえるところだった）
- 楽譜の MIDI 番号は D メジャーのまま書く。鳴る高さは `mtof` が `TRANSPOSE` を足して決める（高さはすべて `mtof` を通すこと。直接 Hz を書くと一緒に動かない）。`TRANSPOSE` を変えたら、いちばん低い音（今は E2→B1）が B1 を下回らないか見る
- メロディ: `(小節, 拍, MIDI番号, 長さ[拍])`。音は**レ ミ ファ# ラ シ**（五音音階）から選ぶ。拾った音（ラ シ レ ミ ファ#）と同じ5音なので、どの曲の上でもぶつかりにくい
- 乱数は曲ごとに種を固定（`version_river` 7・`version_cloud` 11・`version_night` 23・`chimes` 100+i）。**`version_river` は試作のときと同じ順（A を作ってから B）で乱数を使う**ので、A を消したり順を変えたりしない

### 書き出し（build.py）
1. 曲を作る → 2. 長さを **1024 サンプルの倍数**に FFT で伸ばす（`scipy.signal.resample`。周期として扱うのでつなぎ目は保たれる。速さの差は 0.06% 以下）→ 3. ffmpeg の ebur128 で測って **-20 LUFS** にそろえる → 4. **前後に自分の終わり・頭を 8192 サンプルずつ足して**（`CONTEXT`）AAC 112kbps にし（`-movie_timescale 44100`）、**MP4 の編集リスト（elst）を「頭の 8192＋AAC の前置き 1024 を飛ばし、ちょうど n サンプル鳴らす」に書き換える**（`set_loop_edit`）。効果音は 96kbps でそのまま
- 4 の理由: AAC は前の区切りと重ねて音を作るので、何もない所から始まる頭の約 1024 サンプルが崩れる（夜の初版で頭の誤差が真ん中の 8 倍、ブルーアワーも 5 倍）。前後に続きを置けば、頭も終わりも正しく作られる。iPhone の expo-audio は AVQueuePlayer に同じ曲を並べてループし、Android は ExoPlayer の繰り返し。どちらも編集リストどおりに飛ばして継ぎ目なく鳴らす
- `build.py` はデコードし直して「長さがちょうど n」「頭と終わりの誤差が真ん中の2倍未満」を確かめ、外れたら止まる
- 5. 合成した音（書き出す前）の指紋を `approved.json` と比べて出す。「!! 決めた音と違う」が出たら、意図した変更か確かめる。意図した変更でユーザーが聴いて OK なら `--approve`。ほかの PC（WSL など）では浮動小数の計算の差でハッシュが変わることがあり、そのときは音量の並びで「ほぼ同じ」と出る
- 実行: `cd scripts/music && uv run build.py`（1曲だけ書き出すときは `--only me` など。ほかの曲の m4a を書き直さない。`--approve` と一緒に使っても、ほかの曲の指紋は消さない。2026-10-11 に、`--only` のとき `--approve` が最後まで届かず指紋が書かれないまちがいを直した）（曲だけ試すときは `uv run python -c "import compose; ..."` でスクラッチパッドに wav を書く）

### アプリでの鳴らし方（src/ambient.ts）
- `createAudioPlayer` を素のモジュールで持つ（フックの `useAudioPlayer` は、プロパティへの代入が `react-hooks/immutability` で止まる）
- 3曲とも常にループで持ち、`setScene(曲, ms)` で音量を 40ms ごとに目標へ寄せる。0 になったら止める。曲の音量 0.8
- 段階と曲: `SCENE_OF`（`toCloud`→空、`toNight`→夜、`nightToRiver`→川 など、遷移の段階に入った瞬間に次の曲へ）。長さ `MUSIC_FADE_MS`（川⇄空 2000、空⇄夜 3000、夜→川 900、起動 1500）
- 拾った音: 強さ 0.1〜1 → `floor(強さ×5)` 番目（タップ＝ミ、長押しほど高い）、音量 0.5＋0.5×強さ
- **拾った音のプレーヤーは1つの高さに2つ**（`CHIME_VOICES`）。鳴り終わり（`didJustFinish`）で `seekTo(0, 0, 0)` して `ready` にしておき、押したら `ready` のものを**巻き戻しを待たずに** `play`。2つとも鳴っていたら古いほうを止めて、巻き戻しを待ってから鳴らす。`keepAudioSessionActive: true`（鳴り終わるたびに iOS の音のセッションを切らない）
- Web での確認（2026-10-04）: 同じ高さを0.7秒おきに3回 → 1つ目・2つ目・（2つとも鳴っているので）1つ目を巻き戻し、の順で鳴る。鳴り終わったものは頭に戻って止まる
- `setAudioModeAsync({ playsInSilentMode: false, interruptionMode: 'mixWithOthers', shouldPlayInBackground: false })`。アプリが裏から戻ったら、止まっている曲を鳴らし直す
- ♪ ボタンは右下（bottom 34, right 18）。消すと 0.5秒で小さくする。覚えておくかは未決（SPEC）

## 3. 作業のルール（必須）

### 順序
1. このファイルの「1.」「2.」を読む
2. **何を作るか・どう変えるかをユーザーと決める**（どの画面か、雰囲気、参考）。言葉があいまいなとき（「明るく」「にぎやかに」）は、何を変えるか（テンポ・楽器・音の高さ・音の数）を1行で確かめる
3. 道具・言語・ライブラリを足すときは、**決める前にユーザーに聞く**（Python は 2026-10-04 に決定済み。それ以外を足すとき）
4. 作る → **数値で確認**（下の「必ずやる確認」）→ 試聴ファイル（ループ2回分）を送る
5. 方向が分かれるときは**2〜3案を、聴いて違いが分かる幅で**作って選んでもらう
6. ユーザーが選んだら `build.py` で assets に書き出し → `check.py` → アプリで切り替えを確かめる（Web）
7. ユーザーが聴いて OK したら `uv run build.py --approve` で指紋を書き直し、このファイルの「1.」の状態を「決定」にする
8. SPEC の「音」とこのファイルを更新し、「作業時間の記録」に1行足す

### 必ずやる確認（私は音を聴けない。聴いたつもりにならない）
`cd scripts/music && uv run check.py` を通し、次を見る:
1. **音割れ**: peak 0.99 未満
2. **音量**: 曲は -20 LUFS。1秒ごとの音量に、急に消える・跳ねる所がないか
3. **帯域**: 川は <100Hz 15%・100〜400Hz 28%・400〜1.5k 55%（-5 半音で低音が 9% から増えた。イヤホンでこもらないか聴いてもらう）。これから大きく外れたら理由を考える（ブルーアワーの初版は低音がほぼなく 400〜1.5k が 97%＝薄い。その前は <100Hz が 40%＝こもる）
4. **ループ**: 1024 の倍数か。つなぎ目の段差が普段より大きければ、まず**書き出す前の wav で**同じ段差を測る。wav で小さく m4a で大きいなら AAC の頭の崩れ（`build.py` の編集リストの処理が効いていない）。wav でも大きいなら、**ほかの小節の頭（音が鳴り始める所）と比べる**。同じくらいなら音の鳴り始め、飛び抜けていればノイズの層が `seamless` になっていない
5. **決めた音が変わっていないか**: `build.py` の出力の「決めた音とビットまで同じ」を見る（`approved.json` と比べている）。直したくない曲に「!! 決めた音と違う」が出たら、部品（`pad` など）や乱数の順を共有していて巻き込んだ。m4a は AAC が入力のわずかな差で中身を変えるので、m4a 同士では比べない
6. **雰囲気が離れているか**: `check.py` の「明るさ・拍・拍のはっきりさ」。今は（-5 半音にした後）川 606Hz・58・0.55／空 973Hz・96・0.86／夜 305Hz・拍なし（はっきりさ 0.38。拍の BPM は意味のない値が出る）。下げる前は 川 851／空 1778／夜 430Hz で、空が「キンキンする」と言われた。曲を変えたら、ほかの2曲とこの3つが近づいていないか見る（3曲とも 700〜860Hz・44〜63 BPM のときに「同じ曲」と言われた）

### Web での確かめ方（アプリでの切り替え）
- この環境の Chromium は AAC を再生できない。Playwright で m4a の代わりに同じ音の wav を返す（`page.route(/\.m4a(\?|$)/, r => r.fulfill({ body: wav, contentType: 'audio/wav' }))`）
- `page.addInitScript` で `HTMLMediaElement.prototype.play` を包んで要素を集め、0.5秒ごとに各要素の `currentSrc`・`paused`・`volume`・`currentTime` を出す。起動→振り返る→つながりを見る→♪ 2回→川へ戻る を通して、音量が `MUSIC_FADE_MS` どおりに入れ替わるか見る
- **泡を拾うのはマウスでは反応しない**。CDP の `Input.dispatchTouchEvent`（`touchStart` → 待つ → `touchEnd`）で押す。0.1秒なら chime_0・音量 0.55、1.5秒なら chime_3・0.88 前後
- 撮る前に、配信中のバンドルに今回の変更が入っているか確かめる（`/pukapuka-design` の「Web版で確認するときの注意」）

### 速く・品質を落とさずに
- 1曲だけ試すときは `build.py` を回さず、`compose` の関数を直接呼んで wav をスクラッチパッドに書く（全部作り直すと20秒以上）
- 量を決めるとき（低音の大きさなど）は、値を3通り作って帯域の割合を並べて比べてから1つ選ぶ
- 試聴ファイルは `ffmpeg -stream_loop 1 ... -af loudnorm=I=-18` でループ2回分（つなぎ目を聴けるように）にして、`SendUserFile`（display: attach）で送る

## 5. NGパターン

### 作曲
- **既存の曲のメロディをまねる**（著作権）。参考にするのは音色・和音・鳴らし方まで
- **楽器と和音だけ変えて「別の曲」にする**: 3曲とも「ゆっくり・まばら・中くらいの明るさ・深い残響」のままだと、楽器の名前を変えても同じ雰囲気に聞こえる（2026-10-04 指摘。明るさ 716〜862Hz・速さ 44〜63 BPM に固まっていた）。場面の意味から、明るさ・拍の速さとはっきりさ・長調か短調か・音域・残響の長さを決める
- **3画面で同じ和音の進行・メロディを使い回す**: 切り替えが濁らない利点はあるが、ユーザーには「同じ曲」に聞こえる。和音・拍子・楽器から変え、そろえるのは調だけにする
- **メロディや装飾の音に、五音音階（レ ミ ファ# ラ シ）以外を多く使う**: 拾った音とぶつかる。ソ・ド# は和音の中だけにする

### 合成
- **高い楽器を本物の高さのまま鳴らす**（チェレスタを1オクターブ上、ガラス・ベルを6オクターブ目）: 小さなスマホのスピーカーやイヤホンでは耳が痛い（2026-10-04 指摘）。メロディ・飾りの基音は 1.5kHz くらいまでに収め、キラキラは上のオクターブを小さく重ねて出す
- **ゆらぎ（ビブラート）の深さに 2π を余計に掛ける**: 位相の揺れは「周波数の揺れ幅 ÷ 揺れの速さ」（ラジアン）。2π を掛けると約6倍、27セントも揺れて音程が外れる
- **風・水のノイズを、音符と同じように「終わりの残響を頭へ回し込む」でループにする**: ノイズは消えていかないので、つなぎ目に段差ができ、頭の数秒が二重になる。`seamless()` でそれ自体をループにしてから、ループの長さだけ置く
- **乱数を全体で1本にして、作る順で音が変わる**: 曲を足したり順を変えたりすると、選んでもらった曲が変わる。曲ごとに種を固定する
- **低音の量を勘で決める**: 帯域の割合で、川の曲（<100Hz 9%・100〜400Hz 26%）と比べる

### 書き出し
- **速く動く短い音（拾った音の「すっと上がる」）を 96kbps の AAC にする**: 頭の誤差が全体の 3〜4 倍になる。128kbps（ビットレートを上げすぎるとかえってばらつく）
- **前後に足す続きを短くする**（2048 サンプル）: 書き出しの最初の数区切りの崩れが頭に残る（夜を -5 半音にしたとき頭の誤差が真ん中の 2.3 倍。曲をずらして書き出すと同じ所は小さい）。8192 にする
- **ループの長さを 1024 サンプルの倍数にしないまま AAC にする**: 終わりに 8〜20ms 足され、ループのつなぎ目で途切れる。デコードして長さが変わらないか確かめる
- **ループの曲をそのまま AAC にする**: 頭の約 1024 サンプルが崩れる（低い音が鳴り続ける曲ほどひどい）。前後に自分の終わり・頭を足してから書き出し、編集リストで飛ばす。つなぎ目の段差は「最後と最初の1サンプル」だけでなく、デコードした音と書き出す前の音の誤差を頭・終わり・真ん中で比べる
- **編集リストを ffmpeg の既定（時間の単位 1000＝ミリ秒）のまま書き換える**: ループの長さがサンプル単位で書けず、数サンプルずれて継ぎ目ができる。`-movie_timescale 44100` にする
- **ffmpeg の `loudnorm` をループの曲にかける**: 時間で音量を変えるので、つなぎ目で音量がずれる。ebur128 で測って `volume` で一定の量だけ上げ下げする（試聴ファイルは loudnorm でよい）
- **m4a 同士をビットで比べて「変わった」と判断する**: AAC は入力のごくわずかな差でも中身が変わる。比べるのは書き出す前の wav

### 確かめ方
- **「キンキンする」を、重みのない帯域の割合だけで判断する**: エネルギーでは 3kHz より上が 1% 未満でも、耳は 1.5〜5kHz に敏感なのでキンキンして聞こえる。A 特性で重みをつけた 1.5〜6kHz の割合で比べる（下げる前は 川 10%／空 45%／夜 10%、今は 4%／2%／0%）
- **楽器ごとの影響を、楽器を消して作り直して調べるとき、関数を呼ばずに外す**: 乱数の順が変わってほかの楽器の音まで変わる。呼んでから 0 を掛ける
- **雰囲気の違いを測らずに「別の曲にした」と報告する**: `check.py` の明るさ・拍・拍のはっきりさで、ほかの曲と離れているか数値で見る
- **スペクトログラムの絵だけで低音を判断する**: 対数の周波数軸では、低い所が少ない値でも明るく広く描かれる。帯域の割合を数値で見る
- **音を聴かずに「きれいに鳴る」と報告する**: 私は音を聴けない。数値で確かめたことと、聴いてほしいことを分けて書く
- **Web で泡をマウスで押して「拾った音が鳴らない」と判断する**: 泡はタッチでしか反応しない
- **確かめ方のスクリプトをスクラッチパッドにだけ置く**: セッションが変わると消える。繰り返す確認は `scripts/music/` に置く
- **決めた音の見本をスクラッチパッドにだけ置く**: 「ビットまで同じ」を確かめる元がセッションごとに消え、チームの人も確かめられない。指紋を `approved.json` としてリポジトリに置く

### 鳴らし方
- **1つのプレーヤーを `seekTo(0)` で巻き戻しながら、完了を待たずに `play` する**: 続けて拾うと前の音の余韻がぶつっと切れ、iPhone では巻き戻し前の終わりが一瞬鳴る・鳴り出しが遅れる。高さごとに2つ持ち、鳴り終わったら先に頭へ戻しておく
- **`useAudioPlayer`（フック）のプレーヤーのプロパティに代入する**: `react-hooks/immutability` で止まる。`createAudioPlayer` を素のモジュールで持つ
- **曲の切り替えの長さを、遷移の動画と別に決める**: 映像と音がずれる。`MUSIC_FADE_MS` は遷移の動画の長さに合わせる
- **ほかのアプリの音楽を止める（`doNotMix`）／マナーモードで鳴らす**: 隙間時間に開くアプリなので、聴いている音楽を邪魔しない
