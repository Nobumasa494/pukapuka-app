# pukapuka わたしのことスキル

pukapuka の4つ目の画面「わたしのこと」（背景は夜明け）を作る・直す・確かめるためのスキル。画面は 水辺 → 夕空 → 星空 → わたしのこと と、1日がひと回りする。
**何を作るか・なぜかは `docs/SPEC.md`（第1部「MVP」、第2部 C3.・D.）。決めたことは設計書に書く（`/pukapuka-spec`）。このスキルは、作り方・確かめ方・数字の根拠のメモ。** 色と世界観は `/pukapuka-design`、曲は `/pukapuka-music`、保存は `/pukapuka-db`、重さは `/pukapuka-perf`。星空の作り方（検定・見本・スマホの操作）は `/pukapuka-night` がお手本。

## 1. 次にやること（2026-10-10 作成。ここから始める）

- **手順1は済んだ（2026-10-10）**：計算は `src/flow.ts`。手計算の例（`scripts/me/hand-test.ts`）と Python＋NetworkX の別の計算（`scripts/me/crosscheck/`）で、見本6人分すべて一致
- **手順2は済んだ（2026-10-10）**：源は3段階（`topSource`：①文だけ → ②確かめ中 → ③確か）。数字は 4. の表。くり返すめぐりの矢印（`significantFlow`・`FLOW_ALPHA` 1%）の厳しさは、まだユーザーと決めていない（1%で、流れのない人の偽のめぐりはほぼ0語）。PageRank をどの矢印で計算するかも未定
- **段階の形が決まった（2026-10-10）**：①文だけ → ②'見えはじめ（事実だけ）→ ②確かめ中 → ③確か。源（`topSource`）とめぐり（`topLoop`）。一度出たら2週間は残す（`withHold`）。「画面には何かは表示されていて、どんどん確かになっていればいい」
- **次**：行き着きやすい気持ち（PageRank）の計算を直す（残った矢印が少ないと同点だらけ）→ 画面を作る。**速さ**：源＋めぐりで、パソコンで12週 0.7秒（並べかえ500回×2基準×今日・1週前・2週前）。スマホでは数秒かかる見込み。1日1回だけ計算して残す・並べかえを減らす・2つの基準を1回の並べかえで出す、などで速くする
- モックの作り方：`scripts/me/mock-data.ts`（見本の人＋散歩の次の日にわくわく、種418）で JSON を出し、HTML を playwright で PNG にする。**ユーザーは最初のモック（3台並べ）では見方もしくみもわからなかった**。絵を見せるときは、まず「この画面が何をしてくれるか」を小さな例1つで説明してから、1台ずつ
- 本物の記録はまだ少ない（1か月たっていない）。**まず見本の記録（`?demo=1`・`src/demoPersona.ts`）で作る**。本物の記録で数字を見直すのは、ユーザーが数週間使ったあと
- 作る順番（案）：
  1. 計算（矢印・源・行き着きやすい気持ち・めぐり・育ちの割合）を `src/` に、画面なしで書く。手で計算できる小さな例と、Python の別の計算で答え合わせ（4.）
  2. 「偶然より、はっきり多い」の決め方を、星空と同じように偶然の記録で試して決める（3. の表）
  3. 画面：いちばん上に源を1つ、下に3つと数字・グラフ。見本で絵にしてユーザーに見せ、数字とグラフの形を決める
  4. 入り口：水辺の右上の「月と星」のメニューに「わたしのこと」を足す
  5. 夜明けの背景と静かな曲（色・楽器は見せて／聴いてもらって決める）
  6. スマホ（Galaxy S20）で確かめる（`/pukapuka-night` の 6.、`/pukapuka-perf`）

## 2. 決まっていること（設計書の要約。変わったら設計書が正しい）

**見せる4つ**
| 項目 | 計算 | 画面の場所 |
|---|---|---|
| 元気・好奇心の源 | 入次数：元気・好奇心の言葉へ向かう矢印が、どの言葉から多く来るか。「していること」を中心に | **いちばん上に1つだけ大きく** |
| 行き着きやすい気持ち | PageRank：矢印をたどり続けると行き着きやすい言葉 | スクロールした下 |
| くり返すめぐり | 強連結成分分解（Tarjan）：お互いに行き来する言葉の輪 | スクロールした下 |
| 育っていること | 好奇心・元気の言葉の**割合**を週ごと→月ごとに。源が加わった週に印 | スクロールした下。育ちのグラフ |

**矢印の作り方**：ある日に拾った言葉 → 3日以内に拾った言葉。近い日ほど重い。**同じ回の中の順番は使わない**（川が順番を決めてしまうため）。
**元気に近い気持ちの言葉（11語）**：わくわく・ときめき・喜び・うれしい・高揚感・満足・穏やか・ほっとした・解放感・スッキリ・軽い。好奇心の言葉も行き先に入れる（案）。
**データが少ない間**：使い始めて2週間、または元気な日が5日たまるまでは、短い文だけ（数字・グラフは出さない）。
**計算は TypeScript**（NetworkX は使わない）。言葉は百数十語なので、スマホで一瞬。

## 3. 言い方の決まり（画面の文を書くたびに見る）

- 「〜のあとに、よく来ます」と書く。**「〜のせいで」「〜すると」「〜だから」とは書かない**（順番は原因と結果ではない）
- 「あなたは〜な人」と言わない。拾った言葉の事実だけ
- くり返すめぐりに、良い・悪い・注意・助言を付けない（「疲れ ⇄ 不安」をそのまま）
- 「日記のおかげで増えた」など、変化の理由を付けない
- 画面に「分析」という言葉を出さない。PageRank などの計算の名前も出さない
- 疲れている日は、いちばん上の1文だけ読めばよいように書く（短く・1文に1つ）

## 4. 数字の根拠（数字を変えたら、ここと設計書を直す）

根拠の種類は `/pukapuka-night` の 3. と同じ（A＝偶然の記録で試す、B＝画面で測る、C＝スマホで測る、D＝ユーザーが見て決めた）。

| 数字 | 場所 | 何のため | 種類 | 根拠（確かめた日・結果） |
|---|---|---|---|---|
| 矢印は3日以内 | `ARROW_WEIGHTS` の長さ | 日をまたいだ流れを拾う | D | 2026-10-05 ユーザーが決めた。偶然の記録で試していない |
| 近い日ほど重い：1・0.5・0.25 | `ARROW_WEIGHTS` | 翌日のほうが3日後より強い | なし | 設計書 D. の仮の値のまま |
| 源の候補は「していること」だけ | `genkiSourcesTested` の `onlyDoing` | 試す組を減らして、本物を偶然に埋もれさせない | A | 2026-10-10：全部の言葉だと12週で散歩が1位 37%（5%）、していることだけで 55%（10%）。設計書の「していることを中心に」 |
| max-T（全部の組でいちばん目立つものと比べる） | `genkiSourcesTested` | 試す組が数百あっても偽の源を抑える | A | 2026-10-10：1本ずつ1%で比べると、流れのない人の35〜50%に偽の源。max-T で約1割に |
| ③確か：上位10%・重さ3以上 | `SOURCE_ALPHA`・`SOURCE_MIN_WEIGHT` | いちばん上に出す源を、まちがえない | A＋D | 2026-10-10：流れのない人200人で③が出たのは 11〜12%（60人のときは3%と出たが、たまたまだった）。流れのある人で12週 約55% |
| めぐり ③10%・②30%・重さ2・12週 | `LOOP_ALPHA`・`LOOP_TENTATIVE_ALPHA`・`LOOP_MIN_WEIGHT` | 源と同じ考え | A | 2026-10-10 `loop-test.ts`（60人）：偽 8〜12%、焦り⇄後悔を持つ人で 12週63% |
| 2週間は残す | `HOLD_DAYS` | ちらつかせない | D | 2026-10-10 ユーザー「はい」（見本の人で ②→消える→③ だった） |
| ②確かめ中：上位30%・重さ2以上 | `TENTATIVE_ALPHA`・`TENTATIVE_MIN_WEIGHT` | 使い始めにも何か見せる（ユーザー「最初のほうでも出てないといや」） | A＋D | 2026-10-10：4週目で、流れのない人の約3割に何か出る＝はずれも多い。だから「かも」と書く。50%にすると偽と本物が同じくらい |
| 直近12週 | `SOURCE_DAYS` | 本物を見つけやすく | A＋D | 2026-10-10：③で散歩 6週 約30%・12週 約55%。偽は期間によらず約1割。ユーザーが選んだ |
| 並べかえ500回 | `SHUFFLES` | p の細かさ・速さ | C（予定） | パソコンで1人0.05〜0.1秒（12週）。スマホで測る |
| 少ない間：2週間／元気な日5日 | （まだない） | たまたまを決めつけに見せない | なし | 2026-10-07 に決めた。偶然の記録で試していない |
| 週ごと → 月ごとに変える時 | （まだない） | 線がガタガタしない | なし | 未定 |

数字を決めるときの約束（`/pukapuka-night` と同じ）：
- 私が数字を決めない。測った結果と選択肢を**図1枚**で見せて、ユーザーが決める（ユーザーは統計の用語が分からない）
- 試しのスクリプトは `scripts/me/` に残す

## 5. 画面と見た目

- **背景は夜明け**：星空より明るく、文字と数字が読みやすい。背景の動きはほとんどなし（ゆっくり色が変わるくらい）。毎コマ大きな絵を描き直さない（星空のまたたきでスマホが熱くなった。`/pukapuka-night` の 5.）
- 細かい色は、モックを絵で見せて決める（`/pukapuka-design` の色の決まりに合わせる）
- **曲**：ほかの画面より静か。同じ調（A メジャー／F# マイナー）。`/pukapuka-music` で作り、聴いてもらって決める
- **入り口**：水辺の右上の「月と星」のメニュー（いまは「夕空」「星空」）に「わたしのこと」を足す。つなぎ方は案：動画なしで、ふわっと 0.9秒くらい
- 数字とグラフの形は、見本の記録で実物を見せて決める

## 6. 確かめ方

- **手で計算できる小さな例**：言葉3〜5個・数日分の記録を作り、入次数・PageRank・めぐりを手で出した答えと比べる
- **別のやり方で確かめる**：アプリの計算を、Python で教科書どおりに一から書いた計算（NetworkX でもよい。確かめにだけ使う）と比べる（`/pukapuka-night` の `scripts/night/crosscheck/` と同じ考え）。2026-10-10 に星空の FDR で、同じ考え方で書いた道具が同じ間違いを見逃した
- **記録がとても少ない人**（4日・2週間）でも必ず試す。同点の決め方も確かめる
- **見本**：`npx convex run demo:seedDemo '{"days":60,"heavy":true}'`、web で `?demo=1`
- **スマホ**：`/pukapuka-night` の 6.（adb で操作、`scripts/night/phone/`）。ユーザーの 8081 は止めない。確認用は 8091
- 型と書き方：`npx tsc --noEmit`、`npx eslint <変えたファイル>`
