# pukapuka 島スキル

pukapuka の4つ目の画面「島（朝）」を考えて作るためのスキル。島の見た目・植物・小川・動物を考えるとき、3D の島を作る・直すときに呼び出す。
**何を作るか・なぜかは `docs/SPEC.md`（第1部 5.「島」・「島に流れる小川」、第2部 C2.・D.）。世界観と色は `/pukapuka-design`、Blender の技術は `/pukapuka-blender`、曲は `/pukapuka-music`、設計書を書くときは `/pukapuka-spec`。このスキルは島のデザインと作り方のメモ。**

### ユーザーが決めたこと（変えない）

- **言葉のつながり・流れ・行き着く先・くり返すめぐりは、図ではなく景色で直感的に見せる**（2026-10-05「景色で直感的にわかるほうが良いね」）
- **分析されている感じを出さない**: 数字・順位・グラフを出さない。「分析」という言葉も出さない（「分析している感覚を持たせたくない。ストレスになるから」）

- **アプリで作った3Dは全部やめ、Blender で作った物だけにする**（2026-10-05「アプリで作った3Dを全部やめて、Blender で作ったものだけにしてください」）。根もとの影・種の光・選んだ印も Blender の部品にする

### 島の中身について決めたこと（2026-10-05、壁打ちのあとユーザーが選んだ。SPEC 第1部 5.）
- **夜空＝つながり、島＝流れ**：夜空は同じ日に一緒に拾った言葉を星座の線で。島は時間の中で言葉がどこから来てどこへ行くかを、小川・池・渦で。それに動物の日記
- **水の2つの道**：拾った言葉は空を通る（星 → 種 → 植物 → 島の湧き水・小川）。拾わなかった言葉は川を通って海へ流れ込み、島を囲む静かな海になる
  - 島のまわりは**海**。遠くに**川の河口**が見える。川の水は島の中に入らない（島の水は空から：星・雨・朝露）
  - 島 → 川は、海に流れ込む川をさかのぼって戻る
- **小川の矢印のもとは両方**：ふだんは日をまたいだ順番（**3日以内**、近い日ほど強く）。一行の文章を残した日は、その文の流れも足す
- **変わる速さ**：水の量・太さは毎日少しずつ。小川ができる・消えるのは月に1回くらい
- **ストレスになりそうな言葉は自然の一部として**：朝に出て晴れる霧・休める木陰・降ったあと植物が育つ雨雲。嫌なもの・汚いものにしない（正直に拾えなくなるため）
- **最初のころは小さな水たまり・湧き水**が少しずつ現れる（小川の前ぶれ）。小川はデータがたまってから
- **ワクワクの木は島に1本**。好奇心の言葉＋わくわくに近い気持ち（わくわく・ときめき・喜び など）が木になる
- **歩き方は今のまま上から**。触れた所へカメラが近づく（目の高さで歩かない）
- **動物**：**1匹**。どんな動物かは Blender で2〜3案の静止画を作って見比べて決める。**話すのは近づいて触れたときだけ**
- **霧の出す所**：ぐるぐる回る流れ（渦）の所。「この言葉はストレス」とアプリが決めない
- **月1の小川の変化**：知らせずにそっと変える。動物に触れると「新しい小川ができたみたい」と話す
- **朝日は、前に来てから育った所**に当てる。池は水面のきらめき。前に島を見た時刻は **Convex** に保存
- **直さずに残した AI の一行**も矢印に使う。ただし直した文・自分で書いた文より弱く数える
- **川 → 島の動画**：川を下り、河口から海へ出ると島が見える。日が沈み、夜をこえて朝に（島 → 川の逆）
- **朝の島から始まる日**：その日に最初に開いたときで、前に島を見てから育っているときだけ
- **動画と3Dのつなぎ**：動画も同じ Blender の島で作り、**最後の1コマをアプリの最初のカメラの向き**（距離・見下ろす 0.3・上向き 0.09）と同じにする。島 → 川はその逆
- **動物は島と一緒に作る**。話す一行は、まず仮の文で見た目と動きを固め、保存ができてから本物の AI につなぐ
- **島の曲**：やさしい朝。木管（フルート・クラリネット）とつま弾きのギター、小鳥と波の音。ゆったり歩く速さ。ほかの3曲と同じ調（`/pukapuka-music`）
- **4画面は分けたまま**：拾ったことば＝多さ・強さ、夜空＝つながり、島＝流れ
- **動物の一行**：AI に送るのは**その日に拾った言葉と強さだけ**（「そっとしておく」言葉は送らない・AI の会社に残さない設定）。**初めて動物に触れたときに1回**、短い説明と「話してもらう／やめておく」
- **動物の話し方**：やさしく素朴なひとりごと（日記を読むように。話しかけすぎない）
- **動物の名前**：付けられる。付けなくてもよい（文字を打つのはここだけ）
- **配置の方向**（2026-10-05、配置図の静止画を作る前に決めた）
  - ワクワクの木は**草地の真ん中**。まわりに言葉の花、小川が流れ込む
  - 水は**奥の丘の湧き水から手前へ**：草地を通って木のまわりを流れ、手前の池へ。最初の向きで全体が見える（水が坂を上らない）
  - 川の河口は**最初の向きの奥、水平線の山あい**に小さく
  - 島は**もっと大きく**（ユーザーが選んだ。小さい画面で植物が小さく見えないよう、最初のカメラは草地に合わせる）

## 2. 島の設計（案。決定ではない所は SPEC の未決事項）

### 植物（拾った記録だけから決める）

| 記録 | 島で起きること |
|---|---|
| 言葉を拾う | その言葉の種が空から降りて、芽が出る |
| 同じ言葉を何度も拾う | 大きくなる（芽 → 花 → 木） |
| 強く拾う | 色が濃くなる（軽い言葉は白っぽい） |
| 言葉の種類 | 形が変わる。気持ち＝花、体の感じ＝草の株、場面＝茂み、したいこと＝若木、好奇心＝ワクワクの木 |
| よく同じ日に一緒に拾う | 島の同じ所に寄り添って生える（花畑・林） |
| 新しい種類の言葉・言葉の数が増える | 島が少し広がる |
| 前に島を見たあとに育った | 朝日が当たる（決定）・蝶が止まる（案）。まだ作っていない |

- 1回だけの言葉は芽（双葉と、種類の色の小さなつぼみ）
- 色は `src/wordCloud.ts` の `CATEGORY_COLOR`（拾ったことばと同じ5色）を元に、強さで彩度と明るさを変える
- 言葉が少ない間（最初の数日）も、島そのものが気持ちいい景色であること。芽が1つでもさみしくない

### ワクワクの木と、そばに咲く花
- ゴールの瞬間を見せる場所。「ワクワクの木のそばに、いつも同じ花が咲いている」景色を見て、ユーザーが自分で気づく
- そばに咲く花＝好奇心の言葉と同じ日によく拾う言葉（順番なし）
- **決定**: 木は島に1本。好奇心の言葉＋わくわくに近い気持ちの言葉が、この1本に集まる（どの語を入れるかの一覧は作るときに見せて決める）
- 試作ではまだ木を特別に扱っていない（好奇心の言葉ごとに木を植え、ほかの植物と同じグループ分け）。**1本にまとめる直しが要る**
- 案：1本の木を草地の真ん中に置き、まわりにそばの花を寄せる。木の大きさは、集まった言葉の回数の合計で

### 島に流れる小川（景色で見せること・矢印の作り方・変わる速さは決定）

言葉から言葉への流れ（矢印）を水の流れにする。小川の水は空から来た水（拾った言葉）。ことばの川の水（拾わなかった言葉）は島に入らない。

| 見せたいもの | 使う計算（ネットワーク分析） | 島での見え方 |
|---|---|---|
| 時間の流れ（言葉から言葉へ） | 有向グラフ：つながりに向き（矢印）がある網の目 | 植物から植物へ細い小川。よく通る流れほど太い |
| ワクワクの源 | ハブへの入次数：たくさんの線が集まる言葉に、どの言葉から矢印が来るか | ワクワクの木の根もとへ流れ込む小川。どの花から水が来るかで「計画 → ワクワク」が見える |
| 行き着く言葉 | PageRank：矢印をたどり続けたとき、たどり着きやすい所 | 小川が集まる池。水面がきらめく（朝日は育った所に当てる。決定） |

- 矢印は「この言葉のあとに、よくこの言葉が来る」だけ。原因と結果として書かない・見せない

## 3. 今の作り方（試作のコード）

### 植え方（`src/islandLayout.ts`）
```
大きさ   = 0.55 + 0.25 × √回数        （上限 1.8）
育ち     = 1回なら芽（0）。2回から 0.35 + 0.13 × 回数（上限 1）
島の半径 = 2.4 + 0.55 × 言葉の種類の数 + 0.06 × 言葉の数
```
- グループ分け（`findGroups`）
  1. 同じ日に一緒に拾った日数（`cooccurrence`）が2日以上の組だけ
  2. コサイン＝一緒の日数 ÷ √(片方の日数 × もう片方の日数)。0.3 未満は使わない（`MIN_ASSOC`）
  3. お互いの上位3つ（`MAX_LINKS`）に入る組だけ残す
  4. ラベル伝播（となりの多数派に合わせていく）で分ける。順番を固定して毎回同じ結果に
- 位置: 大きいグループほど島の真ん中寄り、黄金角でずらす。言葉が少ない間は、まとまりを真ん中に寄せる（広がり ＝ √(言葉の数 ÷ 20)、1 まで）。グループの中はらせん状。最後に `relax` で近すぎる植物を押し離し（間隔 0.22＋0.2×大きさ を2つ分）、島の 8 割の内側に戻す
- 仮のデータ: `sampleCaptures.ts` の28日分を3回くり返して約3か月（くり返しで5件に1件抜く）。2か月目から6語（やってみたい・調べたい・ひらめいた・スッキリ・趣味・楽しみたい）を足す。仮のデータで決めた組（仕事帰り・不安・好奇心・休日・逃げたい）どおりにグループが分かれるのが正しい結果

### 3D の描画（`src/components/Island3D.tsx`）
- `<Canvas flat frameloop="demand">`。flat は色の変換なし（設定した色のまま出る）。demand は**動いているときだけ描く**（指で動かす・育つ・カメラが近づく・島が広がる・選んだ印が脈打つ間）。描き直してほしいときは `invalidate()`（指の操作は `rig.invalidate`）
- **見た目はすべて Blender から**（`src/islandKit.ts`。地面・海・空・太陽・植物・岩）。材質は MeshBasic（光の計算なし）で、Blender で焼いた色をそのまま出す。霧・ランプは使わない（作り方は 4. の「地面・海・空を Blender で作り、光を焼く」）
- **構図**（縦長の画面では、横の見える幅で島の大きさが決まり、上下は必ず余る。余りを景色にする）
  - 見下ろす角度 0.3、カメラを少し上へ 0.09 向ける → 地平線は上から約25%、島の真ん中は約60%
  - 距離 ＝ 見せる範囲 ÷ tan(横の半分の画角)。v4 では範囲＝草地の真ん中から一番遠い植物＋2（7.5〜12）。最初から草地全体と奥の林が入る
  - 見る点は草地の真ん中（高さ 0.6）。開いたときは 1.25 倍の距離から近づく
  - 歩く：見る点＝触れた地面＋0.6、距離＝全体の約半分（最小 4.2）
- 地面は `island__ground` を横だけ `R / 6` 倍。空と太陽はカメラについて動かし、いちばん先に描く（奥行きを書かない）
- 植物: Blender の部品（`種類__役`）ごとに **InstancedMesh 1つ**。色は「焼いた光 × `setColorAt` の種類の色 × 1.35」。位置は**育っている間・島が広がる間・選んだものが変わったときだけ**計算し直す
- 植物の色：茂み（場面）と若木（したいこと）は葉を緑に寄せ（0.7 前後）、種類の色は実や先の方だけに（青や黄と緑を半々に混ぜると灰色・とんがり帽子になる）
- 根もとに薄い丸い影（`#35552f`・0.2。アプリで作っている）。選んだ植物の根もとに光の輪（2.4秒だけ脈打って止まる）
- 岸の岩6つ（Blender の `rock__rock`、色 `#a39d93`、島の 0.92〜0.99 の所）。言葉ではないので触れても何も出ない
- 時期を変えたとき: 新しい言葉は種（光の粒）が 1.3 秒で降り、0.9 秒で育つ（少し弾む）。降り始めは 1.6 秒の間でばらつかせる。前からある言葉は大きさだけ変わる。カメラは全体が見える所へ戻る
- 触れた所: 画面の上で、触れた点から 44px 以内のいちばん近い植物（の高さの真ん中）を選ぶ。なければ地面に光線を当てて、そこへ歩く
- 言葉のラベル: 選んだ植物の上の点を画面に写し、Reanimated の共有値で RN の文字を動かす。画面の内側（左右 8px、上 96px・下 200px）に収める
- 確かめ用：Web の開発中だけ `globalThis.__island`（植物の画面上の位置）・`__islandRig`（カメラ）・`__islandFrames`（描いた回数）を出す

### 指の操作（`src/app/island.tsx`）
- 1本指のなぞり＝回る、つまむ＝寄る・離れる、触れる＝選ぶ／歩く、2回触れる＝全体に戻る
- ジェスチャーは `.runOnJS(true)`（描画の計算は JS で動くので、そちらで値を書き換える）

- 上に淡い光の帯（`rgba(255,238,226,0.8)`→透明、高さ120）、下に薄い影の帯（`rgba(24,70,84,0.32)`、高さ170）。文字は `#4a3b42` に白いにじみの影

- 島の画面だけ `StatusBar style="dark"`（明るい朝の空。アプリ全体は白い文字）
- 時期のボタンは高さ約36px（上下 9px の余白）

### v4 の作り方（2026-10-05。今アプリに入っているもの）
1. **素材を集める**（`pp_lib` の `pp_search`・`pp_glb`。やり直し6〜8回つき）。作者は絞らない。軽いもの（1つ 1500 三角形まで）を選び、`L_名前` の親に `pp_id`・`pp_title`・`pp_author`・`pp_licence`・`tris` を付ける
2. **同じ色合わせで塗り直す**（材質の色・画像の色を三角形ごとに読み、色の属性 `Albedo` に書く。材質は全部 `PukaAlbedo`＝Albedo を拡散に）
   - 緑（色相 55〜175°）→ 川の緑4色に寄せる（明るさの違いは残す）、茶色（暗い赤〜黄）→ 幹の茶色の幅、灰色・白 → 温かい灰色（とても明るい白は花びらとしてクリーム色）、それ以外（花・実）→ 色相は残して淡く
   - **画像1枚に幹と葉が入っている素材が多い**（Poly by Google の木など）。1色で塗ると幹と葉が同じ色になる。三角形ごとに画像の色を読む（UV の真ん中）
   - 読めない素材（シダ・白い岩・赤茶の岩）は、名前で直接塗る
3. **島の地形**（テキスト `island_terrain`。アプリの `groundY` は草地の部分だけ同じ式）
   - 半径 16、岸の出入り `shore(a)`。草地＝`0.6 + 0.2·sin(0.33x+1.3)·cos(0.29z−0.4) + 0.1·sin(0.71x−0.47z+2)`（±0.3 のゆるい起伏。高い所は明るい緑、くぼみは少し濃い緑）。半径の 0.42〜0.9 に丘（奥ほど高い）。池（中心 (8.8, −3.5)）。0.84 から砂浜、1.0 から水の下
   - **四角い格子（0.62 間隔、点を少しずらす）で作る**。丸い格子だと真ん中に三角形が集まってうず巻きが出た
   - 色は三角形ごと（草→丘で濃い緑→砂→浅瀬）＋明るさ ±6%
4. **景色を置く**（`place_scenery.py`。何度実行しても同じ）。素材ごとに「根もとを原点・目標の高さ」の行列を作ってから置く。林は奥（205°・258°）、丘の木は 232°、桜 150°、池、飛び石は手前（50°）。草地の半径 7.5 は空ける
5. **景色をまとめる**（`V4Scenery` の写しを1つに join → `v4__scenery`）
6. **言葉の植物の部品**（`V4Kit`）：素材を高さ（ワクワクの木 2.6・若木 1.8・茂み 0.75・シダ 1.1 幅・花 0.65・芽 0.5）にそろえ、三角形を `種類__base`（葉・幹＝塗った色）と `種類__accent`（花びら・実＝白。アプリで種類の色を掛ける）に分ける
7. **印**（`fx__shadow`＝真ん中が濃く縁で透明な円盤、`fx__seed`＝光の玉、`fx__ring`＝光の輪）も Blender で作り、色と透明度を頂点に入れる。アプリは置く場所と大きさを決めるだけ
7.5 **太陽** `island__sun`：空より手前（距離 136）の円盤。芯 半径 1.8（見た目 約1.5°）`#fffaea`、縁 2.6 まで `#ffe9b8`、7.5 まで淡い金 `#ffd49a` をまわりの空の色へなじませる
8. **光を三角形ごとに計算する**（`light_faces.py`、約10秒。日なた 1.1・空の光 0.52。起伏が見えるよう、日なたと日陰の差を大きめに）。朝の光（`island_key_dir`）の当たり方・影（三角形の真ん中から光の方へ光線）＋空の光（まわり10本の光線で開け具合）。海だけは Cycles で焼いたもの
9. **書き出し**：写し（`.x`、材質なし、`Baked` だけ、変形を適用）を書き出してすぐ消す。変換で三角形ごとの色に（空・太陽・印だけは頂点ごとの色）

### 地面・海・空を Blender で作り、光を焼く（v3 の作り方。2026-10-05）
- **地面** `island__ground`：アプリと同じ式（`shore(a)`・`heightAt(u, a)`）で、**半径 6（`KIT_R`）**に作る（極座標 22段×64、格子を少しずらす）。アプリでは横だけ `R / 6` 倍。植物の高さ（`groundY`）と形が合う
  - 色：川の Ground と同じ作り（中心からの距離の色の帯 × ノイズの明暗）。草 `#8fc27a`→`#86ba70`→砂 `#e9d7a6`/`#f3e2b8`→浅瀬 `#a8ddd0`→`#74c4cb`
  - 平らな島では面の向きで明るさが変わらず、ローポリに見えない → **三角形ごとの明るさのばらつき（色の属性 `Facet`、±7%）を材質で掛ける**
- **海** `island__sea`：中心から外へ輪の間隔を広げた円盤（半径 150、27輪×72）。小さな波（高さ 0.035）で三角形の面を見せる（川の水面と同じ見え方）。材質は「弱い発光（0.22）＋拡散」、距離で `#2f97ad`→`#5cb8c6`→`#bcd5d2`→`#f2cdb7`（地平線の空の色）。`Facet` ±5%
- **空**：Blender のワールド（高さで朝の色・朝日のにじみ・平たいノイズの雲）を、**パノラマ（正距円筒、2048×1024、Cycles 32、約30秒）**で描き、その色を半球のメッシュ `island__sky`（半径 140、地平線のまわりに輪を細かく）の頂点に写す。**画像を読み込まずに済む**
  - パノラマの向き：カメラを (0,0,2)、回転 (90°,0,0)。画像の横 u と Blender の方位の関係は `u = 0.5 − (atan2(y, x) − 90°) / 360`（太陽の一番明るい所で確かめた）
  - 太陽 `island__sun`：空の上に小さな円盤（真ん中は白、外へ周りの空の色へ）
  - アプリでは空と太陽を**カメラについて動かし**、いちばん先に、奥行きを書かずに描く
- **光**：太陽ランプは「最初の向きのカメラの斜め前上」から（`scene['island_key_dir']`）。見える太陽（`scene['island_sun_dir']`）とは別（逆光で植物が濁るため）
- **焼く**（Cycles 64、`bake.target = 'VERTEX_COLORS'`、`COMBINED`、色の属性 `Baked`（FLOAT_COLOR・CORNER））
  - 地面：植物・岩・空は隠して焼く（時期で変わる物の影を焼き込まない）。1.7秒
  - **海：島も隠して焼く**（島の大きさは時期で 3.6〜7 に変わる。半径 6 の島の影を焼くと、小さい島のまわりに大きな黒い影が残った）
  - 植物と岩：**白い材質（0.8）で、種類ごとに1つずつ**焼く（ほかの部品は隠す）。焼けるのは光の明るさだけ。アプリで「焼いた光 × 種類の色 × 1.35」。葉の玉の間の面はほぼ 0 に焼けるので、アプリで 0.22 だけ底上げ
- **書き出し**：**写し（名前の最後に `.x`、材質なし、色の属性は `Baked` だけ）を作って書き出し、すぐ消す**。元の物体の属性は消さない
- 変換：`node scripts/island/glb-to-ts.mjs`。形は Float32、色は sRGB 8bit、面は Uint16/32 を base64 で `src/islandKit.ts` に（574KB）。**色の平均がほぼ白なら止まる**（焼いた色でない属性が出ているとき。太陽は除く）

### 素材を選ぶ・直すときの決まり
- **作者（シリーズ）をそろえる**。作者が違うと、形の丸さ・面の細かさがばらばらになる
- **色は pukapuka の色に塗り直す**（2. の色、`CATEGORY_COLOR`）。素材の色のまま使わない
- フラットシェード・角のある形に。なめらかすぎるものは使わない（川の v9 の絵柄）
- 重さの目安（仮。実機で決める）: 植物1本 300 三角形まで、島の全体（植物100本込み）5万三角形まで
- CC-BY を使ったら、作者名と出どころを記録して、アプリのクレジットに出す
- 書き出しは glTF（`.glb`）。アプリで読むときの方法（expo-asset と GLTFLoader）は、最初の1つで実機で確かめてから決める

### Web で確かめるときの注意

- 3D を撮るには Chromium を `--use-gl=angle --use-angle=swiftshader --enable-unsafe-swiftshader` で起動する

- 開発用のバンドル（`entry.bundle?platform=android`）には、画面ごとのコードが入っていない（画面は後から読み込まれる）。スマホ用のビルドを確かめるときは `expo export` を使う

## 7. NGパターン

### 計算
- **一緒に拾った回数のままでグループ分けする** → よく拾う言葉（「疲れ」）が何とでもつながり、島じゅうが1つのグループになる。拾った日数で割り引き（コサイン）、お互いの上位だけ残す
- **位置をらせんだけで決める** → グループどうしが重なる。最後に押し離す
- **同じ回の中で拾った順番を矢印に使う** → 川に流れてきた順番（偶然）を気持ちの流れとして見せてしまう
- **順番を原因と結果として書く・見せる**

### UI の監査で見つけた問題と根本原因（2026-10-05、iPhone SE の大きさ 375×667 で6場面を撮って洗い出し）

| 見えた問題 | 根本原因 | 直し方の決まり |
|---|---|---|
| 島が画面の真ん中の帯だけで、下半分が何もない灰色の海 | 縦長の画面では、見える横幅で島の大きさが決まる（横の画角は約26°しかない）。上下は必ず余る。その余りを景色として作っていなかった | 余る上下を景色にする（空の色の移り変わり・雲・海の奥行きの色・朝日の照り返し）。地平線は上から約25%、島の真ん中は約60%に置く（見下ろす角度とカメラの少しの上向きで決める） |
| 植物が暗く濁る（木が灰緑、茂みが灰青） | 朝日（光の向き）がカメラの正面にあり、見えている面が全部影（逆光）。半球光の地面の色が灰緑 | 植物を照らす光はカメラの斜め前上から（カメラについて回る）。見える太陽は景色として別に置く。地面からの照り返しは暖かい色 |
| 太陽が「川へ」などの文字と重なる | 太陽を世界のある1点に置き、最初の向きのとき画面の上の真ん中に来ていた | 太陽は地平線のすぐ上、画面の右寄りに来る向きに置く。上の文字の帯（上から約12%）に入れない |
| 空と海が灰色っぽい | 霧の色を海の青に混ぜると灰色になる。海を光で照らす材質にしたため、半球光の灰緑が乗った | 霧は遠くだけ、色は地平線の空の色に。海は光に左右されない色（手前は青緑、奥は空の色に近い淡い色）で塗る |
| 植物が地面から浮いて見える | 影がない | 植物の根もとに、薄い丸い影を置く（同じ形をまとめて1回で描く） |
| 草地がのっぺり。ローポリに見えない | 色を頂点ごとに付けたので、三角形の間で色がなめらかに混ざる。三角形も細かい | 色は三角形ごとに1色。明るさを少しずつばらつかせる（川の v9 と同じ見え方） |
| 手前の砂浜が広く、茶色く濁る | 砂浜の幅が広い。水の下の砂を茶色にし、半透明の海から透けていた | 砂浜は細く。水の下は砂からエメラルドの浅瀬の色へ |
| 1回目の島がさみしい（大きな島に芽が1つ） | カメラが島の大きさで距離を決めていて、中身が少ないと空き地ばかり写る。芽も小さすぎた | 植物のある範囲で距離を決める（少ない間は近くで撮る）。芽を大きく。岸に岩を置いて、島そのものを景色にする（岩は言葉ではないので触れても何も出ない） |
| 歩くと寄りすぎて、地面しか写らない・木が上で切れる | 歩いたときの距離を 4.5 に固定し、見る点を地面の高さにしていた | 歩いたときの距離は全体の約半分。見る点は植物の高さ（地面＋0.6） |
| 上の文字が空や木の上で読めない。下の説明も海の上で薄い | 明るい景色の上に、薄い文字を何も敷かずに置いた | 上に淡い光の帯、下に薄い影の帯を敷く。文字に影を付ける。説明は短く、触ったら消す |
| スマホの上の時計・電池の文字が見えない（はず） | アプリ全体で白い文字（`StatusBar style="light"`）にしていて、明るい朝の空に白 | 島の画面だけ黒い文字にする |
| 選んだ植物がどれか分かりにくい。言葉が画面の端で切れる | 選んだときの印が、大きさの小さな揺れだけ。言葉の位置を画面の中に収めていなかった | 根もとに光の輪を出す。言葉の位置を画面の内側に収める |
| （スマホで）電池を食う・熱くなる（はず） | 何も動いていなくても毎コマ描き直し、全部の植物の位置を計算し直していた | 動いているとき（指で動かす・育つ・カメラが近づく・選んだ印）だけ描く（`frameloop="demand"`） |

### Blender の部品に取り換えたときの問題と根本原因（2026-10-05）

| 見えた問題 | 根本原因 | 直し方の決まり |
|---|---|---|
| Blender の並べた絵が全体に白っぽい | 川の色は夕方の暗い光で決めた値。朝の明るい光とワールドの強さ 1 で照らすと白く飛ぶ | Blender の色は形の確かめ用と割り切る。色はアプリで決めて、アプリの画面で確かめる |
| 岩が点のように小さい | 川の岩の物体の大きさ（0.25×0.2×0.11）が偏っていた | 取り出したら高さで大きさを直す |
| アプリで花（気持ちの言葉）が見えない | 花の部品は 0.6、木は 2.0。部品の高さのまま並べると、島全体では花が消える | 種類ごとの見え方の倍率（`KIND_BOOST`）で花・ガマを大きく |
| 木が灰色っぽい・オリーブ色 | 葉に種類の色を混ぜすぎた（ミントや黄を 40〜65%） | 葉は川の緑を主に。種類の色は実・花びら・穂・一部の玉で見せる |
| 1回目の手前の岩が大きすぎる | 部品を変えたのに、岩の倍率を前の形のまま上げすぎた | 部品を変えたら、倍率を全部見直す（近くで撮る1回目で確かめる） |

### 地面・海・空を Blender にしたときの問題と根本原因（2026-10-05）

| 見えた問題 | 根本原因 | 直し方の決まり |
|---|---|---|
| 海が描かれない（空の下側が透けて見えた） | 海の面を下向き（頂点の順番が逆）に作っていた。上から見ると裏の面で、描かれない | 地面・海は面を上向きにそろえる（法線の z が負なら裏返す）。下向きの面の数が 0 か確かめる |
| 木の面の 3分の2 が真っ黒 | 川の部品を取り出すとき、**面ごとに新しい頂点を作った**ので面どうしがつながっていない。「法線を外向きに」が内と外を判断できず、多くの面を内向きにした | 取り出したら**重なった頂点をまとめて（remove_doubles）から**法線を外向きに直す |
| 地面が真っ黒に焼けた | 書き出しの前に「要らない」と思って色の属性 `Facet` を消した。材質がそれを掛けていたので 0 になった | 元の物体の属性は消さない。**書き出しは写しで** |
| 地面と海が真っ白で出た | 「使う色の属性（ACTIVE・NAME）」を指定しても、書き出しが `Facet`（ほぼ 1.0）を出した | 写しを作り、`Baked` 以外の属性を消してから書き出す。変換で「ほぼ白なら止まる」 |
| 小さい島のまわりの海に大きな黒い影 | 海を、半径 6 の島と一緒に焼いた | 大きさの変わる物（島）は隠して焼く |
| 木の葉の玉の間が黒い | 玉どうしの間の面に光が届かず 0 に焼ける | アプリで少し底上げ（まわりの光の代わり） |
| 岩が白っぽい | 岩の色に植物と同じ明るさの倍率を掛けた | 岩は倍率を掛けない |

### v4（Poly Pizza の素材で大きな島）の問題と根本原因（2026-10-05）

| 見えた問題 | 根本原因 | 直し方の決まり |
|---|---|---|
| 置いた木が手前に大きく出て、林が見えない | 素材の親を「変形なし」に戻したとき、**大きさの正規化と根もとの位置合わせも消えた**。各素材の元の大きさ・位置のまま置かれた | 素材ごとに「根もとを原点・目標の大きさ」の行列を先に作り、`置く場所 × その行列 × 部品の元の位置` で置く |
| 最初の向きで林が画面の外 | 縦長の画面の横の画角は約26°。真ん中から ±45° の林は入らない | 林は奥の真ん中寄り（±25°以内）に置く |
| 飛び石が大きすぎて固まる | 平たい石を**高さ**で大きさをそろえ、幅が 2m になった | 平たい物（石・蓮の葉）は**幅**でそろえる |
| 草（体の感じ）が地面に寝た板、芽が見えない | 草の素材が「透明の模様を貼った板」だった。模様なしでは平らな板 | 板の素材は使わない。形のある素材（シダ・草の株）にする |
| 空がタイルのようにカクカク | 色を三角形ごとの1色にしたとき、空も1色ずつになった（大きな三角形） | 空・太陽は頂点ごとの色のまま（変換で区別） |
| 飛び石・葉の玉の間が真っ黒 | Blender の「頂点の色へ焼く」は**面の角（頂点）で光を測る**。ローポリの角は隣の面とくっついていて、ふさがれていると判断される | 光は三角形の真ん中で自分で計算する（`light_faces.py`） |
| 法線を「外向きに直す」と、かえって木に黒い点が増えた | 素材には開いた面（1枚の葉・板）が多く、外と内を決められず、正しい面まで裏返した | 法線は直さない（光の計算で、表が埋まっている面だけ裏を表として扱う）。平たい石と蓮の葉だけ上向きにそろえる |
| ワクワクの木の実が白っぽい（雪のよう） | 好奇心の色（ミント）を白い実に掛けた | ワクワクの木の実は金色（`#ffc65c`）に、種類の色を少しだけ |
| 太陽が見えない | 太陽の円盤の色が、まわりの空（クリーム色）とほぼ同じ | 真ん中を暖かい白、まわりを淡い金色のにじみに |
| 太陽がまだ空の白に溶けて、ほとんど見えない（ユーザー指摘） | 太陽の円盤が小さい（半径 1.2／距離 138＝見た目 約0.5°）。まわりの空も白に近いクリーム色で、明るさの差がない | 円盤を大きく（見た目 約1.5°）、まわりの空より一段濃い暖色のにじみを付けて、空との差を作る |
| 草地がのっぺり（川の地面ほど起伏がない。ユーザー指摘） | 植物の高さの計算を簡単にするため、草地の起伏を ±0.04 にしていた。川の地面は ±0.3 くらいの丘がある | 草地にもゆるい起伏（±0.25 くらい）。アプリの `groundY` と Blender の `island_terrain` の式を必ず同じにする |
| 「根もとの影・種の光・選んだ印の輪がアプリのまま」と思われた | v4 で Blender の部品（`fx__*`）に替えたのに、報告で表にしなかった | 「どこで作ったか」の表を、毎回の報告に入れる |
| （進め方）ユーザーは「まずすべては Blender から」 | アプリの画面で見た目を決めてから Blender に戻していた | 見た目は Blender で作って Blender の静止画を先に見せ、OK のあとアプリに入れる |

### 見た目
- **地面の模様や起伏を角度で決める** → 島の真ん中にうず巻きができる。場所（x, z）で決める
- **海のつやを強くする**（roughness 0.25）→ 朝日が海面に照り返して、空まで白い柱に見える。0.75 くらいに
- **カメラの距離を最初の島の大きさで固定する** → 島が広がるとはみ出す。時期を変えたら全体が見える所へ戻す
- **見下ろす角度を急にする**（0.55）→ 空が見えず、海と霧だけの灰色っぽい景色になる。0.38 くらいで地平線と朝日を入れる
- **植物を大きくしすぎる**（上限 2.4）→ 木が島を覆う。上限 1.8
- 素材の色のまま使う／作者の違う素材を混ぜる → 絵柄がばらばら
- 数字・順位・グラフ・「分析」という言葉を島に出す（決まりに反する）
- 渦・霧に「注意」「よくない」などの言葉を添える（助言しない）

### 3D の技術
- **スマホで島を開くと「undefined is not a function」（three.cjs:12）で止まる**（2026-10-05、実機で発生。ブラウザでは出なかった）→ three.js の require 用の入口 `build/three.cjs` が最初に `process.emitWarning`（Node.js にしかない）を呼ぶ。@react-three/fiber のスマホ用は `require('three')` で読むので、スマホだけこの入口を通っていた。**`metro.config.js` で `three` を `build/three.module.js` に向ける**。Metro の設定を変えたら、サーバーを `--clear` で起動し直す。確かめ方：`npx expo export --platform android --dev --no-bytecode` の JS に `THREE_CJS_DEPRECATED` が 0 件
- ブラウザで動いても、スマホで動くとは限らない（読み込む入口がちがう）。新しい道具を入れたら、`expo export --platform android --dev --no-bytecode` の中身も見る
- `@react-three/fiber/native` を直接読み込む → Web とスマホで読み込みを分ける手間が増える。`@react-three/fiber` から読み込めば、スマホでは package.json の `react-native` の指定でスマホ用が使われる（Web はそのまま Web 用）
- 指の判定を three.js の光線だけで行う → 細い茎や小さな芽に当たらない。画面の上の距離で選ぶ
- 3D の中に日本語の文字を描く → 重いし文字の用意が要る。RN の文字を重ねる
- ジェスチャーの中で JS の値を書き換えるのに `.runOnJS(true)` を付けない → UI の側で動いて、描画の側に届かない
- **`frameloop="demand"` にしたのに、状態（選んだ植物・時期）を変えたとき `invalidate()` しない** → 次に何かが動くまで画面に出ない（植物に触れても言葉が出ず、回したら出た）。状態が変わる所では必ず描き直しを頼む
- 選んだ印をずっと脈打たせる → 止まっていても毎コマ描き続ける。少しの間だけ動かして止める
- 毎コマ全部の植物の位置を計算し直す → 動いているときだけ
