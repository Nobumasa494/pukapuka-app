# pukapuka 島スキル

pukapuka の4つ目の画面「島（朝）」を考えて作るためのスキル。島の見た目・植物・小川・動物を考えるとき、3D の島を作る・直すときに呼び出す。
**何を作るか・なぜかは `docs/SPEC.md`（第1部 5.「島」・「島に流れる小川」、第2部 C2.・D.）。世界観と色は `/pukapuka-design`、Blender の技術は `/pukapuka-blender`、曲は `/pukapuka-music`、設計書を書くときは `/pukapuka-spec`。このスキルは島のデザインと作り方のメモ。**

### 今の島の作り（v7、2026-10-07）
- 地形の式：Blender `scripts/island/blender/island_terrain.py` と アプリ `src/islandTerrain.ts` は**必ず同じ式**（`meadow`・`pondU`・`STREAMS`・`LAND_MIN`・`WATER_PAD`）。変えたら両方、数値で比べて差 0 を確かめる
- 島は半径 19。小川3本（奥の湧き水・右奥の湧き水 → 木の根もとの淵 → 手前の池）＋池から海へ出る細い川（いつも流れる）。草地の高さに下限 `LAND_MIN` 0.12（手前の低い所に海が見えないように）
- 水の板は溝より広く（`WATER_PAD` 0.6）、縁は岸の地面の下に隠す。溝は浅く（水面の 0.07 下）
- 光：地面＝`bake_lightmap.py`（Cycles、1024 の光の絵、下限 `LM_FLOOR` 0.32）。景色・言葉の植物＝`bake_faces.py`（Cycles で絵に焼き、三角形の真ん中の明るさを Baked に。景色は 4096、植物は種類ごとに 512、焼く間だけ空の光は白 0.8）。空と海＝`world_colors.py`
- 水の流れ：`water_glint.py` の光の網目の絵を、アプリが大きさと速さの違う2枚でずらす（`FLOW_A`・`FLOW_B`）。Blender で再生するときは `water_frames.py` の16コマ（アプリとは別の見え方）
- 書き出し：`export_kit.py` → `node scripts/island/glb-to-ts.mjs` → `src/islandKit.ts`（約 0.9MB・27部品・約5.8万三角形）。光の絵は `assets/island/lm_ground*.png`・`water_glint.png`
- アプリ：水の様子は時期で出し分け（`layout.water`）、ワクワクの木は真ん中に1本、島は直近12か月、3D は画面の切り替えが終わってから準備、描く細かさ 1.5 倍まで、水が流れるので1秒に15回描く

### ユーザーが決めたこと（変えない）
- **島は4つ目の画面**。朝。夜空の星が種になって島に降り、花や木に育つ（2026-10-05「星空の次は、島を育てていく」）
- ゴールは**ワクワクの源に気づき、育てる**こと。いちばん大事な瞬間は「本当のワクワクの源に気づく」（例：旅行より、旅行の計画にワクワクしていた）
- **島はアプリの中で動かせる 3D で作ってみる**（2026-10-05「いろんな角度から見えるようにしたい」「これやってみたい」）。スマホで重くないか・操作が気持ちいいかを確かめてから決める

- **言葉のつながり・流れ・行き着く先・くり返すめぐりは、図ではなく景色で直感的に見せる**（2026-10-05「景色で直感的にわかるほうが良いね」）

- **見た目は Blender で作った3Dに全部取り換える。アプリの中で3Dとして動かす（A 案）**（2026-10-05「Aでお願いします」）。Blender で形を作り `.glb` に書き出し、今の3Dの仕組み（植え方・種・触れる・歩く）に載せる。three.js で組んだ仮の積み木の見た目は使わない
- **アプリで作った3Dは全部やめ、Blender で作った物だけにする**（2026-10-05「アプリで作った3Dを全部やめて、Blender で作ったものだけにしてください」）。根もとの影・種の光・選んだ印も Blender の部品にする
- **デザインはほとんど Blender で考えて作る。3D で動かすためにどうしても要る所は、Blender を使わなくていい**（2026-10-06「Blenderでほとんどデザインを考えたい。３Dで仕方ないところは、blnderを使わないでいいという意味」）。島は 3D のまま（動画に作り替えない）。形・色・光・水の見た目は Blender、コマの切り替え・模様をずらす動き・カメラ・触れたときの反応はアプリでよい。迷ったら「見た目を決めているのはどちらか」で分け、報告の「どこで作ったか」の表に書く
- **Poly Pizza の素材を土台にしてよいし、自分で作ってもよい。世界観は統一しつつ、いろいろなデザインの素材を選ぶ**（2026-10-05「世界観は統一しつつも、いろいろ、デザインが尽くしいのを選んでね」）。**作者を1人に絞らない・ライセンスを考えすぎない**（「一つに絞るとダサくなるから、絶対それはさけたい」）。統一は「同じ塗り直し・同じローポリの見え方・同じ光で焼く」で行う。CC-BY を使ったら作者名を記録する（クレジットに出すため）

### 島の中身について決めたこと（2026-10-05、壁打ちのあとユーザーが選んだ。SPEC 第1部 5.）
- **小川の意味（2026-10-06）**：島の水は雨・朝露 → 奥の丘の湧き水 → 小川 → 手前の池。星は種になり、水にはならない。植物も水を出さない（「根もとから水が湧く」は不自然でやめた）。**植物は小川のほとりに、拾う順番どおり上流（先に来る言葉・高い奥）から下流（あとに来る言葉・低い手前）へ並ぶ**。ワクワクの木は真ん中で、根もとの淵に上流の小川が集まる。**池そのものは言葉ではなく、ほとりに行き着きやすい言葉が咲く**。言葉だけの説明は伝わらず、図（上から見た島に花・木・池と例の言葉）で伝わった
- **島の水は最後に海へ帰る（2026-10-06）**：池から浜を通って海へ出る川（STREAMS[3]、部品 `island__river`）。1回目からいつも流れている（溝のない地面にも掘る）。ユーザー「たまる一方っておかしいかな？周りは海だし」
- **水は実際に流れる・流れも Blender で（2026-10-06）**：ユーザー「実際流れるようにしたい」「完全にblenderで作ってほしい」。`water_frames.py` が小川・海へ出る川の水面の写しを16コマ作り、波の筋を少しずつ下流へずらして焼く（`island__stream__f00`〜`f15`・`island__river__f00`〜`f15`）。アプリは1秒に10コマ切り替えるだけ（`WATER_FRAMES`・`WATER_FPS`。Blender の N・FPS と同じにする）。**Blender でも再生すると同じ速さで動く**（ユーザー「ここでアニメーションぽっく動かないけど」）：各コマの hide_viewport・hide_render にタイムラインの位置で決まるドライバー。式は「単純な式」だけで書く（% や or を使うと Python が要り、自動実行を切った Blender で開き直すと動かない。`is_simple_expression` を確かめる）。最初のころの絵ではシーンの値 `island_stream_off` を 1 にして小川のコマを隠す。元の水面 `island__stream`・`island__river` はコマの元で、画面でも撮る絵でも隠し、アプリにも書き出さない
- **引きで見られる（2026-10-06）**：全体が見える距離の 2 倍まで（`distLimits`）
- **試し：川の画面に近い質にする（2026-10-07、ユーザーの OK 待ち）**：島は 3D のまま、見た目の材料を Blender で良くする
  - 地面：`bake_lightmap.py` が Cycles で「光だけ」（DIFFUSE の直接＋間接）を上から見た絵（512×512、`assets/island/lm_ground*.png`、明るさ半分で保存）に焼く。アプリは「光を焼く前の元の色（`island__ground_albedo`）× 光の絵 × `LM_GAIN`」。`LM_GAIN` は前の草地の色とブラウザの絵で数値を比べて合わせた（2×1.15）。焼くときの空の光は 0.45（強いと草地が白く青みがかった）
  - 水：`water_glint.py` が作ったきらめきの絵（流れの向きに細長い光の筋、つなぎ目なし）を、小川・海へ出る川・淵・池の水面に足し合わせ、アプリが下流へずらす（`FLOW_SPEED` 0.6m/秒。絵を貼る場所は `flowUV`）。16コマの切り替えは、この試しの間は使っていない（Blender で再生するときのコマは残っている）
  - アプリの描き方：`antialias`・`dpr` 2 まで。水が流れるので1秒に15回描く
  - **景色（林・岩）と言葉の植物も Cycles の光に（2026-10-07）**：`bake_faces.py` が物ごとにライトマップ用の UV「LMF」を作り、Cycles で光だけを絵に焼き、三角形の真ん中の明るさを読んで「Albedo × 明るさ × 1.15」を Baked に書く（地面の光の絵と同じ明るさ）。アプリに UV を送らずに済む（データは増えない）。景色は 4096×4096（1024 では2.4万三角形が1.5ピクセル未満で、焼けていない所を読んだ）、植物は種類ごとに草地の板1枚の上で 512×512。焼く間だけ空の光を青みのない白（強さ 0.8）にする（朝の空 0.45 では日陰がほぼ真っ暗）。下限：景色 35%・植物の葉 45%・花びら 55%
- **重さ・切り替えの遅さを直した（2026-10-07、ユーザー「画面切り替わり遅いし、重い」）**
  - 使っていない部品を書き出さない（水の16コマ・光を焼いた前の地面）。飾りの花・ガマ・シダを減らした（景色 3.7万 → 2.5万三角形）。島のデータ 1.6MB → 0.9MB
  - 3D は画面が切り替わる動きが終わってから準備する（`InteractionManager.runAfterInteractions`。その間は空の色だけ）
  - 描く細かさは 1.5 倍まで（`dpr` 2 では描く量が4倍）
- **水の流れを自然に（2026-10-07、ユーザー「違和感ありすぎ」）**：白い細長い筋が1枚、同じ速さでまっすぐ動き、ベルトコンベアに見えた → `water_glint.py` を、水底に映る光の網目（コースティクス）の絵に作り直し、アプリで大きさと速さを変えた2枚を重ねてずらす（`FLOW_A` 0.42m/秒・`FLOW_B` 0.26m/秒で少し横へ）。重なりが変わってゆらいで見える
- **小川が浮かない・河口が自然に（2026-10-07、ユーザー「川が地面から浮いていて、不自然で全然ダメ」「海に流れ出る川が気持ち悪すぎて」）**：岸は狭く溝は浅く（水面の 0.07 下）、水の板は溝より広く（`WATER_PAD` 0.6）して岸の地面で縁を隠す。板の縁はその場所の地面より少し下に（斜面で浮かない）。海へ出る川は細く曲がりくねり、浜の手前で水の帯を終え、そこから先は海面より下の溝に海が入る。川の色は下流ほど海の浅い所の色へ。光の網目は控えめ（0.26・0.22）。光の絵は 1024
- 近くで水まわりを撮る：`node scripts/island/closeup.mjs <フォルダ>`（河口・河口を開いたときの向きから・木のそばの小川・上流。開発中だけの `__islandRigRef` でカメラを動かす）
- **スマホで流れて見えるかは、まだ確かめていない**（ブラウザでは0.5秒ずつの3枚で網目が動くのを確かめた。Android のビルドに光の絵・水の絵が入ることも確かめた）
- **4画面は見る時間の長さでも分ける（2026-10-06）**：拾ったことば＝最近（今日〜今週）、夜空＝ひと月くらい、島＝**直近12か月**（2026-10-06 に「ずっと」から変えた）。島の大きさは「この1年の積み重ね」の意味
- **島は1つだけ。増やさない・作り足さない（2026-10-06）**：ユーザー「発展していくといろんなデザイン考えなくていけなくるし、ゲームっぽくなるよね」。年ごとの島（諸島）は見送り。12か月より前の言葉は静かに消える（枯れない）。昔の自分は川の「過去の自分の泡」で出会う。**島に新しい仕組み（レベル・集める・広げる・作り足す）を足したくなったら、ゲームっぽくならないか先にユーザーに聞く**
- **すぐ飛べる印（2026-10-06）**：どの画面からも行きたい画面へ1回で。今の動画（川⇄拾ったことば⇄夜空、夜空→川）と川⇄島の動画はそのまま、それ以外はふわっと入れ替える。タブの棒は使わず、端に小さな4つの印（案）。拾い終えたころ島の印がそっと光るだけ（押すかは自分で）
- **6つ目の種類「していること」（2026-10-06）**：料理・作る・絵を描く・書く・写真・片づけ・植物を育てる／散歩・運動・外に出る・お風呂／読書・音楽・映画・ゲーム・調べもの／人と話す・誰かを手伝う・一緒に食べる／計画を立てる・旅・新しい場所・買い物・カフェ の24語＋場面から「趣味」「勉強」を移す。理由：前の約100語に「何をしていたか」がなく、ワクワクの源に届かない。島に新しい植物の形と色が1つ要る
- **ワクワクの木は1日目から若木で立つ（2026-10-06）**：わくわくに近い言葉を拾った日は実が1つ増え、その日一緒に拾った言葉の花が木のそばに咲く（1週目から見える）
- **第1段（AI なし）の動物は、決まった形の文に拾った言葉を当てはめて話す（2026-10-06）**。例「きのうは『帰り道』と『気になる』が、いっしょだったね」
- **夜空＝つながり、島＝流れ**：夜空は同じ日に一緒に拾った言葉を星座の線で。島は時間の中で言葉がどこから来てどこへ行くかを、小川・池・渦で。それに動物の日記
- **水の2つの道**：拾った言葉は空を通る（星 → 種 → 植物 → 島の湧き水・小川）。拾わなかった言葉は川を通って海へ流れ込み、島を囲む静かな海になる
  - 島のまわりは**海**。遠くに**川の河口**が見える。川の水は島の中に入らない（島の水は空から：星・雨・朝露）
  - 島 → 川は、海に流れ込む川をさかのぼって戻る
- **小川の矢印のもとは両方**：ふだんは日をまたいだ順番（**3日以内**、近い日ほど強く）。一行の文章を残した日は、その文の流れも足す
- **変わる速さ**：水の量・太さは毎日少しずつ。小川ができる・消えるのは月に1回くらい
- **ストレスになりそうな言葉は自然の一部として**：朝に出て晴れる霧・休める木陰・降ったあと植物が育つ雨雲。嫌なもの・汚いものにしない（正直に拾えなくなるため）
- **最初のころは小さな水たまり・湧き水**が少しずつ現れる（小川の前ぶれ）。小川はデータがたまってから
- **ワクワクの木は島に1本**。好奇心の言葉＋わくわくに近い気持ち（わくわく・ときめき・喜び など）が木になる
- **歩き方は今のまま上から**。触れた所へカメラが近づく（目の高さで歩かない）
- **動物**：**1匹**。どんな動物かは Blender で2〜3案の静止画を作って見比べて決める。**話すのは近づいて触れたときだけ**
- **霧の出す所**：ぐるぐる回る流れ（渦）の所。「この言葉はストレス」とアプリが決めない
- **月1の小川の変化**：知らせずにそっと変える。動物に触れると「新しい小川ができたみたい」と話す
- **朝日は、前に来てから育った所**に当てる。池は水面のきらめき。前に島を見た時刻は **Convex** に保存
- **直さずに残した AI の一行**も矢印に使う。ただし直した文・自分で書いた文より弱く数える

## 2. 島の設計（案。決定ではない所は SPEC の未決事項）

### 植物（拾った記録だけから決める）

| 記録 | 島で起きること |
|---|---|
| 言葉を拾う | その言葉の種が空から降りて、芽が出る |
| 同じ言葉を何度も拾う | 大きくなる（芽 → 花 → 木） |
| 強く拾う | 色が濃くなる（軽い言葉は白っぽい） |
| 言葉の種類 | 形が変わる。気持ち＝花、体の感じ＝草の株、場面＝茂み、したいこと＝若木、好奇心＝ワクワクの木、**していること＝新しい形（案：実のなる低木。2026-10-06 に6つ目の種類を足すと決定）** |

| 新しい種類の言葉・言葉の数が増える | ~~島が少し広がる~~（見送り 2026-10-06。島の形は変えない） |
| 前に島を見たあとに育った | 朝日が当たる（決定）・蝶が止まる（案）。まだ作っていない |

- 1回だけの言葉は芽（双葉と、種類の色の小さなつぼみ）
- 色は `src/wordCloud.ts` の `CATEGORY_COLOR`（拾ったことばと同じ5色）を元に、強さで彩度と明るさを変える
- 言葉が少ない間（最初の数日）も、島そのものが気持ちいい景色であること。芽が1つでもさみしくない

### ワクワクの木と、そばに咲く花
- ゴールの瞬間を見せる場所。「ワクワクの木のそばに、いつも同じ花が咲いている」景色を見て、ユーザーが自分で気づく
- そばに咲く花＝好奇心の言葉と同じ日によく拾う言葉（順番なし）
- **決定**: 木は島に1本。好奇心の言葉＋わくわくに近い気持ちの言葉が、この1本に集まる（どの語を入れるかの一覧は作るときに見せて決める）
- 試作ではまだ木を特別に扱っていない（好奇心の言葉ごとに木を植え、ほかの植物と同じグループ分け）。**1本にまとめる直しが要る**
- 案：1本の木を草地の真ん中に置き、まわりにそばの花を寄せる。木の大きさは、集まった言葉の回数の合計で

### 島に流れる小川（景色で見せること・矢印の作り方・変わる速さは決定）

言葉から言葉への流れ（矢印）を水の流れにする。小川の水は空から来た水（拾った言葉）。ことばの川の水（拾わなかった言葉）は島に入らない。

| 見せたいもの | 使う計算（ネットワーク分析） | 島での見え方 |
|---|---|---|
| 時間の流れ（言葉から言葉へ） | 有向グラフ：つながりに向き（矢印）がある網の目 | 小川のほとりに、上流から下流へ順番に植物が並ぶ（決定）。よく通る流れほど太い |
| ワクワクの源 | ハブへの入次数：たくさんの線が集まる言葉に、どの言葉から矢印が来るか | ワクワクの木の根もとへ流れ込む小川。どの花から水が来るかで「計画 → ワクワク」が見える |
| 行き着く言葉 | PageRank：矢印をたどり続けたとき、たどり着きやすい所 | 池のほとりに咲く（池は言葉ではない。決定）。水面がきらめく |
| ワクワクを邪魔しているかもしれない流れ | 強連結成分分解：矢印でお互いに行き来できる輪 | 水がぐるぐる回る渦・霧のかかる所。言葉で注意しない |

- 矢印は「この言葉のあとに、よくこの言葉が来る」だけ。原因と結果として書かない・見せない
- **同じ回の中で拾う順番は、川に流れてきた順番（偶然）**。矢印に使わない
- 矢印の元（決定）: ①日をまたいだ順番（ある日の言葉 → 3日以内の言葉。重さは仮に 次の日 1・2日後 0.5・3日後 0.25。カレンダーの日で数え、開かなかった日を詰めない）②残した一行・日記の文（「計画していたらワクワクした」→ 計画 → ワクワク）。直さずに残した AI の一行も使うが、弱く数える（決定）
- 毎日拾う言葉（「疲れ」など）からはどこへでも矢印が出る。偶然より明らかに多い流れだけ小川にする
- 小川の形（できる・消える）は月の初めに決め直す（案）。毎日は水の量・太さだけ変える
- 流れが始まる言葉（矢印が出ていくばかりの言葉）は湧き水のすぐ下、いちばん上流に咲く（案。湧き水は言葉ではない）
- 植える場所：奥⇄手前＝矢印の順番、横＝一緒に拾うまとまり（案。SPEC D. の「小川の形の作り方」）。矢印の網の目は、太い矢印だけで木の淵に集まる川の形にまとめ、行き来する言葉は同じ高さに並べて渦にする
- データが少ない間は小川を出さない。最初は小さな水たまり・湧き水が少しずつ現れ、木のそばの花で見せる
- 霧・木陰・雨雲は「自然の一部」。霧は、ぐるぐる回る流れ（渦）の所に出す（決定。言葉に良い・悪いの印を付けない）

### 島の動物（2026-10-05 ユーザーの思いつき。いつ話すかは決定）

## 3. 今の作り方（試作のコード）

### 植え方（`src/islandLayout.ts`）
```
大きさ   = 0.55 + 0.25 × √回数        （上限 1.8）
育ち     = 1回なら芽（0）。2回から 0.35 + 0.13 × 回数（上限 1）
島の半径 = 2.4 + 0.55 × 言葉の種類の数 + 0.06 × 言葉の数
```
- グループ分け（`findGroups`）
  1. 同じ日に一緒に拾った日数（`cooccurrence`）が2日以上の組だけ
  2. コサイン＝一緒の日数 ÷ √(片方の日数 × もう片方の日数)。0.3 未満は使わない（`MIN_ASSOC`）
  3. お互いの上位3つ（`MAX_LINKS`）に入る組だけ残す
  4. ラベル伝播（となりの多数派に合わせていく）で分ける。順番を固定して毎回同じ結果に
- 位置: 大きいグループほど島の真ん中寄り、黄金角でずらす。言葉が少ない間は、まとまりを真ん中に寄せる（広がり ＝ √(言葉の数 ÷ 20)、1 まで）。グループの中はらせん状。最後に `relax` で近すぎる植物を押し離し（間隔 0.22＋0.2×大きさ を2つ分）、島の 8 割の内側に戻す
- 仮のデータ: `sampleCaptures.ts` の28日分を3回くり返して約3か月（くり返しで5件に1件抜く）。2か月目から6語（やってみたい・調べたい・ひらめいた・スッキリ・趣味・楽しみたい）を足す。仮のデータで決めた組（仕事帰り・不安・好奇心・休日・逃げたい）どおりにグループが分かれるのが正しい結果

### 3D の描画（`src/components/Island3D.tsx`）
- `<Canvas flat frameloop="demand">`。flat は色の変換なし（設定した色のまま出る）。demand は**動いているときだけ描く**（指で動かす・育つ・カメラが近づく・選んだ印が脈打つ間）。描き直してほしいときは `invalidate()`（指の操作は `rig.invalidate`）。v7 から水が流れるので、それに加えて1秒に15回だけ `invalidate()`（`WATER_FPS`。監査では触っていない2秒に約30回）
- 流れる水：Blender の光の網目の絵（`water_glint.png`）を、水面に足し合わせる2枚の材質の地図にして、`useFrame` でずらす（`FLOW_A`・`FLOW_B`）。絵を貼る場所は `flowUV`。地面は「元の色 × 光の絵 × `LM_GAIN`」
- **見た目はすべて Blender から**（`src/islandKit.ts`。地面・海・空・太陽・植物・岩）。材質は MeshBasic（光の計算なし）で、Blender で焼いた色をそのまま出す。霧・ランプは使わない（作り方は 4. の「地面・海・空を Blender で作り、光を焼く」）
- **構図**（縦長の画面では、横の見える幅で島の大きさが決まり、上下は必ず余る。余りを景色にする）
  - 見下ろす角度 0.3、カメラを少し上へ 0.09 向ける → 地平線は上から約25%、島の真ん中は約60%
  - 距離 ＝ 見せる範囲 ÷ tan(横の半分の画角)。v4 では範囲＝草地の真ん中から一番遠い植物＋2（7.5〜12）。最初から草地全体と奥の林が入る
  - 見る点は草地の真ん中（高さ 0.6）。開いたときは 1.25 倍の距離から近づく
  - 歩く：見る点＝触れた地面＋0.6、距離＝全体の約半分（最小 4.2）
- 地面は `island__ground` を横だけ `R / 6` 倍。空と太陽はカメラについて動かし、いちばん先に描く（奥行きを書かない）
- 植物: Blender の部品（`種類__役`）ごとに **InstancedMesh 1つ**。色は「焼いた光 × `setColorAt` の種類の色 × 1.35」。位置は**育っている間・島が広がる間・選んだものが変わったときだけ**計算し直す
- 植物の色：茂み（場面）と若木（したいこと）は葉を緑に寄せ（0.7 前後）、種類の色は実や先の方だけに（青や黄と緑を半々に混ぜると灰色・とんがり帽子になる）
- 根もとに薄い丸い影（`#35552f`・0.2。アプリで作っている）。選んだ植物の根もとに光の輪（2.4秒だけ脈打って止まる）
- 岸の岩6つ（Blender の `rock__rock`、色 `#a39d93`、島の 0.92〜0.99 の所）。言葉ではないので触れても何も出ない
- 時期を変えたとき: 新しい言葉は種（光の粒）が 1.3 秒で降り、0.9 秒で育つ（少し弾む）。降り始めは 1.6 秒の間でばらつかせる。前からある言葉は大きさだけ変わる。カメラは全体が見える所へ戻る
- 触れた所: 画面の上で、触れた点から 44px 以内のいちばん近い植物（の高さの真ん中）を選ぶ。なければ地面に光線を当てて、そこへ歩く
- 言葉のラベル: 選んだ植物の上の点を画面に写し、Reanimated の共有値で RN の文字を動かす。画面の内側（左右 8px、上 96px・下 200px）に収める
- 確かめ用：Web の開発中だけ `globalThis.__island`（植物の画面上の位置）・`__islandRig`（カメラ）・`__islandFrames`（描いた回数）を出す

### 指の操作（`src/app/island.tsx`）
- 1本指のなぞり＝回る、つまむ＝寄る・離れる、触れる＝選ぶ／歩く、2回触れる＝全体に戻る
- ジェスチャーは `.runOnJS(true)`（描画の計算は JS で動くので、そちらで値を書き換える）
- Canvas の上に透明な View を重ね、そこに `GestureDetector` を付ける（Canvas 自身の触れる仕組みとぶつけない）
- 上に淡い光の帯（`rgba(255,238,226,0.8)`→透明、高さ120）、下に薄い影の帯（`rgba(24,70,84,0.32)`、高さ170）。文字は `#4a3b42` に白いにじみの影

- 島の画面だけ `StatusBar style="dark"`（明るい朝の空。アプリ全体は白い文字）
- 時期のボタンは高さ約36px（上下 9px の余白）

### Poly Pizza のライセンスと料金（2026-10-05 に調べた。公式の Press ページ・利用規約より）
- **モデルは無料で商用利用できる**。ただし、モデルごとのライセンスに従う（利用規約は「ダウンロードしたときに付いている Creative Commons のライセンスに従う」とだけ書いている）
  - **CC0**: 条件なし（クレジットも不要）
  - **CC-BY 4.0**: 作者名を出す。書き方は「"モデル名" by 作者名 (poly.pizza) CC-BY 4.0」
- **なるべく CC0 だけを使う**（検索に `licence: "CC0"`）。クレジットの手間と、あとで作者名を管理する手間がなくなる
- **API は「趣味は無料、商用は従量課金」**（公式 Press ページ）。商用の料金の中身は見つからなかった。「アプリが商用でも、素材を探して取り込むのは趣味の範囲」と読むのが自然だが、確かではない
  - 迷うときは API を使わず、サイトから手で `.glb` をダウンロードして Blender に読み込む。または https://poly.pizza/support に問い合わせる
- 禁止: サイトの内容を自動で大量に集める（スクレイピング）、AI・機械学習の学習に使う（書面の許可なし）。アプリの素材として数個〜数十個使うのは当てはまらない
- **使ったモデルの名前・作者・ライセンス・入手元（URL）を記録する**（`docs/` か assets の横に表で）。あとで確かめられるように

### Blender に取り込む手順（2026-10-05 に通した手順）
- 作業ファイル: `C:\Users\nobu2\Documents\pukapuka_blender\pk_island_parts_v1.blend`（川のファイルとは別。部品は `IslandParts` コレクション、親の空の物体 `PP_名前` に `polypizza_id`・`polypizza_licence`・`polypizza_attribution` を付けた）

- 通信が時々 `SSL: UNEXPECTED_EOF` で切れる（検索でも出る）。**6回まで、間を空けてやり直す**。何度実行しても同じ結果になるように、取り込み済み（`PP_名前` がある）は飛ばす
- 取り込んだら必ずやること
  1. **フラットシェードにする**（`polygon.use_smooth = False`）。なめらかなまま取り込まれ、川の v9 のローポリと合わない
  2. **色を pukapuka の色に塗り直す**（材質の Base Color のつながりを外して色を入れる。sRGB → linear に直す）。岩は元の色だと赤茶
  3. **使わない部品を隠す**（うさぎには色のない球 `Icosphere` とにんじん `Carrot` が付いていた）
  4. 大きさをそろえる（一番長い辺で。木 2.4・茂み 1.0・花と草 0.6・岩 0.9）
- 撮るとき: カメラの距離は、**全部の部品の範囲から計算する**（決め打ちだと端の木が切れた）。EEVEE・Standard・50%
- Blender の書き出し画像は Windows の一時フォルダ（`%TEMP%`）。WSL からは `/mnt/c/Users/nobu2/AppData/Local/Temp/` で読める

### 素材を選ぶ・直すときの決まり
- **作者（シリーズ）をそろえる**。作者が違うと、形の丸さ・面の細かさがばらばらになる
- **色は pukapuka の色に塗り直す**（2. の色、`CATEGORY_COLOR`）。素材の色のまま使わない
- フラットシェード・角のある形に。なめらかすぎるものは使わない（川の v9 の絵柄）
- 重さの目安（仮。実機で決める）: 植物1本 300 三角形まで、島の全体（植物100本込み）5万三角形まで
- CC-BY を使ったら、作者名と出どころを記録して、アプリのクレジットに出す
- 書き出しは glTF（`.glb`）。アプリで読むときの方法（expo-asset と GLTFLoader）は、最初の1つで実機で確かめてから決める

- **地面の模様や起伏を角度で決める** → 島の真ん中にうず巻きができる。場所（x, z）で決める
- **海のつやを強くする**（roughness 0.25）→ 朝日が海面に照り返して、空まで白い柱に見える。0.75 くらいに
- **カメラの距離を最初の島の大きさで固定する** → 島が広がるとはみ出す。時期を変えたら全体が見える所へ戻す
- **見下ろす角度を急にする**（0.55）→ 空が見えず、海と霧だけの灰色っぽい景色になる。0.38 くらいで地平線と朝日を入れる
- **植物を大きくしすぎる**（上限 2.4）→ 木が島を覆う。上限 1.8
- 素材の色のまま使う／作者の違う素材を混ぜる → 絵柄がばらばら
- 数字・順位・グラフ・「分析」という言葉を島に出す（決まりに反する）
- 渦・霧に「注意」「よくない」などの言葉を添える（助言しない）

### 3D の技術
- **スマホで島を開くと「undefined is not a function」（three.cjs:12）で止まる**（2026-10-05、実機で発生。ブラウザでは出なかった）→ three.js の require 用の入口 `build/three.cjs` が最初に `process.emitWarning`（Node.js にしかない）を呼ぶ。@react-three/fiber のスマホ用は `require('three')` で読むので、スマホだけこの入口を通っていた。**`metro.config.js` で `three` を `build/three.module.js` に向ける**。Metro の設定を変えたら、サーバーを `--clear` で起動し直す。確かめ方：`npx expo export --platform android --dev --no-bytecode` の JS に `THREE_CJS_DEPRECATED` が 0 件
- ブラウザで動いても、スマホで動くとは限らない（読み込む入口がちがう）。新しい道具を入れたら、`expo export --platform android --dev --no-bytecode` の中身も見る
- `@react-three/fiber/native` を直接読み込む → Web とスマホで読み込みを分ける手間が増える。`@react-three/fiber` から読み込めば、スマホでは package.json の `react-native` の指定でスマホ用が使われる（Web はそのまま Web 用）
- 指の判定を three.js の光線だけで行う → 細い茎や小さな芽に当たらない。画面の上の距離で選ぶ
- 3D の中に日本語の文字を描く → 重いし文字の用意が要る。RN の文字を重ねる
- ジェスチャーの中で JS の値を書き換えるのに `.runOnJS(true)` を付けない → UI の側で動いて、描画の側に届かない
- **`frameloop="demand"` にしたのに、状態（選んだ植物・時期）を変えたとき `invalidate()` しない** → 次に何かが動くまで画面に出ない（植物に触れても言葉が出ず、回したら出た）。状態が変わる所では必ず描き直しを頼む
- 選んだ印をずっと脈打たせる → 止まっていても毎コマ描き続ける。少しの間だけ動かして止める
- 毎コマ全部の植物の位置を計算し直す → 動いているときだけ
