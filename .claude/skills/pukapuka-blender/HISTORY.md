# pukapuka Blender スキル

pukapukaアプリ用の背景アニメーションをBlenderで制作するためのスキル。川・星の背景画像/動画を作るときに呼び出す。

**世界観・カラーパレットは `/pukapuka-design` に定義済み。このスキルはBlenderの技術メモに特化。**

## 現在のシーン構成（川・低ポリアニメシーン）

Blenderファイルはローカルの Blender に接続して作業する（MCP経由）。

### マテリアル（確定版: 夕景アニメパレット）
色はすべて sRGB 表記。`s2l()` で linear に変換して入れる。
| 名前 | 構成 | 色 | 役割 |
|---|---|---|---|
| WaterFacet | Mix( Add(Emission,Diffuse), Glossy, fac=0.032 ) | Em色=フレネルで (.16,.46,.55)→(.95,.66,.62) str0.30 / Df (.13,.39,.48) / Gl (1.0,.90,.76) rough0.30 | 水面。Glossyが夕日の道、フレネルで遠くほど夕焼けを映す |
| Ground | Diffuse | (.36,.53,.26) | 草地 |
| LeafA / LeafB | Diffuse | (.40,.55,.26) / (.30,.46,.24) | 葉（2トーン） |
| Bark | Diffuse | (.42,.30,.23) | 幹 |
| Rock | Diffuse | (.66,.60,.54) | 岩 |
| MtnSoft | Diffuse | (.52,.54,.66) | 遠景の丘 |
| SunCore | Emission str5.0 | (1.0,.94,.80) | 太陽の芯 |
| SunHalo | Mix(Transparent, Emission str2.6) | (1.0,.82,.55) | 太陽のグロー |
| 霞(Haze) | 各マテリアルに Mix | (.99,.85,.75) | 空気遠近。下記参照 |

**重要**: Emissionはパレット色を固定するためだけに **strength 0.3前後**で使い、陰影はDiffuseに担わせる。Emissionを強くすると面の陰影が消えてジオメトリが見えなくなる（波が見えない原因になる）。

### 地形と水面の作り方（確定版・2026-10 v2）

**川の中心線（CL）— v5 ★現行: ゆるいS字** — まっすぐな川は用水路に見える。直線の基線に横方向のサイン波を足し、0.5刻みの181点で持つ。**`scene["CL"]` に JSON で保存してあるので `json.loads(scene["CL"])` で読む**（毎回計算し直さない）:
```python
B0=Vector((10.6,9.1)); u=Vector((-11.8,-8.8)).normalized(); n=Vector((-u.y,u.x))
def off(t):                               # t=基線上の距離
    amp=1.5+0.07*max(0,t-11)              # 奥ほど振れ幅を大きく（遠近で縮むのを補う）
    return smoothstep(8,13,t)*amp*sin((t-11)*2*pi/19)   # 手前(t<8)はまっすぐ＝言葉が流れる帯を中央に保つ
CL=[B0+u*t+n*off(t) for t in arange(-15,75,0.5)]
```
- 弧長 sv は t=-15 から数える。**旧CL（直線）の sv に +15 すると同じ奥行き**になる
- 画面上の川: 手前 x0.45〜0.5 → 中景で左 0.36 → 奥で右 0.71 → さらに奥 0.44。奥の川は右の木立の向こうに回り込んで消える
- 川幅もゆらす: `HW(sv)=1.55+0.22*sin(sv*0.31+0.7)`。地形・水面の範囲（d<HW+1.25）・WaveMask（smoothstep(HW-0.05, HW+0.8)）すべてこの HW を使う
- 地形は Ground の頂点 z を height() で書き直すだけ（グリッドとSUBSURFはそのまま）。水面は bmesh で作り直して River.data に入れ、頂点グループ WaveMask を作り直してから Wave の vertex_group に再設定する

**地形（Ground）** — 中心線までの距離 d で高さを決める。**乱数をZに足さない**（とげとげの原因）:
```python
HW=1.55; BANK=2.3
def height(x,y):
    d=dist_cl(x,y)
    hill=(0.30*sin(x*0.20+1.1)*cos(y*0.17-0.6)      # 正弦波の合成＝なめらかな丘
         +0.16*sin(x*0.38-2.0)*sin(y*0.33+0.8)
         +0.08*cos(x*0.63+0.3)*cos(y*0.57-1.4))
    if d<HW: return -0.55                            # 川底
    z=-0.55+0.95*smoothstep(HW,HW+BANK,d)            # 土手（両端で傾き0＝折れない）
    far=max(0,d-(HW+BANK))
    return z+0.045*far+hill*min(1,far/3.5)
```
グリッド 62×62 / 間隔0.55、xyのゆらぎは **±0.07まで**、市松に三角分割、`use_smooth=False`。

**水面（River）** — 中心線から d<2.7 のセル（間隔0.38）、z=-0.14 の**平らな**グリッド。土手の下にもぐらせる。
`River.visible_shadow=False` — 波が自分に落とす影が硬い縞になるので切る。

**空の映り込み（フレネル）** — `LayerWeight(Blend 0.55).Facing → MapRange(From Min 0.45, Max 1.0) → Mix(RGBA).Factor`、A=水色(.16,.46,.55) / B=夕焼け(.95,.66,.62) → 水面Emissionの Color。浅い角度で見る遠くの水ほど空色になり、手前は水の色のまま。From Min を 0.35 まで下げると中景が灰色に白む。

**波マスク（頂点グループ WaveMask）** — 重み `1 - smoothstep(1.5, 2.35, d)`（d=中心線距離）を River に作り、Waveモディファイア2枚の `vertex_group='WaveMask'`。縁の波を0にして、水面の縁が土手の上に出ないようにする。ループは崩れない（frame1 vs 97 差 3e-6 で確認済み）。

**地形の細分化** — Ground に SUBSURF level 2（`use_smooth=False` のままなのでローポリ感は残る）。

**波（Waveモディファイア2枚）** — これが「流れ」の本体:
```python
def add_wave(name,sx,sy,h,w,T,narrow):
    m=riv.modifiers.new(name,'WAVE')
    m.use_x=m.use_y=m.use_cyclic=True; m.use_normal=False
    m.start_position_x=sx; m.start_position_y=sy
    m.height=h; m.width=w; m.speed=2*w/T      # 時間周期 T フレーム = 2*width/speed
    m.narrowness=narrow; m.falloff_radius=0; m.lifetime=0
    m.time_offset=-8000.0                     # ★必須。理由は下のNG
add_wave('WaveA',-46,-40, 0.105,1.15, 96, 1.2)   # 上流から：96フレームで1周
add_wave('WaveB', 20,-55, 0.048,0.65, 48, 1.8)   # 横から当てて縞を崩す：48フレームで2周
```

### 速く・品質を落とさずに進めるルール（厳守）
**線引き: 軽くするのは途中の確認だけ。最終判断に使う静止画と最後の動画は必ずフル品質。**

1. **確認用の静止画は半分の解像度で撮る**（約4分の1の時間。最終MP4も540×960なので判断は変わらない）
   ```python
   scene.render.resolution_percentage = 50    # 確認用 → 540×960
   # ユーザーに最終確認してもらう1枚と、動画書き出しの前に必ず戻す
   scene.render.resolution_percentage = 100
   ```
2. **レンダリングの前に数値で確認する。** 数値で明らかにおかしければ撮らずに直す
   - 配置: 側ごとの本数、`world_to_camera_view` の画面 x/y/奥行き
   - 波: `evaluated_get(depsgraph).to_mesh()` の Z（動いているか・ループするか）
   - マテリアル: 材質ごとの面数とz範囲
3. **小さな修正はまとめて1回で撮る。** 「岩を消す」「スケールを変える」程度は1つずつ撮らない
4. **原因を絞ってから直す。** 怪しいオブジェクトを `obj.hide_render=True` で隠して1枚撮り、見た目が変わるか確かめてから修正する（地形と思い込んで2回無駄にした失敗の再発防止）。確かめた後は `hide_render=False` に戻す
6. **位置や範囲を決める前に、必ず数値で確かめてから撮る（当て推量で直さない）** — 2026-10-03 に、画面下端が川のどこ（sv）かを確かめずに「手前を細くする範囲」を決め、画面にほとんど効かず1回分無駄にした。画面の点を地面の平面に落として sv を調べてから範囲を決める:
   ```python
   fr=[cam.matrix_world@v for v in cam.data.view_frame(scene=s)]; tr,br,bl,tl=fr
   def gp(sx,sy):  # sx,sy: 0〜1（sy は上から）→ z=-0.14 の平面上の点
       p=tl.lerp(tr,sx).lerp(bl.lerp(br,sx),sy); d=p-cam.location
       return cam.location+d*((-0.14-cam.location.z)/d.z)
   # 例: gp(0.5,1.0) が画面下端の中央。dsv() で sv を出す
   ```
7. **中心線との距離計算は近い区間だけ探す** — 全180区間を総当たりすると、水面1万点×数回で待ち時間が延びる。CL は0.5刻みで等間隔なので、KDTree で一番近い点を見つけ、その前後2区間だけ調べれば同じ結果になる:
   ```python
   from mathutils import kdtree
   kd=kdtree.KDTree(len(CL))
   for i,(x,y) in enumerate(CL): kd.insert((x,y,0),i)
   kd.balance()
   def dsv(x,y):
       i=kd.find((x,y,0))[1]; best=(1e9,0)
       for k in range(max(0,i-2),min(len(segs),i+2)):
           a,l,x1,y1,dx,dy=segs[k]
           t=max(0,min(1,((x-x1)*dx+(y-y1)*dy)/(l*l))); d=math.hypot(x-x1-t*dx,y-y1-t*dy)
           if d<best[0]: best=(d,a+t*l)
       return best
   ```
8. **構図だけ確かめるときは、なめらかにする設定を一時的に軽くする** — 配置・川幅・カメラなど形の確認では SUBSURF の `render_levels` を下げて撮り、質感の確認と最終の1枚では必ず戻す:
   ```python
   saved={}
   for o in s.objects:
       for m in o.modifiers:
           if m.type=='SUBSURF': saved[(o.name,m.name)]=m.render_levels; m.render_levels=min(m.render_levels,1)
   # …構図確認の撮影…
   for (on,mn),lv in saved.items(): bpy.data.objects[on].modifiers[mn].render_levels=lv
   ```
5. **一部だけ見たいときは範囲レンダリングする**
   ```python
   r = scene.render
   r.use_border = True; r.use_crop_to_border = True
   r.border_min_x, r.border_max_x = 0.0, 0.5   # 0〜1の画面比率
   r.border_min_y, r.border_max_y = 0.3, 0.6
   # 終わったら必ず r.use_border = False に戻す
   ```

## NGパターン（Blender 5.2 API）

- **`scene.render.engine = 'BLENDER_EEVEE_NEXT'`** → Blender 5.2では `'BLENDER_EEVEE'` を使う
- **`curve.fill_mode = 'BOTH'`** → `'FULL'` / `'BACK'` / `'FRONT'` / `'HALF'` のみ有効
- **`spline.points.resize(n)`** → Blender 5.2では存在しない。`bmesh`でメッシュを直接作る
- **`action.fcurves`** → Blender 5.2では `Action` に `fcurves` 属性がない。ドライバーで代替する
- **`scene.eevee.use_ssr`** → Blender 5.2では存在しない。代わりに `use_raytracing = True`
- **`sky.sky_type = 'NISHITA'`** → `'HOSEK_WILKIE'` / `'PREETHAM'` 等を使う
- **`scene.view_settings.view_transform = 'None'`** → `'Standard'` / `'AgX'` 等を使う
- **AgXカラーマネジメント** → 色が大幅に潰される。`Standard` に変更すること
- **Cyclesレンダー** → タイムアウトする。`BLENDER_EEVEE` のみ使う
- **96フレーム一括レンダー** → MCPがタイムアウトする。24フレームずつ4バッチに分けること
- **ノードを名前で検索** → `nodes["Principled BSDF"]` はローカライズされた環境で失敗する。`n.type == 'BSDF_PRINCIPLED'` で検索する

## NGパターン（Blender 5.2 API・追加）

- **`scene.node_tree`** → 5.2には存在しない。コンポジタは `scene.compositing_node_group`（ノードグループ）
- **コンポジタのGlareでブルーム** → ノードグループを作って Group Input→Glare→Group Output と繋いでも、**Group Inputにレンダー結果が入らず真っ白**になる。**使わない**。グローは3Dオブジェクトで作る（上の「太陽」参照）
- **Glareノードの設定をプロパティで探す** → 5.2では `glare_type` 等は**入力ソケット**（Type/Quality は MENU ソケットで値は表示名の文字列 'Fog Glow' など）
- **`light.type='SUN'` の直後に古い `obj.data` を使う** → 型が変わるとPythonのラッパーが無効になり `'AreaLight' object has no attribute 'angle'` になる。**型変更後に `obj.data` を取り直す**
- **Waveモディファイアで `time_offset=0`** → Waveは開始点から**広がっていく波紋**。frame1では `speed*(frame-time_offset)` しか進んでおらず**変位ゼロ**になる（見た目は完全に平らなまま）。`time_offset=-8000` のように大きな負値を入れて波面をメッシュの先まで進めること。`use_cyclic=True` で後ろが埋まる
- **変位しているか目視で判断する** → `evaluated_get(depsgraph).to_mesh()` のZの最小/最大を出せば一発で分かる。レンダーを回す前に数値で確認する

## NGパターン（シーン・ビジュアル）

- **マテリアルテクスチャのドライバーでアニメーション** → EEVEEレンダーで変化が見えない。オブジェクトのキーフレームかモディファイアで行う
- **地面・水面を高さゼロの1枚板にする** → 影も段差も出ず、何を足しても平面に見える
- **地形の高さに乱数を足す** → くしゃくしゃに尖る。**正弦波の合成**でなめらかな起伏を作り、xyのゆらぎも±0.07までに留める
- **三角錐の木・尖ったピラミッドの山** → 画面全体がとげとげしく見える。木はicosphereのブロブ、山は潰したicosphereのドームにする
- **Emissionを強く（0.5以上）使う** → 面の陰影が消え、波やポリゴンの立体が見えなくなる。Emissionは色の固定用に0.3前後、陰影はDiffuseに任せる
- **GlossyをAdd Shaderで足す** → 全面が白飛びする。**Mix Shaderで fac 0.04〜0.05**、さらに `sun.data.specular_factor=0.12` まで落とす。rough 0.06だと白い破片のように尖るので0.20前後
- **霞(Haze)の start をカメラ〜被写体の距離より近くする** → 手前まで霞んで画面全体がクリーム色になる。start は18以上
- **WorldのTexCoord.Normalで空グラデ: Zが上向き正だと思い込む** → Normalは**カメラ向き**なので上空ほどZが**負**。MapRangeを `From Min=0 / From Max=-0.45` と逆向きにする。正のままだと地平線側が派手で上空が淡い逆グラデになる
- **水面に自分の波の影を落とす** → 硬い縞模様になり汚れに見える。`River.visible_shadow=False`
- **影が硬くて尖る** → `sun.data.angle` を0.09前後にして影を柔らかくする
- **bmeshで複数パーツを1メッシュにして、面の作成順で `material_index` を振る** → bmeshの面の順番は作った順にならないことがあり、幹の色が樹冠に、葉の色が根元に付く（葉の下に赤茶の三角が出た）。**面の中心座標で振る**（例: 幹軸からの距離 <0.13 かつ z<0.58 → 幹）。振った後は材質ごとの面数とz範囲をprintして確かめる
- **水面の縁まで波を立てる** → 水路より広く作った水面の縁（階段状の境界）が波で持ち上がり、土手の上に出て岸がのこぎり刃のギザギザに見える。頂点グループで縁の波を0にする。原因を地形と思い込んで地形を細分化しても直らない
- **水面を全面同じ色にする** → 夕焼けの空と馴染まず、別の絵を貼ったように見える。フレネルで遠くほど空色を映す
- **カメラの target を適当な点に向けて終わりにする** → 川が画面の右寄り（x0.55〜0.62）に映り、左岸が画面の6割を占めて、同じ密度で置いても左に木が2倍映る。**川の中心線を投影して x≈0.5 になるまでカメラを回す**
- **木や岩をワールド座標の範囲＋視錐台チェックだけで置く** → 左右の数・奥行き・大きさが偏る（左32本・右14本、左の木が画面中央まで並んで消失点を隠し、右の木は画面外）。置いた後は側ごとの本数と画面 x を print して確かめる
- **偏りを直すために左右対称（鏡写し）にする** → 人工的で落ち着かない（「左右対称すぎていやだ」）。ユーザーが欲しいのは**自然な非対称の調和**。直すべきは「片側が画面外・消失点を隠す」ことで、数をそろえることではない。群れと抜けで置く（上の「自然な配置」）
- **ローポリのフラットシェード（`use_smooth=False`）のまま仕上げる** → 「全体的にカクついている」。なめらかな陰影＋SUBSURF にする
- **水面を川の形に切り抜いたメッシュにする** → 縁の階段がなめらかな地面から顔を出し、岸がのこぎり刃になる。全面の一枚シートを地面の下に敷く
- **泡のスペースのために水面を画面の横幅いっぱいにする** → 岸が見えず湖・海に見えて「川のイメージが薄れる」。手前でも両岸が見える幅に細くし、水際に浅瀬の色・泡の線・小石・ガマを置く
- **小物を明るい色・大きめで草の上に散らす** → ピンクの卵のように見える。くすんだ色で小さく、水際に半分沈める
- **空に画面の半分近くを使う** → 言葉の泡を流す水面が足りない（読める泡が4〜6個しか入らない）。カメラを下に向けて水面を画面の約7割に。太陽は地平線近くに下げれば空が狭くても夕焼けは入る
- **手前の水面の波を強く抑えすぎる／照り返しを奥だけに急に切り替える** → 手前が平らな青一色の板になり、境目に横線ができる。手前の波は55%残し、切り替えは距離で広くなめらかに
- **見本の泡を「奥から隙間に詰める」置き方にする** → 全部が奥に固まる。流れてくる前提で、間隔を泡の大きさに比例させる
- **花や草を岸全体に一様にばらまく／決めた数か所に同じように置く** → 人工的に見える。花は川に沿って細長い「花畑」に、ガマはカーブ内側の浅瀬に株でまとめる。中心は濃く外側はまばら
- **小物の位置を「川からの距離」だけで決める** → 画面の奥（高さ30〜40%）に集まって小さすぎて見えない（v19 で花166輪がほぼ見えなかった）。中心は画面上の点から ray_cast で決める
- **曲がり角の手前の岸に木を置く** → 奥の川と、そこを流れてくる泡を木が隠す（「木がかぶって見えない」）。泡の通り道を `ray_cast` で調べ、当たる木は川から離す。カーブの外側は見通しを空けておく
- **泡を遠近どおりに縮める** → 奥の泡の文字が5〜8pxで読めない。最小の文字サイズ（10px）を守り、遠近は大きさの差で残す
