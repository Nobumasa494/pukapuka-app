# 「わたしのこと」の分析：外部レビュー用の資料

統計に詳しい方に、この画面の分析が妥当かを見てもらうための資料です。
書いてあるのは、コード（`src/flow.ts`）が実際にしていることと、試した結果だけです。判断や評価は書いていません（2026-10-11 時点）。

## 1. 何を知りたい画面か

- 利用者が、毎日、決まった約130語の中から「ピンときた言葉」を拾って記録する（1回の記録＝言葉・時刻・押した強さ）。
- この画面は、**「何をした日のあとに、元気・好奇心の言葉を拾うことが多いか」**を、利用者に見せる。
- 目的は利用者が自分で気づくこと。原因の主張や助言はしない（「〜のあと」は順番であって、因果ではない、と画面にも書く）。

## 2. データ

| 項目 | 内容 |
|---|---|
| 単位 | 暦の日（端末の0時で区切る）。1日に何回拾っても「その日にその言葉を拾った」は1回 |
| 言葉 | 約130語。6種類（感情・からだ・状況・価値観・好奇心・していること）。「していること」は26語（散歩・料理・読書など） |
| 元気・好奇心の言葉 | 元気に近い気持ち11語（わくわく・ほっとした 等）＋好奇心14語（もっと知りたい・やってみたい 等）＝25語 |
| 期間 | 直近12週（84日）。使い始めて12週たっていなければ、使い始めから今日まで |
| 記録の量の目安 | 利用者は毎日開くとは限らない。1日に拾う言葉の数も日によってばらつく |
| 使っていないもの | 押した強さ、時刻（時間帯）、曜日、同じ日の中の順番 |

## 3. 統計量の定義

### 3.1 矢印（言葉 A の日 → 言葉 B）

- 日 d に A を拾い、日 d+k（k = 1, 2, 3）に B を拾っていたら、矢印 A→B に重み w(k) を足す。w = (1, 0.5, 0.25)。
- 記録のない日は詰めない（暦の日で数える）。A = B の矢印は作らない。
- 同じ日の中の順番は使わない（水辺の画面が泡の流れで順番を決めてしまうため）。

### 3.2 「そのあとに」（元気・好奇心の源）

- 候補：A が「していること」26語、B が元気・好奇心の言葉25語の、全組み合わせ（約650組）。
- 各候補の矢印の重さ W(A→B) が、偶然で出る重さより大きいかを、並べかえ検定で見る（3.4）。

### 3.3 「行ったり来たり」

- 候補：全言葉の無順序の組 {A, B}（似た意味の言葉どうし 14グループは除く。例：疲れ・目が疲れた・体が重い）。
- 組の強さ = min( z(A→B), z(B→A) )（行きと帰りの弱いほう）。両方の重さが 2 以上のものだけを対象にする。

### 3.4 並べかえ検定（max-T）

1. 観測した日の「その日に拾った言葉の集合」を、**同じ週（月曜はじまり）の中だけで入れ替える**（日の位置は固定。記録のない日の位置も変わらない）。
2. 入れ替えた記録で、全候補の W を数える。これを 300 回くり返す（アプリ）。試験用スクリプトでは 500 回。
3. 各候補について、入れ替えた W の平均 μ と標準偏差 σ を出し、z = (W − μ) / σ とする。σ が 0 のときは 0.25 とする。
4. 各入れ替えで「全候補の z の最大値」（最小の重さの条件を満たすものだけ）を記録する。これが max-T の分布。
5. 本物の z が、max-T 分布の上位 α（10%）の境目を超えた候補を「確か」とする。上位 30% を超えたものは「確かめ中」とするが、画面には出さない。
6. 画面の「そのあとに」には「確か」だけを並べ、各行には回数（W ではなく、実際に矢印が成り立った回数）だけを書く。

- 片側検定（大きいほうだけ）。
- 「確か」の最小の重さは 3、「確かめ中」は 2（1回きりの偶然を除くため）。
- 乱数は種を固定している（同じ記録からは毎回同じ結果）。

### 3.5 「元気・好奇心の言葉の変化」

- 直近12週の中で、前の期間と最近の期間（長さは 7・14・28・42 日。記録がたまるほど長くする）に分け、元気・好奇心の言葉を拾った**日の数**を言葉ごとに数える。
- 検定はしない。事実として並べる。

## 4. すでにしている確認

| 確認 | 結果 |
|---|---|
| 手で計算した小さな例（矢印・入次数・強連結成分・PageRank・割合など）との一致 | 15項目すべて一致（`scripts/me/hand-test.ts`） |
| 別の計算（Python・NetworkX）との一致 | 矢印・入次数・PageRank・強連結成分・週／月ごとの割合の、見本6人分42項目で一致（`scripts/me/crosscheck/`）。**並べかえ検定と max-T は、別の計算での確認をしていない** |
| でたらめな人（見本の人の日の並びを全体でばらばらにしたもの）に、偽の「確か」が出る割合 | 12週で約11%（200人）、2週〜12週で 8〜12% |
| 同じ人に、偽の「確かめ中」が出る割合 | 約3割 |
| 偽の「行ったり来たり」が出る割合 | 約10%（60〜100人） |
| 気分が数日続く人（いい週・つらい週）に、偽の「確か」が出る割合 | 日を全体で入れ替えると、源 95%・めぐり 100%。**同じ週の中だけで入れ替える**と、源 11%・めぐり 12%（100人） |
| 本物の流れを見つける割合（検出力） | 「散歩の次の日に 6割で、わくわく」を足した人で、12週の時点で「確か」の1位に散歩が出る割合は約55%（6週は約30%） |
| 「行ったり来たり」の検出力 | 週に1回ほど「焦り→後悔→焦り…」が数日続く人で、12週で約22%（日を全体で入れ替えたときは63%）。気分が続く人の偽を避けるために下がった |
| 記録を増やしていったときの変化 | 見本の人で、使った日数が増えるほど、「確か」が出る割合が上がる（1週〜12週。例：2週で約15%、12週で約55%）ことを確認 |

試した「人」は、すべて、こちらで作ったシミュレーションの人（`src/demoPersona.ts`）。**本物の利用者の記録では、まだ確かめていない。**

## 5. 分かっている弱点・迷っている点

1. **多重比較は、画面ごと（「そのあとに」と「行ったり来たり」）に別々にしている。** 両方を合わせると、画面のどこかに偽物が出る確率は約2割（1 − 0.9 × 0.9）に上がる。
2. **「していること」だけを候補にする、という絞り込みは、シミュレーションの結果を見たあとで決めた。** 12週の検出力は、全言葉を候補にしたとき約37%、していること だけにしたとき約55%だった（ただし基準が 5% と 10% で、完全に同じ条件の比べではない）。後づけの選択になっている。
3. **σ の推定に、並べかえの標準偏差を使っている。** 日の数が少ないとき、σ が小さくなりすぎて z が過大になるのではないか、という懸念がある（0.25 の下限で押さえているが、十分かは確かめていない）。
4. **週のかたまりで入れ替えると、「週の中の順番」だけが検定の対象になる。** 週をまたぐ矢印（日曜 → 月曜など）は、入れ替えたあとは、週の最初・最後の日の中身が変わるため、本物とは違う頻度になる。この影響が検定に偏りを入れていないかは、確かめていない。
5. **重み（1・0.5・0.25）と 3日は、検定の前に決めた値。** 3日は利用者の希望で、重みは仮の値。感度の確認（重みや日数を変えたときの結果の変化）をしていない。
6. **アプリ用の並べかえは 300 回。** p 値の細かさは 1/300 程度。「上位10%」の境目の安定性は、くり返しでは見ていない。
7. **「確かめ中」を、使い始めに見せる案があったが、画面には出さないことにした。** 偽が約3割のため。
8. **同じ言葉を毎日のように拾う人は、候補が増えにくい。** 毎日拾う言葉は、並べかえても重さが変わらず、検出されにくい。
9. **一度「確か」になったものを、2週間は残す仕組みがある。** 1週間前・2週間前の結果を再計算して、そのころ「確か」だったものを残す（検定の外の運用）。
10. 12週より前の記録は、画面の計算には使わない。

## 6. レビューをお願いしたい点

- この検定（並べかえ＋max-T）の組み立ては、目的に対して妥当か。もっと簡単で十分な手法があるか。
- 週のかたまりでの入れ替えは、日をまたぐ流れを調べる目的に合っているか。弱点 4 の影響は無視できるか。
- 約650組と約数千組を、画面ごとに分けて 10% で検定する扱いは妥当か。まとめて扱うべきか。
- σ が 0 になる場合の 0.25 の代用は、安全か。
- 「確か」とした結果の見せ方（回数だけ・確かさは出さない）に、統計的な誤解を招く点はないか。
