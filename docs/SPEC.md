この設計書は2部に分かれています。

- **第1部 pukapuka の全体**：何のアプリか、画面、機能、大事にすること。誰でも読める
- **第2部 作りの詳細**：数値・計算・音の作り方など。作る人のためのメモ

# 第1部 pukapuka の全体

## 1. ひとことで

**川を流れてくる言葉を、ぷかっと拾うだけ。**
**拾った言葉は夜空の星になり、朝になると種になって島に降る。自分の「ワクワクの島」が少しずつ育っていく。**

- ひとことで言えば**「書かない日記」**（案）
- 文字は1つも打たなくていい。指で触れるだけ
- 拾った言葉から、AI が短い一行の日記を書いてくれる。話してくれるのは、島に住む動物（案）。残すかどうかは自分で選ぶ（案。10.）
- 1回30秒でいい。疲れた日の逃げ場所にもなる
- 続けるうちに、自分が何にワクワクする人なのかが、景色として見えてくる
- 続けるほど、過去の自分が拾った言葉が、泡になって川を流れてくる（軸。7.）
- **最初に使える版（MVP）では、島はまだ入れない**。代わりに「わたしのこと」の画面が、自分の輪郭（何で元気になるか・好奇心がどう育っているか）を短いことばと数字でまとめる（決定 2026-10-07。下の「MVP」）

## 2. だれの、どんな悩み

- **だれ**：25〜40歳くらいの、疲れている社会人（iPhone・Android の両方。決定 2026-10-07「疲れている社会人」）
- **いつ開く**：朝・帰り道や移動中・もやもやした時・寝る前（決定 2026-10-07）。疲れ切ったとき、すき間時間、ちょっと逃げたいとき
- **1回の長さ**：30秒〜1分（決定 2026-10-07）。開く時間帯で、やることや最初の画面は変えない（決定 2026-10-07）
- **悩み**：「自分が何に興味があるのか、わからなくなってきた」
  - 心の中に湧いた感覚が、つかむ前に消えていく
  - 日記やメモは、書くこと自体が負担で続かない
  - 記録をためても、見返す気になれない
  - 大人のワクワクは、やることに埋もれて消えやすい

## 3. ゴール：好奇心の源に気づき、育っていくのが見える（決定 2026-10-05、言い方を 2026-10-07 に直した）

pukapuka のゴールは、**ユーザーが自分の好奇心・ワクワクの源に気づき、それが育っていくのが見えること**です。
（ユーザーの言葉：「わくわくを育てたい、島を育てたいみたいなところがゴールになりそう」（2026-10-05）、「気づくことはできて、それを育てることはそとになるよね」「あくまで、何かが育っているまでがこのアプリの機能かな？」（2026-10-07））

- **アプリの中**：拾う → 自分を知る → 好奇心の源に気づく → 育っているのが見える（決定 2026-10-07）
- **アプリの外**：実際に育てる行動（散歩に行く・計画を立てる・やってみる）は、本人が自由に選ぶ。アプリは気づきと育ちを映す鏡（決定 2026-10-07）
- 気づいたあとの記録は、MVP とは別の「気づきの日記」に残せる（下の「気づきの日記」）

- **1か月使った人に言ってほしい一言は「何で元気になるかわかった」**（決定 2026-10-07）
- **閉じたときの気持ち**：自分の輪郭がわかり、前に進みたい気持ちになる。勇気がもらえる（決定 2026-10-07、ユーザー「ゴールは自分の好奇心を育てて可視化できる」）
  - 一歩を選ばせる仕掛け（「今日はこれをやってみよう」を選ぶ など）は入れない（決定 2026-10-07）。気づいたあとどうするかは、アプリの外で自由に
- 夜空の星は、朝になると種になって島に降る。島に花や木が育っていくのを眺められる（島は MVP のあと。下の「MVP」）
- **いちばん大事な瞬間**は「本当のワクワクの源に気づく」こと
  - 例：「旅行が好き」と思っていたけれど、本当は「旅行の計画を立てている時間」にワクワクしていた
  - 気づきは「思っていた自分とのずれ」から生まれる
  - 決まった言葉には、6つ目の種類「していること」（計画を立てる・旅・料理 など）がある（決定 2026-10-06）。ワクワクの源は、たいてい「していること」だから
  - 「旅行の計画」ほど細かい言葉は、決まった言葉にはない。AI の一行を少し直したり、ひとこと日記に書いたりすると入ってくる（10.）
- アプリは答えを教えない。ワクワクの木のそばに、いつも同じ花が咲いている。その景色を見て、ユーザーが自分で気づく
- MVP では島がないので、元気・好奇心の源は「わたしのこと」の画面で、短いことばと数字で見せる（決定 2026-10-07。流れの入次数）。ここでも「あなたは〜な人」とは言わず、拾った言葉の事実だけを並べる
- 見せ方は、図ではなく景色で、直感的にわかるようにする（決定 2026-10-05、ユーザー「景色で直感的にわかるほうが良いね」）
  - どの言葉からワクワクへ流れているかは、ワクワクの木へ流れ込む小川の上流に咲く花で見せる（決定 2026-10-06。5. の「島に流れる小川」）

## 4. 大事にすること（決定）

pukapuka のどの画面・機能も、これに反しないようにする。

1. **アプリが決めつけない**：「あなたはこういう人」とは言わない。気づくのはユーザー
2. **分析されている感じを出さない**（2026-10-05、ユーザー「分析している感覚を持たせたくない。ストレスになるから」）
   - 画面に数字・順位・グラフを出さない
   - 変化は景色で見せる（芽が出る、花が咲く、木が少し大きくなる）
   - 言葉から言葉への流れ・行き着く先・くり返すめぐりも、図にせず景色で見せる（2026-10-05、ユーザー「景色で直感的にわかるほうが良いね」）
   - 言葉を添えるなら短い一言だけ（例：「ワクワクの木のそばに、新しい芽」）
   - **例外：「わたしのこと」の画面だけは、数字とグラフを出してよい**（決定 2026-10-07）。自分から見に行く画面なので。ただし上に短いことば、数字・グラフはその下（疲れている日は上だけ読めばよい）。ほかの3画面（川・拾ったことば・夜空）は今までどおり出さない
3. **がんばらせない**：ノルマ・連続記録・点数は作らない。開かない日があっても責めない
4. **助言しない**：「夜は SNS を見ないで」のようなことは言わない。悪い流れも注意として見せない
5. **選ぶのはユーザー**（2026-10-05、ユーザー「あくまで、ユーザーは選ぶ感じがいい。言語化したくないことばもあるし」）
   - AI が書いたもの・取り出したものは、下書きとして見せるだけ。残す・直す・捨てるはユーザーが選ぶ
   - **言葉にしない自由**：言葉にしたくない言葉は、言葉にしなくていい。日記にもカードにも使わない、と選べる
   - ユーザーが選ぶ前に、勝手に記録したり人に見せたりしない
6. **気持ちいいこと**（案）：泡に触れる手ざわり・音・振動が、それだけで心地よい

## MVP：最初に使える版（決定 2026-10-07）

pukapuka は「自分の輪郭を知って、好奇心を育てる」アプリ（決定 2026-10-07、ユーザーの言葉）。
川で言葉を集め、3つの画面がそれぞれ輪郭の一面を分析する。最後の「わたしのこと」が、それを1つにまとめる集大成（ゴール）。
島の3Dはデザインに手間がかかったので、MVP には入れない（ユーザー「島がデザインで変にてこづったから」「できるだけ、絶対必要な機能を入れて、まず使えるようにしたい」）。

| 画面 | 輪郭のどの面か | 分析の方法 | 見る期間 | 数字・グラフ |
|---|---|---|---|---|
| ことばの川 | 材料を集める入口 | ー | 今 | なし |
| 拾ったことば | **今の自分**：何をよく感じ、何を強く感じるか（口ぐせと本音） | 集計（回数・強さの平均） | 最近 | なし |
| 夜空 | **自分の中のまとまり**：どんなテーマが一緒にあるか | 無向ネットワーク（向きのない網の目）・つながりの強さ・偶然との比較（検定）・グループ分け | 6週間（決定 2026-10-09） | なし |
| **わたしのこと**（集大成） | **流れと、わたしの輪郭**：何のあとに元気・好奇心が来るか。それが育っているか | 有向ネットワーク（向きのある網の目）＋時間の変化 | 数週間〜 | **この画面だけ出す** |

- 1つの画面に1つの分析（決定 2026-10-07、ユーザー「ちゃんと画面ごとに技術や分析を区別化したい」）
- 流れ（日をまたいだ順番）は、わたしのことの中で見せる（決定 2026-10-07。流れ専用の画面は作らない）
- 数字とグラフは、わたしのことだけ（決定 2026-10-07）。拾ったことば・夜空は、30秒でぱっと見て感じる景色のまま。じっくり読みたいときだけ、わたしのことを開く
- **わたしのことで見せること**（4つ。決定 2026-10-07、ユーザー「機能はかぶりたくないからこれだけでいいかも」）。拾ったことば・夜空と同じこと（よく感じる言葉・本音・テーマ）は、ここでは見せない

| 項目 | 例 | もとになる分析 |
|---|---|---|
| 元気・好奇心の源 | 散歩・計画を立てる → わくわく | 流れ：入次数（元気・好奇心の言葉へ向かう矢印が、どこから多く来るか） |
| 行き着きやすい気持ち | ほっとした | 流れ：PageRank |
| くり返すめぐり | 疲れ ⇄ 不安 | 流れ：強連結成分分解（良い・悪いは言わない） |
| 育っていること | 先月より「やってみたい」が増えた。下に育ちのグラフ（案） | 時間の変化（週ごと・月ごと） |

- 見せ方：上に短いことば、下に数字とグラフ（決定 2026-10-07）。疲れている日は上だけ読めばよい
- 元気に近い気持ちの言葉（11語、決定 2026-10-07）：わくわく・ときめき・喜び・うれしい・高揚感・満足・穏やか・ほっとした・解放感・スッキリ・軽い。好奇心の言葉も「元気・好奇心の源」の行き先に入れる（案）
- **データが少ない間**（決定 2026-10-07）：短い文だけを出す（例：「元気な日が、あと少し集まると見えてきます」）
  - 期間は、使い始めて2週間、または元気な気持ちの日が5日たまるまで
  - 数字とグラフは出さない。少ない数で出すと、たまたまでも決めつけに見えるため
  - 流れ（矢印）は、毎日くらい拾って1か月ほどで見え始める（案）
- **6つ目の種類「していること」は MVP に入れる**（決定 2026-10-07）。これがないと「何で」元気になるかに届かない
- 名前：3つ目は「夜空」、4つ目は「わたしのこと」（決定 2026-10-07。前は夜空を「ふりかえり」と呼んでいた）
- **作る順番**（決定 2026-10-07）：保存（ログインなし・端末ごとの仮のID）→ 3画面を本物の記録につなぐ（夜空は、つながりの強さと検定で作り直す。2026-10-09 に作った）→ わたしのこと
- **島は残しておく**：今の3Dの島（v10）はアプリに残し、使い道はあとで考える
- 詳しい計算は第2部 C3.

## 気づきの日記（MVP とは別の機能。決定 2026-10-07）

わたしのことで好奇心の源に気づいたあと、自分で試したことを、日記として残せる。
川とは仕組みの上で独立していて、本人の気づきでだけつながる。
（ユーザー「気づいた後の行動は、あくまで日記として、メモを残し、個人的に育てたら、スタンプ押していくだけ」「あくまで、MVPとは別の機能だし、河にも影響を受けないし、与えない」）

- **5つ目の画面にする**（決定 2026-10-07。ユーザーが3案から選んだ）。MVP の4画面はそのままで、MVP のあとに足す。見た目・ほかの画面からの行き方は、作るときに見せて決める
- **できること**：わたしのことの「元気・好奇心の源」の言葉に、「やってみた」のスタンプを押せる。書きたい日だけ、一言メモを付けられる
- **見え方**：押したスタンプとメモが、日記として並ぶだけ
- **出さないもの**：スタンプの数・連続日数・点数・催促の知らせ（4. の「がんばらせない」）。メモは必須にしない（文字を打たなくても使える）
- **川との関係**（決定 2026-10-07、ユーザー「この方針でいこう」）
  - 仕組みの上では独立：日記は川の言葉を増やさない・かたよらせない。川の記録も日記を書き換えない
  - つながるのは本人の気づきだけ：気づく → 試す・日記に残す → 興味が少し変わる → 川で選ぶ言葉が変わる → また気づいて、日記を更新できる
  - よい所：拾った言葉は本人の今の気持ちのまま（わたしのことの分析も信じられる）。アプリが押しつけない。気づきが本人のものになる
- **アプリは「日記のおかげで変わった」とは言わない**（決定 2026-10-07）。変化が日記によるものか、季節や仕事など別の理由か、アプリには見分けられない。言えば決めつけになり、日記がノルマにもなる。日記と「育っていること」を見比べて気づくのは本人
- **「ひとこと日記」（10. の案）とは別のもの**：ひとこと日記は、書いた文から言葉を取り出して「自分の言葉の泡」として川に流す案。気づきの日記のメモは、川に流さない・言葉を取り出さない
- 採らなかった案：気づいた言葉を川に多めに流して、拾うと育つ形。川をかたよらせ、「よく拾う＝関心」が崩れるため（第2部 D. の「川が決めてしまうこと」）
- 作る量（案）：わたしのことに押すボタンと、日記の画面。保存は「どの言葉に・いつ・メモ」の小さな表が1つ増える（第2部 G.）

## 5. 画面は4つ（決定 2026-10-05。MVP では島の代わりに「わたしのこと」。上の「MVP」）

夕方の川 → ブルーアワーの空 → 夜空 → 朝の島、と1日がめぐるように画面がつながる。
画面は切り替わらず、時間が進む動画でつながる。
どの画面からも、行きたい画面へすぐ飛べる（決定 2026-10-06。第2部 F. の「すぐ飛べる印」）。
（ユーザーの選択：島は「4つ目の画面として足す」。星空の次は、島を育てていく）

| 画面 | 時間 | ここで何をするか | 見え方 |
|---|---|---|---|
| **ことばの川** | 夕方 | 流れてくる言葉の泡を、ピンときたら拾う | 露天風呂から眺める夕方の渓流。泡はガラス玉のよう |
| **拾ったことば** | ブルーアワー | 最近拾った言葉を眺める | 夕焼けが少し残る空に、言葉がキラキラ浮かぶ（まだ星になる前の言葉） |
| **夜空** | 夜 | 言葉のつながりを、星座として眺める | 満天の星。拾った言葉が星になり、金色の細い線で星座になる |
| **わたしのこと**（MVP） | ー | 言葉の流れ（何のあとに元気・好奇心が来るか）と、育っていることを読む。集大成 | 上に短いことば、下に数字とグラフ（第2部 C3.） |
| **島**（MVP のあと） | 朝 | 自分の島が育つのを眺める | 海に浮かぶ島。夜空の星が種になって降り、芽・花・木に育つ。遠くに川の河口が見える |

**4つの画面は分けたまま**（決定 2026-10-05。MVP では、拾ったことば＝集計、夜空＝無向ネットワーク、わたしのこと＝有向ネットワークと集大成。決定 2026-10-07）：拾ったことば＝どの言葉が多いか・強いか、夜空＝つながり、島＝流れ。役割が別々で、1日の時間のめぐりも保てる

**見る時間の長さでも分ける**（決定 2026-10-06、ユーザーの「4画面、機能を区別できてるかな」から）
- 見せ方だけで分けると、島が回数（大きさ）・つながり（花畑）・流れ（小川）を全部見せていて、ほかの画面と重なる。小川はデータが数か月たまるまで出ないので、最初のころの島はほかの2画面の言い換えになる
- そこで、画面ごとに見る時間の長さを変える

| 画面 | 見る時間の長さ | 答える問い |
|---|---|---|
| 拾ったことば | 最近（今日〜今週） | このごろ、何を拾ってる？ |
| 夜空 | 6週間（決定 2026-10-09。前は「ひと月くらい」） | 何と何が、いつも一緒？ |
| 島 | 直近12か月（決定 2026-10-06） | この1年、何から何へ流れ、何が育ってきた？ |

- 島の大きさ（回数）は「この1年の積み重ね」の意味になる。夜空は線、島は水の流れ、と見せ方も分ける
- **島は1つだけで、直近12か月を見せる**（決定 2026-10-06。ユーザー「発展していくといろんなデザイン考えなくていけなくるし、ゲームっぽくなるよね」）
  - 理由：島を年ごとに増やす・広げる・作り足すと、育てる遊びが主役になり、「がんばらせない」とぶつかる。景色のデザインも増え続ける。島は気づくための鏡で、遊ぶ場所ではない
  - 12か月より前の言葉は、島から静かに消えていく（枯れるのではなく、季節が過ぎるように）。島はいつも同じくらいの賑わいで、混みあわない
  - 季節がひとめぐり入るので、小川（日をまたいだ順番）に要るデータは十分たまる
  - 昔の自分とは、川を流れてくる「過去の自分の泡」（7. の軸）で出会う。過去を見せる役は川に任せる
- 期間の切り替え（今週・今月・今年・すべて）は、なくした（2026-10-09）。拾ったことば＝直近7日、夜空＝直近6週間で決まっている（第2部 B.・C.）

**夜空と島の違い**（決定 2026-10-05）
- **夜空は「つながり」**：同じ日に一緒に拾った言葉を、星座の線で見せる
- **島は「流れ」**：時間の中で、言葉がどこから来て、どこへ行くかを、小川・池・渦で見せる。島に住む動物が、一行の日記を話してくれる

**水の2つの道**（決定 2026-10-05）
- **拾った言葉は、空を通る**：星になる（夜空）→ 種になって島に降る → 小川のほとりで植物に育つ
- **拾わなかった言葉は、川を通る**：川を下る → 海へ流れ込む → 島を囲む静かな海になる
- 島は、拾った言葉だけでできている。流した言葉は、島の植物にも小川にもならない
- 流した言葉もなくならず、島を囲む海になる（4. の「言葉にしない自由」と合う）
- 島の水は空から来る（雨・朝露）。奥の丘にしみこみ、湧き水になって小川が流れ出す（決定 2026-10-06）。川の水は島の中には入らない
- 星は種になる。水にはならない。植物も水を出さない（決定 2026-10-06。「根もとから水が湧く」は、自然に見えないのでやめた）
- 島から川へは、海に流れ込む川をさかのぼって戻る（第2部 F.）

### 島に流れる小川（景色で見せること・矢印の作り方・変わる速さは決定 2026-10-05）

言葉から言葉への流れ（「この言葉のあと、よくこの言葉が来る」）を、島の中を流れる小川で見せる。
**植物（言葉）は、小川のほとりに、拾う順番どおり上流から下流へ並んで咲く**（決定 2026-10-06）。
ワクワクの源は、ワクワクの木へ流れ込む小川の上流に咲く花として見える。図や数字は出さない。

**小川の意味**（決定 2026-10-06。ユーザーと図で確かめた）
- 小川の水は、空から降った雨や朝露（上の「水の2つの道」）。言葉そのものは水にならない
- **先に来る言葉ほど上流（高い奥）、あとに来る言葉ほど下流（低い手前）**に咲く。水はいつも坂を下る
  - 例：「旅行の計画」を拾った次の日に「わくわく」、が何度もある → 計画の花が、ワクワクの木へ流れ込む小川の上流に咲く
  - 見た人は「ワクワクの木に流れこむ小川の上には、いつも計画の花が咲いてる」と気づく
- ワクワクの木は真ん中。根もとの淵に、いろいろな上流からの小川が集まる
- 木より下流には、わくわくの**あとに**よく来る言葉が咲く
- **池そのものは言葉ではない**。池のほとりに、流れをたどると最後に行き着きやすい言葉が咲く（2026-10-06、ユーザー「言葉はそのほとりに咲く」）
- **水は実際に流れて見える**（決定 2026-10-06、ユーザー「実際流れるようにしたい」）。水面の明るい筋が、上流から下流へゆっくり動く
  - 流れも Blender で作る（決定 2026-10-06、ユーザー「完全にblenderで作ってほしい」）。波の筋を少しずつ下流へずらした16コマを Blender で焼き、アプリはコマを切り替えるだけ
  - 島を見ている間は1秒に10回だけ描き直す（電池の減りを小さくするため）

| 見せたいもの | 使う計算（第2部 D.） | 島での見え方 |
|---|---|---|
| 時間の流れ（言葉から言葉へ） | 有向グラフ：つながりに向き（矢印）がある網の目 | 小川のほとりに、上流から下流へ順番に植物が並ぶ（決定 2026-10-06）。よく通る流れほど小川が太い（案） |
| ワクワクの源 | ハブへの入次数：たくさんの線が集まる言葉（ハブ）に、どの言葉から矢印が来るか | ワクワクの木の淵へ流れ込む小川と、その上流に咲く花。「計画 → ワクワク」が見える |

| ワクワクを邪魔しているかもしれない流れ（くり返すめぐり） | 強連結成分分解：矢印でお互いに行き来できる輪を見つける計算 | 水がぐるぐる回る渦や、霧のかかる所。言葉では注意しない |

- 小川の向きは「この言葉のあとに、よくこの言葉が来る」だけ。原因と結果ではない
- 渦や霧は、良い・悪いを言わない。注意もしない。気づくのはユーザー（4. の「助言しない」）
- 小川を作るには、言葉の順番（矢印）が要る。でも、**同じ回の中で拾う順番は使わない**。川に流れてきた順番で、偶然だから（第2部 D.）

**矢印の作り方**（決定 2026-10-05。ユーザーは「両方」を選んだ）
1. **ふだんは、日をまたいだ順番**：ある日に拾った言葉から、**3日以内**に拾った言葉へ矢印を引く。近い日ほど強く数える（次の日がいちばん強い）
2. **一行の文章を残した日は、その文の流れも足す**：例：「計画していたらワクワクした」→ 計画 → ワクワク（10. の一行）
   - 直さずに残した AI の一行も使う。ただし、直した文・自分で書いた文より弱く数える（決定 2026-10-05）。AI の考えた流れが入るため
- 毎日拾う言葉（「疲れ」など）からは、どの言葉へも矢印が出る。偶然でも起きる回数より、はっきり多い流れだけを小川にする

**変わる速さ**（決定 2026-10-05）
- 小川の水の量や太さは、**毎日少しずつ**変わる（見に行く楽しみ）
- 新しい小川ができる・消えるのは、**月に1回くらい**（落ち着く）
- 変わったことは知らせない。そっと変える。島の動物に触れると「新しい小川ができたみたい」と話す（決定 2026-10-05）

**ストレスになりそうな言葉**（決定 2026-10-05）
- 「不安」「疲れ」などは、嫌なもの・汚いものにしない。**自然の一部として**見せる
- 例：朝に出て、昼には晴れる霧。休める木陰。降ったあとに植物が育つ雨雲
- 理由：拾うと島が汚くなるなら、正直に拾えなくなる。「良い・悪いを言わない」（4.）とも合う
- **出す所は、ぐるぐる回る流れ（渦）の所**（決定 2026-10-05）。「この言葉はストレス」とアプリが決めない。どの言葉でも、くり返すめぐりがあれば朝の霧がかかる

**最初のころ**（決定 2026-10-05）
- データが少ない間は、小川は出さない
- 代わりに、**小さな水たまりや湧き水**が少しずつ現れる。これから流れが生まれる知らせ
- ワクワクの源は、木のそばに咲く花（同じ日に一緒に拾う。順番なし）で見せる

## 6. 使っているうちに起きること（体験の流れ）

最初は触るのが気持ちいいだけ。続けるうちに、島に自分だけの庭が育ってくる。

|---|---|

## 7. 何十年も使われ、広がるための考え（案。2026-10-05）

ユーザーの願い：「本当にみんなが使いたくなる、画期的でバズる、何十年もみんなが使い続けるアプリ」。
長く使われるものは「ためるほど大事になる」「くり返す時間に結びつく」「がんばらなくていい」。
バズるものは「一言で言える新しさ」「3秒で伝わる気持ちよさ」「人に送りたくなる仕組み」を持つ。
この2つを、3つの層に分けて考える。どれも「大事にすること」を守る。

### ひとことで言える新しさ

- **「書かない日記」**。日記は続かない。でも、言葉を拾うだけなら続く。拾った言葉が、星になり、島になり、一行の日記になる
- 「日記アプリ」でも「性格診断」でもない、新しい置き場所。人に説明するときの一言になる

| ~~年ごとの島が諸島になる~~（見送り 2026-10-06） | 島を増やすと、育てる遊び（ゲーム）が主役になり、景色のデザインも増え続ける（ユーザー「発展していくといろんなデザイン考えなくていけなくるし、ゲームっぽくなるよね」）。島は1つで「直近12か月」にした（5.） | — |

| **ずっと自分のもの** | 島と言葉をいつでも書き出せる。アプリがなくなっても残る | 何十年も預けるには、この安心が要る |

### 軸にする案（決定 2026-10-05）

- **過去の自分から流れてくる泡**を、pukapuka の軸にする（ユーザーが「いちばんワクワクする」と選んだ）
- 続けるほど過去の自分と出会えるので、何十年も使うほど大事になる。「書かない日記」とも合う（読み返さなくても、過去の言葉のほうから流れてくる）
- ほかの案は、この軸を引き立てる形で足していく
- 「去年の今ごろ」だけだと、使い始めて1年は一度も出てこないため、**少し前の自分から始めて、だんだん遠くなる**（決定 2026-10-05）
  - 最初の数週間は数日前の言葉、1か月たつと先月の言葉、季節が変わると前の季節の言葉、1年たつと去年の今ごろの言葉
  - 続けるほど、遠い過去の自分から泡が届くようになる。何年も続けた人だけが、何年も前の自分と出会える
  - 古びた色の濃さで、どれくらい前の泡かが分かる（数字は出さない）

### いちばん強い組み合わせ（私の考え）

1. **「書かない日記」と触る気持ちよさ**で、始めてもらう
2. **ことばの種を贈る**で、人から人へ広がる

## 10. 全体の流れ（設計図。案 2026-10-05）

言葉が入ってから景色になるまでの流れ。4つの段がある。
ユーザーが気に入った流れ「日記入力 → AI抽出 → NetworkX分析 → 画面表示」を、pukapuka の決まりに合わせた形。
文字を打たなくても日記が残る。ただし、AI の書いたものを残すかどうかは、いつもユーザーが選ぶ。

| 段 | すること | ユーザーに見えるか |
|---|---|---|
| ① 入れる | 川で言葉を拾う（いつもの入口。文字なし） | 見える |
| ② 一行にする | 拾った言葉から、AI が短い一行の下書きを書く（メインの入口）。自分で書きたい日は、ひとこと日記も書ける（おまけ） | 見える（選ぶ・直すだけ） |
| ③ つながりを読む | 拾った言葉どうしのつながりを裏で計算する（どの言葉がよく一緒か、など） | 見えない |
| ④ 景色にする | 計算の結果で、星座の線や島の植え方・育ち方・小川を決める | 景色だけが見える（わたしのこと だけは、ことばと数字で見える。決定 2026-10-07） |

- **日記は必須にしない**。pukapuka は「書くのが負担で続かない」人のためのアプリなので、書かない日も今までどおり川だけで使える

### ② AI の一行の下書き（2026-10-05 ユーザーの思いつき「言葉から、AI が日記を書いてくれる・提案してくれる」）

- 拾った言葉を使って、AI が短い一行（詩のような日記）を書く
  - 例：拾った言葉「帰り道・疲れ・気になる」→「疲れた帰り道、それでも何かが気になった夜」
- **気持ちを言い当てない**。「今日のあなたは不安だった」のような診断は書かない。拾った言葉で遊ぶ一行にする
- 下書きは「残す・直す・捨てる」を選ぶ（何もしなければ残らない）
- 言葉にしたくない言葉は、一行に使わないよう選べる（「そっとしておく」）。そっとしておいた言葉も、星や島にはなる
  - 選び方（決定 2026-10-05）：「この言葉はいつもそっとしておく」と「今日はそっとしておく」の両方を選べる
- **直すと、自分の言葉になる**：「旅行」を「旅行の計画」に直したら、それが自分の言葉になる
- 出す場所：**島に住む動物が、さりげなく話してくれる**（2026-10-05 ユーザーの思いつき「島に住んでいる動物みたいのが、さりげなく、日記のようにまとめて、話してくれたらいいね」）
  - 動物は、拾った言葉を日記のように一行にまとめて話す。例：「きのうは疲れた帰り道に、何かが気になったんだね」
  - 話すのは、ユーザーが近づいて触れたときだけ（決定 2026-10-05）。どんな動物かは静止画で見比べて決める（決定）
  - 動物も、気持ちを言い当てない・助言しない（4.）。拾った言葉で話すだけ
  - 動物の一行も下書き。残す・直す・捨てるはユーザーが選ぶ（4. の「選ぶのはユーザー」）
  - 話し方は、やさしく素朴なひとりごと（決定 2026-10-05）。話しかけすぎず、日記を読むように。例：「きのうは、疲れた帰り道に何かが気になったんだね」
  - 名前を付けられる。付けなくてもよい（決定 2026-10-05）。文字を打つのはここだけで、必須にしない
  - 前の案：夜空（1日の終わりに、一行が星座のそばに浮かぶ）

### 自分の言葉の泡

- 一行を直して生まれた言葉や、ひとこと日記から取り出した言葉は、「自分の言葉の泡」として川に流れてくる。拾うと、ほかの言葉と同じく星になり、島の種になる
  - 例：「旅行の計画」が泡になって流れてくる → 拾う → 島に植わる。決まった言葉では届かない、細かいワクワクの源に気づける
  - 拾う手ざわり（川で拾う）はそのまま残る。日記の言葉も、流れてきたときにピンときたら拾うもの
- AI は勝手に記録しない。取り出した言葉・下書きを見せて、ユーザーが選ぶ（「これはちがう」を消せる。4. の「選ぶのはユーザー」）
- ③の計算は、アプリでは TypeScript（第2部 D.。NetworkX は使わない。決定 2026-10-07）。画面に「分析」という言葉は出さない。結果を見せるのは、わたしのことだけ（決定 2026-10-07）
- 注意
  - 拾った言葉や日記の文章を AI に送ることになる。何を送るか・保存するかを、はっきり伝える。「そっとしておく」言葉は送らない
  - 動物の一行のために送るのは、**その日に拾った言葉と強さだけ**（決定 2026-10-05）。名前・過去の記録は送らない。AI の会社に残さない設定にする
  - 伝えるのは、**初めて動物に触れたときに1回**（決定 2026-10-05）。短い説明と「話してもらう／やめておく」を選ぶ。あとから設定で変えられる
  - 自分の言葉の泡は、ほかの言葉より拾われやすい。かたよりを分けて考えるため、「どの言葉が何回流れたか」を記録する（第2部 D.）
  - AI を使うたびにお金がかかる（1日に何回まで、などを決める）

# 第2部 作りの詳細

## A. ことばの川

言葉の泡が川の奥から流れ、触れて離すと拾える。押した長さが気持ちの強さになる。

### 流れ方（2026-10-04〜05 決定。数値は `src/riverFlow.ts`・`src/app/index.tsx`）

- 泡は Blender で作った川の中心線に沿って、奥から手前へ流れる
- 速さは手前で 32px/秒。奥でも9割の速さ（遠さは泡の大きさで表す）
- 横の位置は5列。川幅いっぱいに散らす
- 泡は川の奥〜中ほど（川筋の最初の350px）の水面から、1.2秒かけて浮かび上がる
- 泡どうしの間隔は、泡の大きさの1.18倍
- **泡が減ったら補う**：流れている泡が13個より少ないと、空いている水面のどこからでも泡を出す
  - 2026-10-04、ユーザー「続けて押すと泡が一気になくなってさみしい」
- **泡は最大15個**：縦に長い画面で泡が増えすぎ、奥で詰まったため（2026-10-04、ユーザーの実機で「流れずに詰まる」）
- 結果（計算で確かめた）：見える泡は iPhone SE で約11個。8個続けて拾っても約8個残り、1秒以内に戻る
- **長押し中はゆっくり**：泡を押さえている間、ほかの泡は 0.12倍の速さ（止めない。2026-10-04、ユーザー「慌てるといやだから、かなりゆっくり」）
- 起動したときは、30秒流した状態から始める（開いた瞬間から川に泡がある）

### 拾い方と強さ

- 触れて離すと拾う。泡は1.4秒かけて空へ昇って消える
- 強さ：0.2秒未満で離せば 0.1（最小）。それより長ければ「押した秒数 ÷ 2」（2秒で1.0）
- チャージリング：泡のまわりの輪が、押すほど満ちる（ゴールド → オレンジ）
- **光の粒**（2026-10-04、ユーザー「長押しのゲージが指で隠れる」）
  - 泡の上、タッチした所から約60px（約9mm）以上上に5つ並ぶ
  - 0・0.4・0.8・1.2・1.6秒で1つずつ灯る。拾う音の5つの高さと同じ段
  - 1段上がるたびに軽い振動。5段目だけ少し強め
  - リングと粒は、押して0.15秒たってから出す（さっと触れるだけのときは出さない。スマホで軽くするため）
- 画面下に「「〇〇」を拾った」が1.8秒出る

### 言葉

- 103語。5つの種類（気持ち・体の感じ・場面・したいこと・好奇心）。`src/words.ts`（今の作り）
- 6つ目の種類「していること」を足す（決定 2026-10-06）。新しい24語と、場面から移す「趣味」「勉強」で26語。全部で127語、場面は22語になる
  - 手を動かす：料理・作る・絵を描く・書く・写真・片づけ・植物を育てる
  - 体を動かす：散歩・運動・外に出る・お風呂
  - 受け取る：読書・音楽・映画・ゲーム・調べもの
  - 人と：人と話す・誰かを手伝う・一緒に食べる
  - 先のこと：計画を立てる・旅・新しい場所・買い物・カフェ
  - 毎日のふつうのこと（お風呂・片づけ）も入れる。ワクワクの源は、意外とふつうの所にあるから
  - 作るときに要るもの：新しい色を1つ（拾ったことば・夜空・島）、島の植物の形を1つ（案：実のなる低木）、拾ったことばの色の説明
- 今は全部から均等にランダムに流す。同じ言葉が続けて・同時に流れないようにする
- 将来、AI の一行を直して生まれた言葉や、ひとこと日記から取り出した「自分の言葉」も流す（案。第1部の10.）。自分の言葉は見た目を少し変える
- 流す言葉をかたよらせると、「よく拾う＝関心がある」が崩れる（D. の「川が決めてしまうこと」）。自分の言葉を流すときは、流れた回数も記録する

## B. 拾ったことば

拾った言葉を、大きさ（回数）とキラキラ（強さ）と色（種類）で見せる。

### 見せ方（2026-10-04 決定）

- **実際に拾った言葉だけ**を、言葉のまま出す（まとめたり名前を付けたりしない）
- 文字の大きさ＝拾った回数
- 文字の色＝言葉の種類（今は5色。「していること」の色を足して6色にする。決定 2026-10-06）
- **同じ色（種類）の言葉は、近くに集まる**（決定 2026-10-09。ユーザー「色わけしてるんなら、色わけごとにわけたほうがよくない」「Bがいい」）
  - 画面を3段×2列の6つの区画に分ける（左上から、感情・身体感覚／状況・場面・価値観・欲求／好奇心・していること）。区画の大きさは、言葉の量に合わせて決める。言葉は、自分の種類の区画の中だけに置く（区画のあいだは8px空ける。線は引かない）
  - 位置は、種類の目安。くわしい意味は持たせない。これで、「何を感じているか」の偏りが、ひと目で見える
  - 試して比べた：A＝まぜて散らばる（前の配置）、C＝半分だけ寄せる、B＝はっきりまとめる。Bに決めた。中心から広げるだけだと、色がまざったので、区画の中だけに置く形にした（ユーザー「ちゃんとわかれていない気がする」「これでいい」）
  - 区画に入りきらないと文字が縮む（小さいスマホで、30語のとき約56%）
- 文字のキラキラ＋まわりの光の広さ＝気持ちの強さ（1回あたりの平均）
  - まわりの光は強さだけで決め、文字の大きさに合わせない（回数と混ざらないように）
- 回数と強さを1つの数字にまとめない。2つの見え方の組み合わせから気づきが生まれる

| 見え方 | 意味かもしれないこと（決めつけない） |
|---|---|
| 大きくてキラキラしない | いつもの感覚・口ぐせ |
| 小さくて強くキラキラする | 本音かもしれない |
| 大きくて強くキラキラする | 真ん中にある関心ごと |
| 小さくてキラキラしない | まだ薄い気持ち |

経緯：文字の濃さ → 後ろの光の円 → 言葉のまわりの星、と試し、「文字そのものがキラキラする度合いで強さ」に決めた（ユーザー指定）。

### 計算（仮の値。実機を見て調整する。`src/wordCloud.ts`）

```
文字の大きさ(px) = 16 + 回数 × 2                    （上限 40）
k               = (強さの平均 - 0.25) / 0.75         （0〜1。0.25以下はキラキラしない）
光る写しの濃さ   = 0.35 + 0.65 × k
光のにじみ(px)   = 3 + 13 × k
まわりの光の半径 = 16 + 40 × k (px)
まわりの光の濃さ = 0.7 × k       （場面の青だけ ×0.75。青は強く光って見える）
またたき         = 2.4秒周期。3グループに分けて時間をずらす
文字の濃さ       = 0.78 + 0.22 × 強さの平均
```

### 画面の決まり

- 期間：**直近7日**（決定 2026-10-06「最近（今日〜今週）」。期間の切り替えは、なくした 2026-10-09）。平日と週末が1回ずつ入る
- **言葉は30語まで**（仮。2026-10-09）。言葉が多いと、文字が縮み、入りきらずに消えるため（小さいスマホで、50語で56%、80語で13語が消えた）
  - 選び方：回数の多い言葉（口ぐせ）20語 ＋ 残りから強く押した言葉（本音かも）10語
  - 1回だけ強く押した言葉（本音かも）を残すため、「2回以上だけ」にはしない
- 言葉に触れると、夜空のその星を真ん中にして開く
- 画面下のヒント「文字の大きさ＝拾った回数　キラキラ・光＝気持ちの強さ」と色の凡例（今は常に出している）

## C. 夜空

拾った言葉を星に、よく一緒に拾う言葉を線にして、星座を描く。

### 夜空の作り方（決定 2026-10-09。`src/constellation.ts`・`src/communities.ts`）

直近6週間の記録から、「偶然では起きにくい、いっしょに拾った言葉」だけを線にして、星座を描く。色・文字・数字は出さない。
グループ（まとまり）は、線と位置だけで見える。

- 星＝拾った言葉。星の大きさ＝拾った回数
- **線を引く条件**（ユーザー「検定は入れたい」）
  1. いっしょに拾った日が2日以上ある組（1日に何回拾っても、1日と数える）
  2. 「偶然だけで、これ以上いっしょになる確率」が5%未満（検定。下に説明）
- **線の太さ・濃さ・星どうしの引き合う力は、つながりの強さ**（ユーザー「太さがつながりの強さでしょ」）
  - 太さ・濃さは、「いま画面に出ている線の中での強さ」で決める（ユーザー「線の太さに違いが判らない」。出る線の強さは0.5〜0.8に集まり、0〜1のままだと、太さの差が約0.5pxしかなかった。2026-10-09）。同じ強さの線でも、別の日の夜空では、太さが変わることがある
  - つながりの強さ＝いっしょの日数 ÷ √（Aの日数 × Bの日数）。0〜1の数。コサイン類似度という名前の計算
  - 毎日拾う言葉は、だれとでも同じ日になりやすい。この計算で割り引くと、そういう言葉の線が太くならない
- **グループ分け**：強さを足し合わせる「ラベル伝播」で、言葉ごとに「まとまり」を決める（C2. の島と同じ計算）
  - 言葉ごとに、つながる相手のまとまりを見て、強さの合計がいちばん大きいまとまりに入る。誰も変わらなくなるまでくり返す
  - **別のまとまりをつなぐ線は、うすい点線で残す。星は引き寄せない**（位置は、同じまとまりの線だけで決める）。意外なつながりに気づけるように（ユーザー「④がいいかも」）
  - 色や文字でまとまりは示さない（ユーザー「星のイメージがあるから色なしがいい」。まとまりに名前をつけると、決めつけになる）
  - 画面の言葉では、同じまとまりの星を**「星座」**と呼ぶ（実線でつながった星の集まり。ユーザー「星座は同じグループ」）。「まとまり」「グループ」「かたまり」は、使う人に分かりにくいので、画面には出さない。星座1つ1つに名前はつけない
- 置き方：線でつながる星どうしが引き合い、ほかは離れ合うように動かして決める（力指向配置）
- **上限**：星は最大26個、線は最大38本、1つの星から最大5本。強い線から順に選ぶ（仮。6週間で、前の22・34では足りなくなったため）。ごちゃごちゃを防ぐ最後の歯止め
  - 記録が多い人は、上限で弱い線が消える（ダミーで、記録が2倍だと、上限なしで線93本）
- 期間：直近6週間（42日）。平日と週末が同じ数入る。切り替えはない
- 線のない星は出さない（拾ったことばから飛んできた言葉だけは出す）。1回だけ拾った言葉や、相手のいない言葉は、夜空には出ない（拾ったことばには出る）
- 星に触れると、つながる星と線だけ明るく残る。もう一度触れる・空に触れると戻る。点線がある星に触れたときは、「「散歩」は、「お風呂」とも、小さくつながっています」と一言そえる（決定 2026-10-09。相手は強い順に2つまで）
  - 点線の言い方の経緯：「ちがう星座の」→「はなれた星の」→「小さなつながり」。星座の境目は計算が決めたもので、「ちがう星座なのに、つながっている」が引っかかり、「はなれた星」は見た目だけで意味が伝わらないため。点線は、星座をまたぐ線で、ほとんどは弱いつながり（ダミー60人で、またぐ線の90%が、星座の中の線の真ん中より弱い。平均0.54と0.63。星座の中のどの線より強い点線は0%）。ユーザー「小さなつながりとして伝えたい」
- 星は3グループに分けて、3.2秒周期でゆっくりまたたく
- **夜空の見かた**（決定 2026-10-09。ユーザー「それで」。線と星座の意味が、使う人に分からないかもしれないため）
  - 初めて夜空を開いたとき、短い案内を1回だけ出す。右上の「？」で、いつでも、もう一度見られる（見たかどうかは、端末に覚える）
  - 星：あなたが拾った言葉。大きいほど、よく拾った／線：いっしょによく拾った言葉を、つないでいる。太いほど、よくいっしょだった／星座：線でつながった星の集まり。いっしょに出やすい言葉たち／点線：小さなつながり
  - 最後に「どんな言葉が、いっしょに出てくるか、ながめてみてください。」と、ヒントだけ出す。何に気づくかは決めつけない。数字や「分析」という言葉は使わない
- **使い始め（星が1つも出ない間）**（決定 2026-10-09。ユーザー「日にちがたまらない間は、こんな感じになりますと、ダミーを表示したらユーザーがわかりやすいのでは？ 点線の意味も」）
  - 「もう少し拾うと見えてきます」の下に、「見本を見る」ボタンを出す。押すと、ダミーの人の夜空（6週間ぶん。`src/demoPersona.ts`）を出す
  - 見本の画面には、「見本（ダミーの人の夜空です。あなたの記録ではありません）」と、凡例「点線は、小さなつながり」を出す。「見本をとじる」で戻る
  - 自動では出さない。自分の記録と間違えないように、ボタンで見る形にした
  - 自分の記録の夜空には、見本は出さない

```
星の芯の半径(px)  1.4 + 0.35 × 回数          （上限 5）
星の名前(px)      9.5 + 0.25 × 回数          （上限 13）
線の太さ(px)      0.5 + 3.1 × 相対の強さ     （またぐ線は ×0.7）
線の濃さ          0.2 + 0.55 × 相対の強さ    （またぐ線は ×0.6。点線 3px・4px）
引き合う力の重み  0.6 + 0.4 × 強さ
相対の強さ        いま出ている線の中での強さ（弱い線＝0、強い線＝1）。強さの幅が0.25より小さいときは、差を大きく見せすぎない
星どうしの間隔    線でつながる星は 64px。入りきらないときだけ全体を縮める
```

**「偶然との比較」（検定）とは**（フィッシャーの正確確率検定の片側。超幾何分布という数え方）
- 全体の日数のうち、Aを拾った日と、Bを拾った日を、でたらめに選んだとする。何日重なるかは、選び方の数を数えると分かる
- 実際の重なりが、でたらめなら5%未満でしか起きないとき、「偶然ではなさそう」として線にする
- 全体の日数は、記録のある日の数
- 必要な重なりは、言葉の日数で変わる（毎日拾う言葉どうしは、多く重ならないと線にならない）
- 「偶然より多く重なる」側だけを見る（いっしょに出にくい組は、線にしない）
- 使い始めは日数が少ないので、線が出にくい。2つの言葉を2日ずつ拾って、2日とも同じでも、5%を切るのは記録のある日が7日以上のとき（1%なら15日以上）

**試して分かったこと（ダミーの人・ランダムな記録。数字は仮）**
- 意味のないランダムな記録（30日）で、検定なしだと線が約34本。5%で約9本、1%で約1.3本
- **拾う量が日によって大きくばらつくと、偽の線が増える**（1%でも約19本）。検定が「どの日も同じくらい拾う」と考えているため。これは未解決の弱点
- 「強さ0.3以上」と「お互いの強い上位3人まで」は使わない。0.3は、上位3人があると結果が変わらなかった。上位3人は線が減って星座らしくなるが、意外なつながりが消える。ごちゃごちゃが気になったら足す案
- 期間を6週間にすると、4週間より、意外なつながりが見つかりやすい（ダミー）。8週間では上限に当たりやすい
- ダミーの人は、想像で作ったもの。本物の記録では、まだ確かめていない
- 使い始めの1〜2週間は、星がほとんど出ない。2週間で小さなまとまり、4〜6週間でまとまりがはっきりする（ダミー）

**開発用：ダミーの人**
- web で `?demo=1` をつけて開くと、ダミーの人（`convex/demo.ts` の `seedDemo`。60日ぶん）の記録で動く。この間は保存しない
- 数週間待たずに、夜空の見え方を確かめるため。本物の記録とは、端末の目印が別

### 見直すこと（2026-10-05 の「分析されている感じを出さない」と合っていない所）

- **画面下の回数をやめた**（決定・反映済み 2026-10-05）：前は「「不安」 10回　同じ日に拾った言葉 5」と出ていた
  - 星を選んだとき：「「不安」とよく一緒の星が、光っています」（つながる星がないときは「「不安」のまわりは、もう少し拾うと見えてきます」）
  - ふだん：「大きな星ほど、よく拾った言葉　太い線ほど、よく一緒に拾った言葉」（2026-10-09 に「太い線ほど」を足した。線の太さの意味が伝わるように）
- 星に触れたときの詳細（拾った日を並べた線・曜日や時間帯のかたより）は、グラフにせず景色で見せられる形が見つかるまで作らない

## C2. 島（朝）（案。MVP のあと）

拾った言葉から島の景色を作る。新しいデータは要らず、拾った記録から毎回作り直せる。
島はアプリの中の3Dで試作している（2026-10-05）。

- 島の植物は、拾った記録（言葉・強さ・時刻）だけから決める
  - 植物の大きさ＝その言葉を拾った回数。花の色づき＝強さの平均
  - 植える場所＝よく一緒に拾う言葉のグループ（D.）
  - 小川ができてからは、拾う順番で上流（奥）から下流（手前）へも並べる（決定 2026-10-06。並べ方は D. の「小川の形の作り方」）
  - 言葉の種類（6つ）ごとに植物の種類を変える。「していること」は新しい形（案：実のなる低木）。ワクワクの木のそばに何が咲いているかを見分けやすく
  - ワクワクの木は島に1本（決定 2026-10-05）。好奇心の言葉と、わくわくに近い気持ちの言葉（わくわく・ときめき・喜び など）が、この木に集まる。どの言葉を入れるかは、`src/words.ts` の決まった言葉から選んで一覧にする
  - **1日目から若木で立っている**（決定 2026-10-06）。わくわくに近い言葉を拾った日は、木に実が1つ増える。その日一緒に拾った言葉の花が、木のそばに咲く
  - 「一緒の日」はデータが少なくても使えるので、1週目から「わくわくした日に何があったか」が見える。小川（順番）はデータがたまってから
  - 試作は、好奇心の言葉ごとに木を植えている。1本にまとめる直しが要る
- 「前に来たときから育った所」を出すには、前に島を見た時刻を覚えておく必要がある。Convex に保存する（決定 2026-10-05。機種変更しても引き継げる）
- 作る量：島と植物（6種類×育ちの段階）の3Dの形を Blender で作り、アプリで3Dとして表示する（`/pukapuka-blender`）。夜明けの動画も要る
- 重さ：植物が100近くになっても、スマホで重くならない描き方にする
  - 同じ形の部品（茎・花びら・葉など）は、まとめて1回で描く（InstancedMesh という three.js の仕組み）
  - 試作は、ブラウザで約30本を表示できた。スマホの実機でも動いた（2026-10-05、ユーザーの確認）。100本近くでの重さは、これから実機で確かめる
- 曲：朝の島の曲が要る（今は3曲。`/pukapuka-music`）
- 言葉が少ない間（最初の数日）も、さみしく見えないこと。芽が1つでも、島そのものが気持ちいい景色であること
- **島まで遠い**：川から 拾ったことば → 夜空 → 島 と、動画を3回見ないと着かない（合わせて7秒以上）
  - 決定（2026-10-05）：川から直接行ける入口と、朝の島から始まる日の両方をつくる。直接行くときは、川を下って海へ出る動画（第2部 F.）
  - 決定（2026-10-06）：どの画面からも、端の小さな印で島へすぐ飛べる。拾い終えたころ、島の印がそっと光る（第2部 F. の「すぐ飛べる印」）

### 3Dの試作（2026-10-05。`src/islandLayout.ts`・`src/components/Island3D.tsx`・`src/app/island.tsx`）

仮のデータで、使い始めてからの4つの時期の島を見比べる。川の画面の「島（試作）」から入る（仮の入口）。

- 操作：1本指でなぞると回る。つまむと寄る・離れる。地面に触れるとそこへ近づく。植物に触れると言葉が出る。2回触れると全体に戻る
- 引きで見られるよう、全体が見える距離の 2 倍まで離れられる（2026-10-06、ユーザー「あと少し、引きで見れるようにもしたい」）
- 時期：1回目・1週間・1か月・数か月（約3か月）。仮のデータは、拾ったことば・夜空と同じもの（28日分）を3回くり返し、2か月目から新しい言葉を足した
- 時期を変えると、新しい言葉は光の種が空から降りてきて芽が出る。島は言葉の種類と数が増えると広がる
- 植物の形（仮の積み木）：気持ち＝花、体の感じ＝草の株、場面＝茂み、したいこと＝若木、好奇心＝ワクワクの木（金色の実）。1回だけの言葉は芽。「していること」の形はまだない（決定 2026-10-06 で足す）
- まとまりの見つけ方
  - 同じ日に一緒に拾った日数を、それぞれの言葉を拾った日数で割り引く（コサイン）
  - コサイン ＝ 一緒の日数 ÷ √(片方の日数 × もう片方の日数)。0.3 未満の組と、一緒が1日だけの組は使わない
  - お互いの上位3つに入る組だけ残す
  - ラベル伝播（となりの多数派に合わせていく計算）でグループに分ける
  - 割り引かないと、よく拾う「疲れ」が何とでもつながり、数か月で全部が1つのグループになった
  - 割り引くと、仮のデータで決めた組（仕事帰り・不安・好奇心・休日・逃げたい）どおりに分かれた

```
大きさ   = 0.55 + 0.25 × √回数        （上限 1.8）
育ち     = 1回なら芽。2回から 0.35 + 0.13 × 回数（上限 1）
島の半径 = 2.4 + 0.55 × 言葉の種類の数 + 0.06 × 言葉の数
```

- まだないもの：1本のワクワクの木とそばの花（今は木を特別に扱っていない）、木の根もとの淵、水たまり・小川、順番で上流から下流へ並べる植え方、島の動物、遠くの川の河口、朝日・蝶、前に来たときとの比べ

## C3. わたしのこと（MVP。決定 2026-10-07）

流れ（有向ネットワーク）と時間の変化で、自分の輪郭と好奇心の育ちを見せる集大成。流れはこの画面だけで使う。ほかの画面と同じことは見せない（決定 2026-10-07）。
数字とグラフを出してよいのは、この画面だけ（第1部 4. の例外）。上に短いことば、下に数字・グラフ。

### 流れ（有向ネットワーク）

- 矢印：ある日に拾った言葉 → 3日以内に拾った言葉。近い日ほど重い（D. の「矢印の作り方」）。同じ回の中の順番は使わない（D. の「川が決めてしまうこと」）
- 元気・好奇心の源（入次数）：元気・好奇心の言葉へ向かう矢印が、どの言葉から多く来るか。「していること」を中心に見る
  - 毎日拾う言葉（「疲れ」「仕事」）からは、どこへでも矢印が出る。偶然でも起きる数より、はっきり多いものだけ出す
- 行き着きやすい気持ち（PageRank）：矢印をたどり続けると行き着きやすい言葉
- くり返すめぐり（強連結成分分解）：お互いに行き来する言葉の輪。良い・悪いは言わない。注意・助言にしない（第1部 4.）
- 順番は原因と結果ではない。画面でも「〜のせいで」「〜すると」とは書かない。「〜のあとに、よく来る」と書く
- 言い方の例（案）：「『散歩』『計画を立てる』のあとに、元気な言葉がよく来ます」

### 育っていること（時間の変化）

- アプリの中で「育っていくのが見える」場所はここ（第1部 3.）。島を MVP から外したので、見守る役はこの項目が受け持つ
- 上の短いことば：先月と比べて、好奇心・元気の言葉が増えたか、源が広がったか（案）
- 下の育ちのグラフ（案 2026-10-07。ユーザーの OK はまだ）：好奇心・元気の言葉の多さを、はじめは週ごと、たまったら月ごとに、なだらかな線で見せる。源の言葉が加わった時も印で見せる（例：「3週間前：散歩が源に加わった」）
- 事実だけを出す。「日記を書いたから増えた」のような理由は付けない（第1部の「気づきの日記」）
- ほかの画面と機能がかぶらないよう、拾ったことば（よく感じる言葉・本音）と夜空（テーマ）のまとめは、この画面では見せない（決定 2026-10-07）

### 計算の道具（決定 2026-10-07）

- **NetworkX は使わない**。同じ分析（入次数・PageRank・強連結成分分解）を、アプリの中で TypeScript で書く（ユーザー「networkXを使わなくても、同じような分析ができたらいいな」）
- 理由：NetworkX は Python の道具で、スマホと Convex の中では動かない。言葉は百数十語なので、どれも数十行で書け、スマホで一瞬で終わる。拾った言葉を外に送らずに済む
  - 入次数：ある言葉に集まる矢印の重さを足すだけ
  - PageRank：矢印に沿って少しずつ重みを流す計算を、数十回くり返す（行き場のない言葉からは、全体に均等に流す）
  - 強連結成分分解：矢印をたどって、お互いに行き来できる言葉の輪を見つける（Tarjan という決まった手順）
- 正しく計算できているかは、仮のデータで手計算できる小さな例を作って確かめる（案）

### データが少ない間（決定 2026-10-07）

- 使い始めて2週間、または元気な日が5日たまるまでは、短い文だけ（例：「元気な日が、あと少し集まると見えてきます」）
- 数字とグラフは出さない（少ない数では、たまたまでも決めつけに見える）

## D. 裏で動く分析（わたしのこと以外では見せない）

島の植え方・小川・育ち方・星座を決めるために使う。結果そのものは見せず、景色にして見せる（決定 2026-10-05）。
ただし「わたしのこと」（C3.）では、流れ（有向ネットワーク）と育っていることを、ことばと数字で見せる（決定 2026-10-07）。
言葉を点、つながりを線にした網の目を調べる（ネットワーク分析）。

- 線に向き（矢印）がないものを無向グラフ、あるものを有向グラフと呼ぶ
- 今の星座と島の植え方は、無向グラフ（同じ日に一緒に拾った）。小川は有向グラフ（矢印）

| 何のため | どう計算するか | つながりの作り方 | 島での見え方 |
|---|---|---|---|
| 島のどこに植えるか | よく一緒に拾う言葉をグループに分け、同じグループを近くに植える（コミュニティ検出） | 同じ日に一緒に拾った | 花畑・林 |
| ワクワクの木のそばに何を植えるか | 好奇心の言葉と同じ日によく拾う言葉 | 同じ日 | 木のそばに咲く花 |
| どこが育ったか | 前に島へ来たときと比べて、増えた・大きくなった植物 | 同じ日 | 朝日が当たる・蝶が止まる |
| ワクワクの源 | ワクワクの木の言葉へ向かう矢印が、どの言葉から多く来るか（入次数：ある言葉に集まる矢印の数） | 矢印 | 木の根もとの淵へ流れ込む小川と、その上流に咲く花 |
| 気持ちが行き着きやすい言葉 | PageRank：矢印をたどり続けたとき、たどり着きやすい所を見つける計算 | 矢印 | 池のほとりに咲く |
| 流れが始まる言葉 | 矢印が出ていくばかりで、入ってこない言葉（案） | 矢印 | 丘の湧き水のすぐ下、いちばん上流に咲く（案。湧き水そのものは言葉ではない） |
| 上流か下流か | 矢印の順番で言葉を並べる（案。下の「小川の形の作り方」） | 矢印 | 植える高さ（奥の丘ほど上流） |
| くり返すめぐり | 強連結成分分解：矢印でお互いに行き来できる集まりを見つける計算 | 矢印 | 渦・霧 |

**矢印の作り方**（決定 2026-10-05。第1部 5. の「島に流れる小川」）
- 日をまたいだ順番：ある日に拾った言葉 → 3日以内に拾った言葉。近い日ほど重くする（重さの例：次の日 1、2日後 0.5、3日後 0.25。数値は仮）
- 一行の文章を残した日は、その文の中の流れ（「計画していたらワクワクした」→ 計画 → ワクワク）も足す
- 3日は、カレンダーの日で数える（案）。開かなかった日があっても、間を詰めない（1週間ぶりに開いた日を「次の日」として扱わない）
- 新しい小川ができる・消えるのは月に1回くらい。毎日は、水の量や太さだけを少し変える（決定）。毎日の計算で小川が出たり消えたりしないよう、月の初めに小川の形を決め直す（案）
- 矢印が多すぎると、ほとんどの言葉が1つの輪にまとまって意味がなくなる。2回以上あった組だけを使う
- めぐりは形（渦・霧）だけで見せる。注意・助言にはしない

**小川の形の作り方**（案 2026-10-06）
- 植物は小川のほとりに、上流から下流へ順番に並ぶ（決定 2026-10-06）。水は坂を上れないので、植える場所を順番で決める
  - 奥から手前（高い → 低い）の向き：矢印の順番。先に来る言葉ほど奥
  - 横の向き：よく一緒に拾う言葉のまとまり（今のグループ分け）。花畑になる
- 矢印の網の目は、そのままでは川の形にならない（川は合流するだけで、輪にならない）。そのため
  - 太い矢印だけを選び、いくつもの小川がワクワクの木の淵に集まり、淵から池へ1本で流れ出る形にまとめる
  - お互いに行き来する言葉（くり返すめぐり）は、同じ高さに並べて、そこを渦にする
- データが少ない間は小川を出さないので、この並べ方は数か月たまってから使う（第1部 5. の「最初のころ」）

### もとになった考え（2026-10-05 ユーザーが外部の AI と話して気に入った案）

「ネットワーク分析でワクワクを育てる3つの方法」。日記の文章から矢印を作る前提の案なので、pukapuka の決まりに合わせて形を変えた。

| もとの案 | 中身 | pukapuka での扱い |
|---|---|---|
| 1. 隠れたワクワクの源泉を見つける | 「楽しい」「おもしろい」などの言葉（ハブ）に、どの言葉から矢印が集まるかを逆にたどる。例：「旅行」より「旅行の計画 → ワクワク」に気持ちが集まっていた | **ゴールにした（第1部 3.）**。データで答えを示さず、ワクワクの木のそばの花と、木へ流れ込む小川で見せる |
| 2. エネルギー泥棒を見つける | 不安や焦りのくり返す輪（強連結成分分解）を見つけ、「夜は SNS を開かない」などの境界線を引く | **助言はしない（第1部 4.）**。輪は渦や霧の景色として見せるだけ |
| 3. ワクワクの島を広げる | グループ分け（コミュニティ検出）で、興味のまとまりが育つ様子を地図の成長として見る | **4つ目の画面「島」になった**。地図ではなく、花畑や林が育つ景色 |

- もとの案は「計画 → ワクワク」の矢印を日記の文から作る。pukapuka は川で拾うだけなので、文がない。拾う順番は川の偶然（下の「川が決めてしまうこと」）
- そのため、最初は矢印を使わず「同じ日に一緒に拾った」でつなぐ。矢印（小川）は、日をまたいだ順番（3日以内）と残した一行の文で作る（決定 2026-10-05）。データが数か月たまってから

### 川が決めてしまうこと（2026-10-05 ユーザー指摘）

- 1回の中で拾う順番は、川に流れてきた順番でほぼ決まる。**同じ回の中の順番は、気持ちではなく川の偶然**
- 島の植え方と育ちは「同じ日に一緒に拾った」（順番なし）で作るので、この影響を受けない
- 方針（案）
  1. 同じ回の中の順番は使わない
  2. 順番を使うなら、川が決められない大きな単位（日をまたいで、3日以内。決定 2026-10-05）で。データが数か月たまってから試す
  3. 偶然でも起きる回数と比べて、明らかに多い組だけ残す
  4. 決まった言葉（約130語）は、均等なランダムのまま流す。かたよらせるなら「どの言葉が何回流れたか」も記録する
  5. 特別な泡（自分の言葉・過去の自分・贈りもの・季節の言葉。第1部の7. と10.）は、決まった言葉に「足す」もの。どこから来たかを記録し、決まった言葉と分けて数える。流れた回数も記録する
  6. 日をまたいだ順番で矢印を作ると、毎日拾う言葉（「疲れ」など）からは、どの言葉へも矢印が出る。偶然でも起きる回数と比べて、明らかに多い組だけ小川にする（方針3）
  7. 一行・日記の文から矢印を作るとき、AI が書いただけの一行は AI の考えた流れ。直さずに残した一行も使うが、直した文・自分で書いた文より弱く数える（決定 2026-10-05）
- 時間帯のかたより：夜にばかり開く人は、夜の言葉が多くなる。同じ日の中で順番をつなぐと、夜の言葉ほど「行き着く先」になる（仮のデータで確かめた）

### 道具

- **NetworkX（Python）**は、アイデアを試すときだけ使ってもよい（アプリには入れない）。グループ分け・PageRank・強連結成分分解などがそろっていて、図にして見比べやすい
- スマホと Convex では Python が動かない
- アプリに出すと決めた計算は、TypeScript で書き直す（約130語なら数十行）。わたしのこと（C3.）の計算も TypeScript で書く。アプリでは NetworkX を使わない（決定 2026-10-07）
- 試すときは NetworkX をプロジェクトに足さず、`uv run --with networkx` で一時的に使う

### 仮のデータで試したこと（2026-10-05）

- 流れ着く言葉（PageRank）：よく拾う言葉と行き着く言葉は違った（「疲れ」は回数1位だが7位。ほかの言葉への通り道）。ただし同じ日の中の順番で作ったので、川と時間帯のかたよりをそのまま含む試作

- マナーモードでは鳴らさない。ほかのアプリの音楽は止めずに重ねる。アプリが裏に回ったら止める

## G. データ

記録するのは「いつ・どの言葉を・どれくらいの強さで拾ったか」だけ。

```typescript
Capture {
  _id: Id<"captures">
  deviceId?: string     // 端末ごとの仮のID（ログインなしの間。MVP。決定 2026-10-05・2026-10-07）
  userId?: string       // ログインしたときのユーザーID（あとで）
  capturedAt: number    // 拾った時刻（ミリ秒）
  word: string          // 拾った言葉
  strength: number      // 強さ 0.0〜1.0（押した長さで決まる）
}
```

- 端末ごとの仮のIDは、アプリが最初に作って端末に覚える、推測しにくい長い文字列（32文字）。`src/useCaptures.ts`・`convex/captures.ts`（作り始め 2026-10-07、確認済み 2026-10-08）

- 気づきの日記を作るとき（MVP のあと）：「どの言葉に・いつ・メモ（なくてもよい）」を記録する小さな表を足す。拾った記録とはつなげない（第1部の「気づきの日記」）
- ユーザーは文字を打たなくても使える（AI の一行を直す・ひとこと日記はどれも選べるだけ。案）
- 拾わなかった泡は記録しない（ただし自分の言葉を流すときや、D. の方針4で言葉をかたよらせるときは、流れた回数を記録する）
- 一行・日記を入れるなら（案）
  - 残すと選んだ一行・日記（本文・時刻）と、そこから生まれた自分の言葉を記録する。捨てた下書きは残さない
  - 拾った記録に「どこから来た言葉か（決まった言葉／自分の言葉／過去の自分／贈りもの／季節）」と「そっとしておく」を足す
- 未来の自分へ流す言葉・贈った言葉を入れるなら（案）：言葉・流した日・戻ってくる日、贈った相手と受け取ったか、を記録する
- 置き場所：Convex（シドニー）
- 保存は動く（2026-10-08、ブラウザとスマホで確かめた。拾うと入り、開き直しても同じ目印）。前（2026-10-07）は `captures.add` がユーザーIDなしで止まり、保存されていなかった
- ログインなしの間は、端末ごとの仮のIDで記録し、ログインしたら引き継ぐ（H.）
- **日付は保存しない**（決定 2026-10-09、ユーザー「普通の時刻でいい」）：残すのは時刻（`capturedAt`）だけ。「同じ日」は、アプリが端末の時計で、0時で切って数える（`src/period.ts` の `dayKey`）
  - 今は日本だけで使うので、困らない
  - 旅行や夏時間の国では、数え方が1日ずれることがある。海外の人が使う公開のときに決め直す
  - 夜ふかし（午前3時までを前の日に数えるか）は、わたしのことを作ってデータを見てから決める（案）
