# pukapuka-app 仕様書

## 概要

自分の中から湧いてくる感覚・興味の種が、掴む前に消えていく——
その問題を解決するアプリ。

反射的に捕まえて、積み重なりを見返すことで、
「自分が何に興味がある人間か」の輪郭が見えてくる。
生きる勇気と、好奇心を育てる自信が生まれる。

## コンセプト

**「流れてくる言葉を拾い、夜に星として振り返る」**

- 川を流れる言葉（泡）をタップして拾う
- 昼に拾った言葉が、夜の星空に星座として浮かぶ
- 積み重なりが「自分の輪郭」を映し出す

---

## 想定ユーザー

- **年齢・職業**: 25〜40歳の社会人
- **デバイス**: Android / iOS 両方
- 忙しさに飲まれて、自分の輪郭や興味を見失いかけている人
- 疲れ切ったとき・隙間時間・逃げ場所がほしいときに開く

## 解きたい問題

**「自分が何に興味があるかわからない」**

- 自分の中から湧いてくる感覚が、掴む前に消えていく
- 記録しようとすること自体が負荷になって続かない
- 記録を溜めても見返す気になれない
- やり過ごすだけで、解決している感じがしない

## 世界観・ビジュアル

### ことばの川（メイン画面）
夕方17〜18時頃の渓流。露天風呂から眺める川。
深緑の木々、木漏れ日、水面のきらめき、温泉旅館の灯り。
言葉は半透明のガラス球の泡として浮かんでくる。

### ふりかえり画面
深い藍色の夜空。満天の星、天の川。
昼に拾った言葉が夜空の星として配置され、
星座のように細い金色の線で結ばれる。
川面に星が反射し、旅館の灯りが揺れる。

### 画面遷移（川→拾ったことば）
「振り返る」を押すと、泡が空へ昇りながら消え、カメラが川岸から空を見上げる（Blender の2秒の動画）。
夕暮れ → 日没直後 → ブルーアワーへ時間が進み、拾ったことば（ワードクラウド）画面になる。

### 画面遷移（拾ったことば→川）
行きの動画を逆に再生。カメラが空から川岸へ下り、泡は元の水面から「ぷかっ」と浮かび上がる。

### 拾ったことば（ワードクラウド画面）
ブルーアワーの空。地平線に夕焼けが少し残り、星はまだ出ていない（星になる前の言葉）。

### 画面遷移（拾ったことば→ふりかえり）
カメラが空へ近づきながら夜が更け、星が1つずつ出てくる（Blender の3秒の動画）。夜になったら、言葉の星がふわっと浮かび（0.9秒）、少し遅れて金色の線が引かれる（0.6秒後から1.2秒）。

### 画面遷移（ふりかえり→川）
夜空がフェードし、夕方の渓流へ戻る。

## 機能

### ことばの川（メイン画面）

1. 画面を言葉が**右から左へ川のように流れる**（7列、中央ほど速い）
2. 言葉は以下の5カテゴリが約100語混ざっている
   - **感情** — 不安・わくわく・怒り・悲しみ・恥・嫉妬・安心 など
   - **身体感覚** — 疲れ・眠い・胸が痛い・軽い・重い など
   - **状況・場面** — 仕事・人間関係・将来・お金・家族・恋愛 など
   - **価値観・欲求** — 自由になりたい・認められたい・逃げたい・成長したい など
   - **好奇心** — 面白い・気になる・もっと知りたい・なんで？ など
3. 言葉はリアルタイムで流れてきて消えていく
4. ピンときた言葉を**タップ or 長押し**して離す → 言葉がふわっと上に昇って消える → 記録される
5. **押している時間＝気持ちの強さ**として記録される
   - タップ（即離す）: 強さ 0.1（最小）
   - 押し続けるほど強さが増し、2秒で最大（1.0）
   - 押している間、言葉の周りに**チャージリング**が広がって強さを可視化する（ゴールド→オレンジ）
6. 画面下部に「「〇〇」を拾った」と一時表示される（1.8秒）

#### 言葉の生成ロジック

| 記録数 | 挙動 |
|---|---|
| 0〜19個 | 固定リスト（約100語）からランダムに表示 |
| 20個以上 | 過去の記録をもとにAIがパーソナライズした言葉を生成（将来） |

### 分析の考え方

「ワードクラウドでよく使う言葉（キーワード）をざっくり洗い出し、共起ネットワークで深掘りする」。
画面を2つに分け、**ざっくり把握 → 深掘り**の順に見られるようにする。

#### 設計の方針（決めたこと）

- **目的は「ユーザーが自分で気づく」こと**。アプリが「あなたはこういう人」と断定しない
- 気づきは**予想とのずれ**から生まれる（例：何度も拾う言葉と、強く拾う言葉が違う）
- 拾った言葉は**そのまま**集計する。conceptId などのグループ化は採用しない（言葉の多様性がワードクラウドの価値のため）
- 将来AIが毎回違う言葉を作っても、ワードクラウドの大きさが揃うだけで問題にしない。つながりはふりかえり（共起）で見る
- 回数と強さは**掛け算で1つにまとめない**。大きさと明るさに分ける（上記）
- 固定リスト（約100語）を均等に出している間は、拾った回数が「関心」を反映する。AIで出す言葉を偏らせると、回数が「出た回数」の影響を受ける点に注意する

---

### 拾ったことば（ワードクラウド画面）

- 過去に**実際に拾った言葉だけ**を、言葉そのままで表示する（グループ化・ラベル付けはしない。拾っていない言葉は出さない）
- 単純なワードクラウドはNG。川・泡・星の世界観に合う見せ方にする（デザイン未定）
- 期間フィルター: 今週 / 今月 / 今年 / すべて
- 言葉をタップすると、ふりかえり（共起ネットワーク）へ移動し、その言葉が中心に表示される

#### 大きさとキラキラの決め方（「習慣」と「本音」を見分ける）

回数と強さを1つの数字（掛け算）にまとめない。**別々の見え方**にして、2つの組み合わせから気づきが生まれるようにする。

- **文字の大きさ＝拾った回数**
- **文字の色＝既存の5カテゴリ**（感情・身体感覚・状況・価値観・好奇心）。画面下に凡例を出す
- **文字のキラキラの度合い＋周りの光の広がり＝気持ちの強さ（1回あたりの平均）**。文字そのものが自分の色で光ってまたたき、文字の後ろに同じ色の光が広がって息づく。強いほど明るく輝き、光が広い。弱い言葉はどちらもない
- 強さという1つの情報を2通りで見せて、差を読み取りやすくする（回数と強さを同じ見え方に混ぜるのとは違い、迷わせない）
- **周りの光の広がりは強さだけで決め、文字の大きさに比例させない**。比例させると大きい言葉ほど光も大きくなり、回数と混ざる。小さい字なのに光が広い＝本音かも、が見えるようにする
- 星などの飾りは足さない

| 見え方 | 意味（仮説） |
|---|---|
| 大きくてキラキラしない | **習慣**。何度も拾うが、軽く拾っている（口ぐせ・いつもの感覚） |
| 小さくて強くキラキラする | **本音**かもしれない。回数は少ないが、強く長押しした言葉 |
| 大きくて強くキラキラする | 中心にある関心事 |
| 小さくてキラキラしない | まだ薄い気持ち |

「本音」はあくまで仮説で、断定しない。強さは気分や指の癖にも左右される。

経緯（2026-10-04）: 文字の明るさ（濃淡）→ 後ろの光の円 → 言葉のまわりの星 と試し、最終的に「文字は色分けし、その文字自体がキラキラする度合いで強さ」に決めた（ユーザー指定）。

**計算式**（仮の値。実機を見て調整する）

```
文字の大きさ(px) = 16 + 回数 × 2                    （上限 40）
k               = (強さの平均 - 0.25) / 0.75         （0〜1に収める。0.25以下はキラキラしない）
光る写しの濃さ   = 0.35 + 0.65 × k                    （k=0 なら写しなし）
光のにじみ(px)   = 3 + 13 × k
周りの光の半径   = 16 + 40 × k  (px。文字の大きさに関係なく強さだけ。k=0 なら光なし)
周りの光の濃さ   = 0.7 × k       （状況・場面の青だけ ×0.75。青は強く光って見える）
またたき         = 2.4秒周期。3グループに分けて時間をずらす。周りの光も同じ時計でゆっくり明るさが変わる（0.55〜1倍）
文字の濃さ       = 0.78 + 0.22 × 強さの平均
```

- 平均にするので、キラキラは回数に左右されない
- 1回だけ拾った言葉は、その1回の強さがそのままキラキラになる。気になれば後から補正を足す（全体平均を混ぜるなど）

**ユーザーへの伝え方**

- 画面下にヒント「文字の大きさ＝拾った回数　キラキラ・光＝気持ちの強さ」と凡例（今は常に表示。初回だけにするかは使って決める）
- 言葉をタップすると、実際の強さを点で見て答え合わせできる（ふりかえり画面の詳細）

### ふりかえり（共起ネットワーク画面）

- 言葉を**星**、一緒に拾われた関係を**細い金色の線**で表示する（星座のように）
- 星の大きさ＝拾った回数、線の太さ＝共起回数
- 配置は力指向（共起が強い言葉ほど近くに寄る）。共起が一定回数以上の線だけ表示して見づらさを防ぐ
- 期間フィルター: 今週 / 今月 / 今年 / すべて
- データが少なく線が出ないときは「もう少し拾うと見えてきます」と表示する
- 将来: つながりの強いグループごとに色分け（クラスタリング）

#### 見せる星と線の決め方（2026-10-04 仮データで実装。値は実機を見て調整する）

計算は `src/constellation.ts`（RN に依存しないので node で検証できる）。

```
線を出す条件      共起回数 2 以上（1回だけ一緒だった組は偶然が多い）
線の選び方        強い線から順に採る。星は最大22個・線は最大34本・1つの星から最大5本
                  （よく拾う言葉が全部とつながる「団子」を防ぐ。将来は PMI / lift で選ぶ）
星の芯の半径(px)  1.4 + 0.35 × 回数         （上限 5）
星の名前(px)      9.5 + 0.25 × 回数         （上限 13）
線の太さ(px)      0.6 + 0.28 × (共起回数 - 2)（上限 2）
線の濃さ          0.28 + 0.05 × (共起回数 - 2)（上限 0.5）
配置              力指向。線でつながる星の理想の間隔 64px（星が少なくても引き伸ばさない）。
                  広さを気にせず動かしてから、入りきらないときだけ全体を縮めて真ん中に置く
                  （壁の中で動かすと星が画面の端に貼りつく）
```

- 線のない星は出さない（拾ったことばからタップして来た言葉だけは、線がなくても出す）
- 拾ったことばで言葉をタップして来たときは、その言葉をできるだけ中心に置き、選んだ状態で開く（全体が画面からはみ出さない分だけ中心へ寄せる）
- 星をタップすると、その星と線でつながる星・線だけが明るく残り、ほかは薄くなる。もう一度押す・空を押すと戻る
- 画面下のヒントは、ふだんは「星の大きさ＝拾った回数　線＝同じ日に2回以上」、星を選ぶと「「不安」 10回　同じ日に拾った言葉 5」（線がなければ「もう少し拾うと見えてきます」）
- 星の周りの光は3グループに分けて時間をずらし、3.2秒周期でゆっくりまたたく

#### 星をタップして掘り下げる（相互作用）

星（言葉）をタップすると詳細が開き、ユーザーが自分で気づけるようにする。答えは教えない。

- 拾った日が点で並ぶ**時間の線**（点の大きさ＝その日の強さ）
- **曜日・時間帯**の偏り（例：「日曜の夜に集まっている」）
- 同じ日に一緒に拾った言葉（そこから別の星へ移れる）
- 拾った回数が少ないうちは詳細が薄くなるため、「もう少し拾うと見えてきます」を出す
- 最初は時間の線だけ作り、曜日などは使ってみて足りなければ足す
- （未実装。今は選んだ星とつながる星が明るく残るだけ）

#### 共起の定義

**同じ日に拾った言葉同士を共起とみなす。**

- 例: 10/3 に「不安・疲れた・仕事」、10/4 に「不安・仕事・わくわく」を拾った場合、「不安」と「仕事」は2日とも一緒なので共起回数 2
- 将来、同じ時間帯・連続して拾った言葉など、より細かい定義も検討する

## 音

参考は**ジブリ（久石譲）・どうぶつの森・Sky 星を紡ぐ子どもたち**。メロディはまねず、音色・和音・鳴らし方の傾向だけを取り入れる。

### 画面ごとに別の曲

どうぶつの森の「時間で曲が変わる」のように、3画面それぞれに別の曲を流す。拍子・速さ・和音の進行・メロディ・主役の楽器を画面ごとに変え、同じものを使い回さない。

**場面ごとに雰囲気を大きく変える**（2026-10-04）。楽器や和音だけでなく、明るさ（音域）・拍の速さとはっきりさ・長調か短調か・残響の長さを場面の意味から決める。曲を変えたら `check.py` の「雰囲気」（明るさ・拍・拍のはっきりさ）で、ほかの曲と離れているかを確かめる

| 画面 | 曲 | 中身 |
|---|---|---|
| ことばの川（夕方） | `bgm_river.m4a`（4拍子・58 BPM・33秒ループ） | まばらなピアノのメロディ、ハープの上りのアルペジオ、ゆらぎのある弦の和音、ときどきベル、遠くの水のさざめき。深い残響。高い帯域をなだらかに丸めている。和音: DM7 → E6 → C#m7 → F#m7 → Bm7 → C#m7 → DM7 → E7sus4（王道進行から始まる） |
| 拾ったことば（ブルーアワー） | `bgm_cloud.m4a`（4拍子・**96 BPM**・軽いスウィング・40秒） | **明るく弾む**（キラキラ光る言葉を眺める）。チェレスタのメロディ（1オクターブ上を小さく重ねてキラキラさせる）、ピチカートのベース、マリンバの裏拍、シェイカー。残響は短く乾いた音。和音: A → F#m → D → E を中心にした明るい進行（16小節） |
| ふりかえり（夜） | `bgm_night.m4a`（**拍なし**・42秒） | **暗く静かな内省**（星座を見て自分を振り返る）。**F# マイナー**。低い持続音、弓で弾く低い弦の長い音、高いガラスの音が星のようにまばらに。残響がとても深い。和音: F#m9 → DM9 → Bm9 → C#sus4（10.5秒ずつ） |

- 3曲とも**同じ調**（Aメジャー／平行調のF#マイナー。シャープ3つ）にする。画面が変わるとき2〜3秒重なっても濁らず、泡を拾った音がどの曲にも合う
- **高さは低めにする**（2026-10-04「高くてキンキンする」「泡の音が耳が痛い」→ 聴き比べて -5 半音を選択）。初めは D メジャー／B マイナーで、空のチェレスタは最高 E7、夜の星は B6 まであった。楽譜は D メジャーのまま書き、`compose.py` の `TRANSPOSE = -5` で曲と拾った音を同じだけ下げる（5音と調の関係が変わらない）。高い楽器は音域も下げた（川のベル・空のチェレスタ・夜の星）。明るさ（音の重心）は 川 606Hz／空 973Hz／夜 305Hz
- 画面が変わるときは遷移の動画と同じ長さで重ねて切り替える（川⇄空 2秒、空⇄夜 3秒、夜→川 0.9秒）

### 泡を拾ったときの音

- **「ぷかっ」**（2026-10-04、3案から選択）: 泡がすっと上がる音（低い所から 0.025秒で目標の高さへ）に、柔らかいガラスの音が残る（`chime_0〜4.m4a`、各4秒）。前の版（ハープ＋ベル）は高い金属の響きで耳が痛かった
- 押した強さで高さと大きさが変わる（タップ＝ミ、2秒の長押し＝ド#）。ミ ファ# ラ シ ド# の5音（A メジャーの五音音階）は3曲のどの和音ともぶつかりにくい
- スマホでつかえずに鳴らす: 1つの高さにつき2つ用意し、続けて拾っても前の音の余韻を切らない。鳴り終わったら頭へ戻しておき、押したら待たずに鳴らす

### 鳴らし方

- マナーモードでは鳴らさない。ほかのアプリの音楽は止めずに重ねる。裏に回ったら止める
- 右下の ♪ で音を消せる（今はアプリを閉じると元に戻る。覚えておくかは未決事項）

### 作り方（2026-10-04 決定）

- **曲と効果音は Python でコードから合成する**（`scripts/music/`）。楽譜（和音・メロディ）も楽器の音も残響もコードで書く。Blender と同じ「素材を作る道具」で、アプリには含まれず、書き出した m4a だけを使う
- 決めた理由: 動いている／素材の利用規約の心配がない／誰でも同じ音を作り直せる（コードなので git で履歴とレビューができる）／直しが早い。弱点はピアノや弦が少し電子音っぽいこと。公開前に気になったら、楽譜はそのままで楽器の音だけ差し替える
- **Python 3.13**、**uv** で管理（`scripts/music/.python-version`・`pyproject.toml`・`uv.lock`）。numpy・scipy のバージョンは `uv.lock` で固定。ffmpeg 6 以上が必要（uv では管理できないので README に書く）
- **3曲と拾った音は 2026-10-04 にユーザーが聴いて決定**（同じ日に -5 半音下げ、拾った音を「ぷかっ」に変えて、聴いて決定）。決めた音の指紋は `scripts/music/approved.json`。`build.py` が作るたびに比べ、変わっていれば知らせる。変えるときは聴いてもらってから `uv run build.py --approve`
- 作り直し: `cd scripts/music && uv run build.py`。乱数は曲ごとに種を固定していて、同じ環境なら同じ音になる。数値の確認は `uv run check.py`。作り方の詳しいルールはスキル `/pukapuka-music`
- 書き出しの決まり: 3曲とも -20 LUFS にそろえる（切り替えで音量が跳ねない）。ループの長さは 1024 サンプルの倍数（AAC で終わりに無音が足されて途切れないように）。ループの曲は前後に続き（8192 サンプル）を足して AAC にし、MP4 の編集リストで飛ばす（AAC は何もない所から始まる頭が崩れるため）。風・水のような消えていかない音は、それ自体をループにしてから重ねる（つなぎ目に段差ができないように）

## データモデル

```typescript
Capture {
  _id: Id<"captures">
  userId: string        // GoogleログインのユーザーID
  capturedAt: number    // Unix timestamp(ms)
  word: string          // 選んだ言葉
  strength: number      // 0.0〜1.0（長押し時間で決まる）
}
```

- ユーザーが一文字も打つことはない
- 「流れ去った泡（拾わなかった言葉）」はレコードを作らない
- バックエンド: Convex（Asia Pacific Sydney）
